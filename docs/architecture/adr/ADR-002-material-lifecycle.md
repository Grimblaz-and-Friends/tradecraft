# ADR-002: The three materials, and the lifecycle between them

**Status:** Accepted 2026-08-15 · Amended 2026-08-16 (a second road into the lifecycle — admission by trial — for mechanisms that have no judgment-tier form — evidence: the convergence gate was piloted end to end in [PR #6](https://github.com/Grimblaz-and-Friends/tradecraft/pull/6) under no rule permitting a pilot, and a session then read this ADR as forbidding the pilot and stopped, stalling two open items — [issue #14](https://github.com/Grimblaz-and-Friends/tradecraft/issues/14))

## Context

Every rule in this system is expressed in one of three materials: **model judgment** (nothing written), **prose** (methodology the model reads), or **code** (contracts that execute). The predecessor repo supplied hard evidence about all three failure modes:

- **Prose contracts fail silently.** Nearly every recurring defect class was a format or state rule written in prose that a model then violated invisibly (marker syntax rules, assertion formats, comment-placement contracts). Each cost a debugging session; none would have existed had a script owned the format.
- **Code encoding unstable rules rots expensively.** An elaborate audit apparatus (manifest schemas, containment guards, drift detection) needed crash fixes in its final month, guarding rules that existed only because of how the then-current process happened to work. Worse, workflow logic pushed into code was root-caused *six times* to the same failure — a unit-tested library never wired to the live path. Workflow is exactly what changes when models improve.
- **Prose written for weaker models becomes a tax.** The root instruction file grew to thousands of always-loaded words because every incident defaulted to "add a paragraph" — paragraphs that fire every session, relevant or not, and never retire.

A one-axis rule ("if it can be violated silently, make it code") produces the second failure. The rule needs two axes — **checkability × durability** — and, more importantly, a lifecycle rather than a static assignment.

## Decision

**Every rule starts as model judgment.** Promotion is earned, never speculative:

1. **Judgment → prose**: when inconsistency across sessions has *actually cost something*, and the rule shapes judgment (what to consider, in what order, to what standard). Litmus: *would a strong senior engineer need this instruction, or just the goal and constraints?* Prose teaches; it never enforces.
2. **Prose → code**: only when the rule has (a) been violated at real cost, (b) survived change long enough to look stable, and (c) has a checkable form. Code is the retirement home for rules that have proven durable — never the first draft of a rule.

**Rule prose carries three things, and only the third belongs elsewhere.** The **specification** is the rule — four seats, one pass, an 8,000-character budget; numbers here are part of the rule and cannot rot. The **reason** is the mechanism a reader needs to apply the rule well and to notice when it stops applying; it is short, general, and stays inline, because a model reading mid-task will not follow a link and a rule whose point is invisible gets tidied away by whoever meets it next. The **evidence** is what proves the reason — counts, dates, incidents, prior findings — and it goes behind a pointer into the evidence registry: it is long, it drifts, it cannot be checked from the prose anyway, and reciting it spends every session's context serving a reader who is not there. Explain why; do not litigate it. A sweep deciding whether a rule is still load-bearing **follows the pointer**; a session applying the rule reads the reason and never needs to.

**Precision follows load, not grammar.** A figure that carries a decision — or that is a rule's only evidence — must be exact and checkable, because someone will act on it or revise a rule by it. A figure that conveys a magnitude so a reader grasps the shape of the thing is held to *honest*, not *exact*: it must not mislead, and it does not need defending to the decimal. Writing every sentence to the first standard is how prose becomes unreadable and its review becomes an audit of rounding.

**Evidence moves only if the pointer carries it, and only if the reader can reach it.** Verify the target contains the claim before cutting the recital — a citation that does not carry what it is attached to is worse than the text it replaced, because it converts a self-auditing statement into an unsupported one that *looks* supported, and no reader can tell from the prose. Reachability binds hardest in the shipped zone, where ADR-004 forbids a skill from citing `docs/` by path. A full web URL to the same file is lawful and does resolve for a consumer, so registry-only evidence is reachable — by that form, and only while the repository is public. Check the form before cutting; when the pointer cannot carry the claim or cannot be reached, the recital is not clutter, it is the only support the claim can have.

**Demotion is just as mandatory:**

- Prose is pruned when models stop needing it. Every prose rule carries its exhibit (why it exists), so a future sweep can tell load-bearing from vestigial.
- A code guard whose condition can no longer recur (the process it guarded changed) is deleted, not maintained. A test suite you are afraid to delete from is doctrine accreting in a compiler.

**The one exception that skips the lifecycle: boundary formats.** Formats and state at the GitHub boundary (markers, ledger rows, version stamps) are interchange formats whose whole point is durability across sessions and runtimes — stable by nature, and the site of every historical silent-violation incident. These are code from day one: the model never hand-writes them; it calls an emitter and a validator. (Interim waiver, recorded in ADR-006 §5: until the emitter library exists, ledger rows are hand-written and validated by the packaging lint — the smallest honest discharge of this rule, not an exception to it.)

**The second road in: admission by trial.** Promotion is one way into this lifecycle. It cannot serve everything, because **a rule can start as nothing and a mechanism cannot.**

**The two are told apart by what writing buys.** A **rule** is anything a competent session could do correctly from the goal and the constraints alone; writing it down makes that more reliable, but writing it is not what makes it *possible*. A **mechanism** is a thing that must be the *same thing* across sessions to work at all — a fixed name, shape, callable surface, or coordination point another party has to be able to find. A gate procedure is a mechanism: ADR-005 makes it *"designed-in, non-overridable by pacing directives"*, and the owner must know where to answer it. A checklist lens is a rule: a session applies it from the goal, which is why a recurring class is closed by promoting a lens rather than by admitting one. (That is this section's artifact sense of the word; the *"Rule prose carries three things"* paragraph above uses *mechanism* for a rule's explanatory **reason**, which is prose and keeps the promotion road.) **Boundary formats are neither, and nothing on this road reaches them**: they are code from day one under the paragraph above, and they *skip* the lifecycle rather than entering it — so a ledger row, a marker, a version stamp, and the vocabularies ADR-006 §5 grows by amendment are excluded here **by name, not by a preposition a reader has to notice**.

**What a trial admits** is a mechanism's **procedural specification** — its name, surface, shape, trigger, question, record format — and never the **advisory methodology** carried alongside it, which stays on the promotion road and is still earned by incident. A gate procedure's trigger and record ship with the trial; the guidance on writing a good one does not. A skill's steps ship; its rationale does not. This clause is what stops the road becoming the predecessor's paragraph tax under a new name, and it is the clause the first draft of this section lacked.

**The loop that makes the road necessary.** For a mechanism whose value cannot be shown without running it, "start as nothing" means *never start*: the promotion trigger cannot fire, because the incidents it demands are produced only by the mechanism running. Zero pilots, zero incidents, not earned, no pilot permitted, zero pilots — and that verdict is indistinguishable from evidence weighing against the mechanism. **Stated at that width deliberately, because the unqualified form is false.** Promotion's trigger is *"inconsistency across sessions has actually cost something"*, and a mechanism's **absence** can cost something too: the convergence gate was promoted on exactly such an incident — `git grep -i affirm` returning nothing across the tree (ADR-006 §2). The loop therefore closes only for mechanisms whose absence is *silent*, which is why [#11](https://github.com/Grimblaz-and-Friends/tradecraft/issues/11)'s framing and commitment gates are stuck and convergence was not.

This is the third instance of one class here: [PR #6](https://github.com/Grimblaz-and-Friends/tradecraft/pull/6) found a *schema* that could only answer no, [PR #12](https://github.com/Grimblaz-and-Friends/tradecraft/pull/12) found the *rule* above it doing the same, and this is the *lifecycle* above both. ADR-006 §5's sentence, written for the first and applying unchanged to the rest: an evidence loop whose instrument cannot express the finding it tests for is not evidence.

So the owner may **admit a mechanism as a trial, before any evidence exists.** Six properties, each carrying the failure it blocks, because a property whose point is invisible is one a later reader tidies away:

1. **Mechanisms only; rules keep the promotion road.** Blocks the predecessor's paragraph tax — its root file passed 30k characters at its peak because every incident defaulted to prose — accreting through a door built for something else.
2. **Marked as a trial wherever it is used.** The marker is the word **`trial`** with its admission date, in the mechanism's own opening prose, at **every** site the mechanism is stated, so `git grep -in trial` returns every live one as a single class. Without a fixed form two sessions' trials are not greppable together and property 3 has nothing to fire on. Inside a shipped-zone skill the marker's pointer back here must be a full `https://` URL — ADR-004's zone wall forbids a `docs/` path there and the lint enforces it. Blocks speculation laundering itself as evidence: a trial a reader cannot distinguish from an earned rule is worse than no trial, because it spends the credibility the earned ones paid for.
3. **Cut at its review trigger unless evidence for it has arrived.** Removal takes no argument; retention takes one, made to the owner and recorded where the marker is. **This is a norm and not yet an operation** — nothing in the tree observes a trigger today, so the obligation sits on whoever next reads the marker, and writing it as though something fired would claim a mechanism this repo does not have. Blocks accretion, which turns wherever the default is "keep." The nearest precedent is ADR-005's cut rule for gates, and it is only near: that one cuts a gate which **fails an affirmative test** — *"cannot state what the human uniquely decides"* — where this cuts on **inaction at a trigger**. Default-on-inaction is the novel half and is borrowed from nowhere.
4. **States its falsifier and review trigger before it runs**, in a unit the instrument actually counts. The instrument is the ledger (ADR-006 §5); what it counts is rows, the fields on a row, and distinct `source` values. Elapsed time, sessions, pull requests and "uses" are not among them, and are the units a trigger will reach for first. Blocks the defect ADR-006 §5 caught in its own grandfathering rule — a governing distinction written in a unit the instrument does not carry is one nothing can evaluate.
5. **The owner admits it**, and the admission is recorded where the convergence gate's is (ADR-006 §2): on the work's issue, before the first commit. Blocks the pretence that this is evidence. It is intent and risk appetite — ADR-005's first answer, judgment no model capability substitutes for.
6. **A trial produces ledger rows attributable to it while it runs.** Blocks a slower ratchet — this is what makes the road pay for itself, by manufacturing exactly the record promotion demands.

Properties 3 and 6 are the structural argument, and neither works alone: a trial is **self-liquidating**, promoted on the evidence it generated or cut for generating none. It cannot sit and become furniture. **A promotion removes the marker in the commit that promotes it** — the recordable event Consequences requires — and a cut reaches the mechanism's own text *and* every reference that accreted around it while it ran.

**Until [#17](https://github.com/Grimblaz-and-Friends/tradecraft/issues/17) lands, this road is open only to a trial seat in a review panel.** Properties 4 and 6 need a ledger value that attributes a row to a trial, and §5 has none — `found_by` names seats and stages and grows only by amending that section. A **seat** escapes this, because seat names are open in `found_by`: a trial seat's rows are attributable and its trigger countable in distinct `source` values. A gate procedure, a skill or a script has no such surface, so neither property can be discharged for it and it may not be admitted yet. Stated here rather than only on the issue, because a road whose reachable width lives outside the tree is one a session will read as open.

**Even for a seat, the ledger cannot say the trial ran clean.** A seat that finds nothing writes no rows, so *ran and found nothing* and *never ran* are the same silence in the instrument — the identical shape this road's own evidence unit was faulted for, one level down, inside the escape hatch. The distinguishing fact exists elsewhere: the review report names which seats were staffed and which were swapped in, and every row's `ref` reaches it. So property 3 reads the report for **whether** the trial ran and the ledger for **what it found**, and a seat trial whose panel produced no report cannot be retained on the ledger's silence alone. Recording the split rather than pretending one surface carries both.

**Nothing already in the tree is a trial.** This road binds mechanisms admitted from this amendment forward; anything that reached prose or code by the ordinary road — the convergence gate among them — stays there, unmarked, and is not exposed to property 3.

**A cut trial leaves no record beyond the ones that already exist** — the pull request and this ADR's own status line, immutable and append-only respectively. A dedicated graveyard would be a maintained corpus, the exit ADR-006 §2 forbids. **The cost is real and is not being hidden:** a cut trial is then discoverable only by reading history, so its lesson resurfaces weakly, and someone may try the same thing twice. That was ruled acceptable against the cost of a corpus (owner, 2026-08-16). Nothing caps how many trials run at once, on the same day's ruling: promotion here is *"earned, never speculative"*, and a cap set with zero live trials would be a figure with nothing behind it — while a number that does reach this prose becomes part of the rule and has to be right. Property 3 is the pressure; if trials accumulate and it is observably not cutting them, that record earns the cap.

**This road's own falsifier is property 1's boundary failing in use.** Everything rests on a reader telling *a thing a competent session could do from the goal alone* from *a thing that must be the same across sessions*. That line is untested prose, and it took two drafts: the first was vacuous — it tested whether a thing existed before it was written, which nothing does, so it admitted all prose — and was caught by this section's own review before any trial ran. If the line does not hold **in use** — if trials are admitted for things that had a judgment-tier form all along — the failure is the incident that earns a stronger material, and this section is demoted or replaced rather than defended (owner, 2026-08-16).

**The evidence for this section is thin, and saying so is part of it:** two incidents, one day, in a repository days old. What weighs against that is the class being thrice-recorded above and the cost being live rather than hypothetical — two open items were stalled behind the closed loop when this was written. It is enough to open a road and not enough to claim the road is proven. **Re-read this section when the ledger carries a row whose `found_by` or `source` names a trial** — the first countable event that can say anything about it, and one that cannot occur until [#17](https://github.com/Grimblaz-and-Friends/tradecraft/issues/17) lands.

## Consequences

- New rules are cheap to try (they start as nothing) and expensive to fossilize (promotion requires an incident record). Mechanisms, which cannot start as nothing, are cheap to try by trial and expensive to keep (retention requires evidence the trial produced).
- Code volume stays proportional to *proven* stability, which is the brittleness control: when models or requirements change, the demolition surface is small.
- Every promotion and demotion is a recordable event, which is what lets process weight be governed by evidence (ADR-006).
