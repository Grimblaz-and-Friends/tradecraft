# ADR-006: Process defaults — start light, escalate on evidence

**Status:** Accepted 2026-08-15 · Amended 2026-08-15 (review made artifact-positional, not implementation-only) · Amended 2026-08-15 (differentiated panel made the default for substantial artifacts; seat attribution added to the ledger — evidence: the seat-level mining of the predecessor's review record, [issue #1](https://github.com/Grimblaz-and-Friends/tradecraft/issues/1)) · Amended 2026-08-16 (§5's phase vocabulary split into position and stage axes, `found_by: owner` added, `ref` required to enumerate findings — evidence: every row then written held one value per phase field, making §5's own retirement test unable to return anything but "no" — [registry](../evidence.md), [issue #5](https://github.com/Grimblaz-and-Friends/tradecraft/issues/5)) · Amended 2026-08-16 (`catchable` given a detectability test of its own, the burden's direction and the classifier named; the convergence gate's procedure written down and the upstream artifact rehomed to the work's issue — evidence: the preventing-decision rule set `catchable` from `introduced`, so the retirement test keyed on a field forbidden to disagree with its neighbour on all 253 rows, and the gate settled in #5 and piloted in #6 appeared in no tracked file — [issue #7](https://github.com/Grimblaz-and-Friends/tradecraft/issues/7))

## Context

The predecessor started heavy and spent years earning its way lighter: a five-stage pipeline as the entrance, a five-pass review panel, and filing-by-default that turned every unit of work into two or three tracked follow-ups (324 open issues; 40% untouched for 90+ days). Its own measurements pointed the other way: the widest review panel once sustained a *false* finding, while re-running fixes cheaply and reliably caught real defects the fixes themselves introduced (the per-cycle records are in evidence.md); the instrument for right-sizing process (a phase-containment ledger recording where defects were introduced vs caught) was the right idea, added years too late to shape the defaults.

## Decision

Invert the predecessor's defaults; keep its instrument from day one.

1. **The minimal lane is the entrance.** One conversation takes work from intent to done. Heavier lanes (staged design, deeper review, unattended runs) exist and are opt-in — chosen for cause, not defaulted into.
2. **Review attaches to artifacts, not only to code.** A framing, a design, a plan, and an implementation are each reviewable artifacts, and a defect is cheapest caught at the artifact where it was introduced — a design flaw found in the design costs a conversation; the same flaw found in the implementation costs the implementation. So escalation has **two axes**: *depth* (a wider or stronger review of one artifact) and **position** (reviewing an earlier artifact before building on it). When risk justifies exactly one escalation, position usually beats depth. In the minimal lane this costs almost nothing: the pre-implementation artifact may be a stated approach a paragraph long, and its review *is* the convergence gate (ADR-005) — the check always runs; what's opt-in is a dedicated adversarial challenge of the design or plan before implementation begins.

   **The convergence gate's procedure**, written here because it was settled in [#5](https://github.com/Grimblaz-and-Friends/tradecraft/issues/5), piloted end to end in [PR #6](https://github.com/Grimblaz-and-Friends/tradecraft/pull/6), and then existed in no tracked file for the twelve days between — a process lesson living only in an issue comment and a PR body, which is the failure ADR-008 forbids and this section had been committing about itself.

   - **It fires before the first line of implementation**, on any change carrying a pre-implementation artifact. What the owner uniquely decides is ADR-005's convergence question — *is this the approach?* — and the artifact is affirmed, amended, or rejected as a whole. Nothing below the trivial floor reaches it; that floor is **not yet stated**, and until it is, the gate's scope is a judgment the session declares and the owner can overrule.
   - **The artifact lives on the work's issue**, as a comment. This replaces the branch file [PR #6](https://github.com/Grimblaz-and-Friends/tradecraft/pull/6) piloted, which had two holes its own record named: multi-PR work breaks the "empty by construction" property for the whole interval, and the artifact's identity dies with the branch. An issue closes both, and it was excluded from the original choice by being ruled out rather than rejected (§4). The predecessor's 377-line comment protocol is not inherited with it: that cost bought a machine-parsed versioned record, and this artifact is written once, read by people and agents, and parsed by nothing. **A revision is a new comment, latest wins** — comment edits are invisible where the thread is read, and append-only ordering needs no reconciler.
   - **Its shape is weighted to acceptance criteria and the boundary statement**, on #5's experiment: of four clean catches, three came from criteria and one from the boundary, and nothing was caught by exploring options. Criteria state what a nonconforming run looks like, so silence cannot pass as conformance. Rejected options take §5's three exits and never accumulate a corpus.
   - **The affirmation record is the owner's own reply**, carrying a timestamp the session cannot author. An agent writing down that the owner agreed is not the record — it is the class of evidence the ledger's `found_by: owner` exists to stop being invisible, and it is not durable in the one direction that matters. Implementation begins after the reply, and the ordering is checkable from the thread rather than asserted.
3. **Review default at any position, scaled by the artifact's weight.** For routine changes: one adversarial pass that reads the artifact **cold** — before any prior findings, self-review, or earlier ledgers are exposed to it — then an evidence-bound defense, then mandatory re-validation of fixes; there is no judge, and defense's evidence verdicts terminate. For substantial artifacts (newly written foundational prose, new scripts, high blast radius — and when in doubt, this lane, since going below the default is bought only by ledger evidence): a **differentiated panel of four seats is the default, not an escalation** — the roster, its staffing, and its canonical seat names live in the practice's skill, [skills/adversarial-review](../../../skills/adversarial-review/SKILL.md) — then defense, then a judge whose job is independent re-execution of contested evidence and severity settling (a separate judge is earned by a panel-width ledger). Every review records which lane was chosen, and why, in its review report, so the classification itself stays auditable. This inverts this section's first version, which made one pass the default everywhere: the seat-level mining of the predecessor's review record ([issue #1](https://github.com/Grimblaz-and-Friends/tradecraft/issues/1), 2026-08-15) overturned it — across the six review rounds where per-seat attribution survives (116 sustained findings), a single pass kept 12% of the sustained yield and lost nearly every critical and high, the *best* single seat chosen with hindsight still kept only 46%, seats' unique yields barely overlapped, and no seat was consistently strongest (the best seat's identity changed nearly every round). The same rounds set the width: the best three seats retained roughly 75–100% by round, the fourth seat's marginal yield stayed real (up to a fifth of a round's sustained findings, at times including highs), and the fifth's went thin — hence four, wider only by declared risk. Three bounds keep the panel honest: **no clone seats** — a seat is added for a lens or vantage the panel lacks, not for a second pass at one it has. Stated honestly this is a judgment rather than a measurement: the predecessor's same-lens pair did sole-find real defects, so redundancy is not worthless; differentiation is simply what the seat record measures, and concurrence between passes has amplified a false finding — in the recorded instance across two tiers, which is the weaker case and still held. Revisable by `found_by` evidence in either direction; **every finding's finder is recorded** (`found_by`, §5) so seats retire by ledger evidence — the instrument the predecessor never had, which is why its seat question stayed unanswerable across its whole measured corpus (~850 entries at mining, session-measured); and **recurring defect classes are closed by lens promotion (ADR-002), never by adding seats** — the predecessor's best-documented escape survived fifteen seat-readings across three artifacts plus two post-fix cycles, fell to a differently-positioned lens, and stopped recurring only when a checklist lens was worded to catch its class. Defense is mandatory at every depth: it is what makes width safe (in the predecessor's record it killed 40+ false or inflated findings and originated 8+ sustained ones, including a critical). Fix re-validation is mandatory at every depth, **executable rather than a re-read** — every reading stage, defense included, showed shared blind spots that only live runs caught — and scoped to **every branch the fix touched**, because the escaped class recurred three times in its own fix's mirror image. Depth and position are escalated per-change by declared risk (wider panels, external fresh-session reviewers), and de-escalated only by ledger evidence — in both directions, weight follows evidence, never cost arguments and never habit.

   **For an implementation artifact, the review runs on the pull request, and running it is never a question.** Publish the branch and open the PR *first*, then run the review, then reconcile whatever automated reviewers posted while it ran. The ordering is the point: they start within seconds of the PR opening, so publishing first converts the external pass from a serial cost into a concurrent one. Scope, stated because the unqualified form of this paragraph collapsed two things it should not: **this sequence is about artifacts that have a branch and a PR.** The upstream positions §2 makes reviewable — a framing, a design, a plan — have neither, and their review is the convergence gate, which is a human gate and does ask. Nothing here reaches them. Within this sequence, **running the review is a check, not a gate** (ADR-005): approving the work approves its review, and an agent that finishes a change and hands the review back as a command for the human to run has invented a gate the charter does not have. One seam inside it does lawfully ask — §4's opening ledger read batches any open `owner-pending` rows into a single argued question — and that question is not suppressed to keep the sequence tidy. The release gate is untouched: the sequence ends at a reviewed PR, and merging remains the human's.

   **The pull request body states what it closes.** `Closes #N` for every issue the change discharges, **or one line saying it closes none and why**. The second half is the load-bearing one. Closing keywords fire only from the PR body or from a commit landing on the default branch — never from a comment — so an issue whose work has landed otherwise stays open in silence, and *silence and a deliberate no are the same string*. That ambiguity is not hypothetical: [PR #6](https://github.com/Grimblaz-and-Friends/tradecraft/pull/6) merged with no keyword, and four panel seats, a defense, a judge, a post-fix cycle and an external reconciliation all read that body without being able to notice, because a PR that lawfully closes nothing looks identical to one that forgot. Stated as prose rather than a guard on purpose: not every PR closes an issue, so a check cannot fail hard without an escape hatch, and a warn-only check is the shape that gets ignored — the "closes none, because X" half is what would make a future guard checkable at all, by converting an absence into an assertion. Recurrence is provable rather than arguable: the miss is ledgered (`O4`, `found_by: owner`, `caught: post-merge`).
4. **Filing is the exception — for findings.** **This section governs findings, not work.** A unit of work may hold an issue for the ordinary reasons any tracker exists: it is the durable identity the work is discussed under, the home its pre-implementation artifact can live in (§2), and the thing that survives a branch. Nothing here discourages that, and reading it as "this repo does not file issues" is a misreading that has already cost something — an upstream artifact was designed onto a branch file plus a pull-request snapshot, with known holes at multi-PR work and at branch deletion, because the issue option had been quietly ruled out rather than rejected. The predecessor's failure was **filing findings by default**, two or three per unit of work, until 324 sat open with 40% untouched for 90 days. That is the thing being prevented; a repository with almost no issues is not evidence of health, and this section is not an argument for one.

   A finding's default disposition is *fix it now* or *drop it with a one-line reason*. Its two lawful homes are the change that found it, or a guard (ADR-002 promotion) — a guard fires when the condition recurs; an issue fires never. Proposing a tracked follow-up requires stating why both other homes were rejected, and the proposal must pass the pickup test: would this actually get picked up if time opened tomorrow? A finding that turns on a decision only the owner can make is neither filed nor dropped: it is recorded with disposition `owner-pending` and **resurfaced from the ledger** — every review's opening ledger read batches the open ones into a single argued question at a phase seam (ADR-005), and a row still open after several such surfacings has failed the pickup test in fact, so it is re-dispositioned `recorded` with a one-line reason. The owner's queue lives inside the instrument that already gets read, rather than in a backlog that does not.

   **What `owner-pending` is for, stated because the mechanism reads as a parking space and is not one.** It exists so that work continuing *while the owner is absent* does not lose a decision it cannot make — a holding pen for unattended stretches, not a queue to accumulate in. **When the owner is present and the row comes up, the conversation converts it to a decision;** carrying it forward through a discussion in which it could have been settled is the failure, not the resurfacing. An agent that surfaces such a row owes a recommendation, not a menu. Recorded on the owner's own framing, 2026-08-16, the day the disposition was first used at all — one row, one conversation, converted the same day.
5. **The ledger exists, with a defined shape.** Home: `docs/ledger.jsonl`, one JSON object per line with required fields `{id, date, artifact, severity, introduced, catchable, caught, source, disposition, found_by, ref}`. Field contracts: `date` is an ISO `YYYY-MM-DD` day; `source` names the review event that produced the row and `id` is unique within it, both strings, so the pair `(source, id)` is globally unique; `disposition` is one of `fixed | reworded | recorded | owner-pending`; `found_by` is a non-empty string naming the seat or stage that first surfaced the defect (a canonical seat name from the skill's roster, `defense`, `judge`, `post-fix`, `external`, `ci`, `owner`, `consumer`, or `unrecorded` for rows predating the field) — **`owner` is not decoration**: the maintainer has been functioning as an unrecorded finder, and the decisions that reshaped this very ADR arrived that way, so without the value the instrument's denominator silently excludes exactly the catches an upstream review would be substituting for, written as a lowercase name of letters, digits and hyphens so one seat occupies exactly one bucket — a merged finding's row carries its primary (first-surfacing) finder, the review report's merged ledger is where dual credit lives, and this field is what lets a seat be retired or added on evidence instead of argument; `ref` is a URL to the durable surface carrying that review's findings — because the row itself holds no description, so without it a row proves a defect occurred but never what it was, and a later claim that a class *recurred* cannot be checked at all. Two properties. The second was **under-specified and unenforced** until 2026-08-16, not absent: the prior text asked for a surface "carrying that review's findings *in full*", which already demanded more than counts and highs — this amendment sharpens those words rather than supplying a property that was never there, and an earlier draft of this sentence claimed otherwise while deleting the very words that carried the weaker form. It must **survive a squash-merge and branch deletion**: a PR, an issue, or a squash-merge commit on the default branch does; a branch SHA may not. And it must **name findings individually** — a surface reporting only counts, severities, and the highs does not discharge this field, because a reader arriving from a row still cannot learn what that row was. **The historical corpus does not meet this property and is not claimed to** — most rows point at a real record of a review that never wrote down what each finding was ([the rate, its bias, and the re-aiming experiment are in the registry](../evidence.md)). That is a recorded debt, not a passing grade, and it is why this property binds reviews from here rather than being claimed as satisfied. The remedy is the review practice recording per-finding descriptions on the durable surface, since counts, severities and the highs are what it records today. It is **not** re-aiming rows at whichever surface reads richer: that was drafted in this amendment and reverted once measured, because a row resolves by its `id`, and prose describing findings without naming them cannot answer what `M25` was — the only question a reader arriving from a row is asking. The artifact vocabulary — what kind of material the defect sits in — is `constitution | repo-docs | skill-prose | script | lint | tests | ci | packaging`.

   **The remaining three fields are two axes, not one.** `introduced` and `catchable` name **artifact positions**: where the defect was made, and the earliest position from which it could have been caught. Their vocabulary is §2's own list of reviewable artifacts — `framing | design | plan | implementation`, ordered as written — plus `unrecorded`, which is **outside that order** and is not a position at all. `caught` names the **review stage** that actually found it: `authoring-review | adversarial-review | post-fix | external | ci | post-merge | consumer | unrecorded`. A defect whose preventing decision belonged to an earlier position is `introduced` there even when no artifact existed to hold it — the missing artifact is what made it invisible, not what made it absent. **That rule governs `introduced` alone.** Until 2026-08-16 it governed both, and the reason given was that `catchable` is the field the retirement test keys on — which made the test key on a field forbidden to disagree with its neighbour. Eight rules keep the axes honest.

   **`catchable` is a claim about detectability, and it is tested by writing the sentence.** A defect is `catchable` at position P when the sentence the P-artifact would have had to contain to prevent it **is writable using only what was knowable at P**. A bare "a design pass would have caught this" does not discharge the test; the sentence is constructed, and if constructing it requires knowledge that arrived later, P is not the answer and the test moves downstream. This is the method [#5's experiment](https://github.com/Grimblaz-and-Friends/tradecraft/issues/5#issuecomment-5305941143) already ran, promoted from an experiment to the field's definition — the promotion is what it earns; **its 4-of-8 result mandates nothing**, having been run on rows pre-selected and judged by one author, and no threshold, rate or tolerance anywhere in this section rests on it.

   The shape the axis exists to capture is `introduced: design, catchable: implementation` — made early, detectable only once the artifact existed. **No row in the corpus is that shape**, and one appearing is not required for the test to be correct; if none ever does, the axis reads flat and that is a result the instrument can now honestly produce, rather than one its own rules guaranteed.

   **The burden falls on the direction the classifier benefits from.** `catchable` defaults to `introduced`; a deviation is argued in the review report, never silent. The asymmetry is deliberate and runs one way: a classifier who wants a standing pre-implementation review is served by `catchable` reading *upstream*, so **an upstream deviation must be argued and a downstream one may be recorded on the test alone**. Arguing in the direction that weakens the case for more process is not where the incentive lies, and demanding argument there would restore the collapse by making the cheap answer the identity again.

   **The classifier is the finder, not the artifact's author.** `found_by` already names the finder on every row, so this costs no new field and stays checkable after the fact. A defect's author judging whether their own artifact could have caught it is the interested-party problem [#5](https://github.com/Grimblaz-and-Friends/tradecraft/issues/5) named as this investigation's weakest point; it is not solved here, only moved off the party with the strongest interest. Where finder and author coincide — `found_by: owner`, or a self-review — the row says so by that field alone, and the coincidence is readable rather than hidden.

   **This test binds from 2026-08-16 forward, and the 253 existing rows are not reclassified.** Re-judging a closed corpus against a new test, by the same parties, is the interested-party problem operating retroactively and at scale — and it would manufacture exactly the variance this amendment must not be able to produce on demand. The corpus is a recorded debt, on the precedent `ref`'s second property set in the same section. Rows written before the split keep `unrecorded`; rows written between the split and this amendment keep `catchable` as the old rule set it, and are read as introduction positions.

   **`unrecorded` means one thing: the position was not judged.** It is not a fallback for a defect whose position *was* judged and fits nothing listed — that reading would restore exactly the double duty `authoring` was retired for, where one value covers both "we looked" and "nobody looked" and the retirement test cannot tell them apart. A judged position with no lawful value is a **signal that the vocabulary is short**, and the row waits on the amendment rather than absorbing the gap silently. That is what makes the growth trigger fire instead of rot.

   **A new position or stage is added by amending this section**, editing the lint's single definition site. A vocabulary that cannot grow files its consumers under the wrong heading: the predecessor's token schema declares its *"closed five-value phase enum is **deliberately not extended**"*, and a distinct flow's checkpoints are consequently emitted under another phase's name, with an explicit instruction not to add one ([open-for-work § Gate-decision tokens](https://github.com/Grimblaz/agent-orchestra/blob/main/skills/open-for-work/SKILL.md#gate-decision-tokens)). Stated fairly, that source defends its own mapping as apt and gives a mechanical reason — a new value fails validation before reaching its reconciler. The exhibit is the *cost structure*, not an admission: once a vocabulary is closed, the cheapest lawful move is always to file under an existing heading, and the reasons for doing so will always look good locally.

   **Seven properties of this section are stated and not enforced in code**, named together so a reader can tell which of §5's MUSTs the lint carries: the ordering between the axes (`introduced` no later than `catchable`, over the four ordered positions only); both `ref` properties below; the correspondence between this prose's vocabularies and the lint's sets, which no check reads; `catchable`'s detectability test; the burden's direction; and the finder-classifies rule. A rule the lint does not carry must say so, or a reader assumes CI is holding a line that nothing holds.

   Two reasons sit behind that list, and they are not the same reason. The first four are unenforced *for now* — new semantic rules with no incident record, and ADR-002 earns code by recurrence, not by plausibility. The last three are **unenforceable in principle**: each is a judgment about what a defect was and what was knowable when, which no check can read off a JSON row. Distinguishing them matters, because a reader waiting for a guard that can never arrive will mistake a permanent property of the instrument for a backlog item. What *can* be checked about them is downstream and negative: whether a deviation was argued at all, and whether `found_by` names the artifact's own author — and both wait on recurrence like anything else.

   **What a row records when the catch arrives outside a review event.** `found_by: owner`, `ci`, and `consumer` name finders that produce no review report. Such a row takes `source` as the event that surfaced it — a conversation, a CI run, a consumer report — named as durably as the surface allows, and `ref` pointing at whatever record exists. `ref` is required and must be an `https://` URL, so a catch with no durable record cannot be written until one is made — post a comment naming the finding and point at that. The row is never dropped for want of a surface; the surface is created, because a catch left uncounted is the failure this field exists to prevent.

   Rows are validated by the packaging lint until the core library exists to own emit/validate (ADR-002's boundary-format rule, discharged in its smallest honest form).

   **The retirement test, and the full record of its rewriting.** What buys a standing pre-implementation review is **`catchable` at an upstream position — `framing`, `design` or `plan` — recurring in the ledger**; its absence is what retires one. The sentence has been rewritten twice, and **both halves changed**, so both are recorded here rather than one. A third change followed, in which **the sentence did not change at all** and what it means changed more than either rewrite — recorded below on the ground that this paragraph exists for changes to the test, not for changes to its characters.

   *The second conjunct.* The original read `"catchable at design, caught at implementation"`. The 2026-08-16 split made `implementation` a position rather than a stage, so `caught: implementation` became unwritable, and the amendment's first draft silently substituted `caught: adversarial-review` — a value **every row in the corpus already carried**, which made the conjunct select everything and discriminate nothing. It is therefore **dropped rather than replaced**.

   *The first conjunct.* The original said `catchable at design`; this text says `framing`, `design` **or** `plan`. That broadening is defensible on its merits — a pre-implementation review covers all three positions, so a defect catchable at any of them is evidence for one — but it was made silently, in the paragraph whose stated purpose is recording exactly this kind of change, and a first correction of that paragraph then *misdescribed* the original as having paired the broadened clause with `caught: implementation`, which it never did.

   *The redefinition, 2026-08-16.* `catchable` stopped being set by the `introduced` rule and became a detectability claim with its own test. The test's characters are identical either side of that change; its content is not, because the term it selects on now means something the old rule forbade it to mean. **A reader diffing this section would see the test as untouched, which is why it is written down here.** The prior two failures were both a sentence changing while the record stayed silent; this is the mirror case — the record speaking while the sentence stays still — and the paragraph would have missed it on its own wording, which asked only whether the sentence had been rewritten.

   Recorded at this length, and three times over, because a governing sentence rewritten in passing is the failure this section exists to prevent, and the correction reproduced the defect it was correcting. The second conjunct's substitution was caught by the defense stage of the amendment's own review, after four seats read the new text forward and none diffed it against the old; the first conjunct's broadening was caught only by the post-fix pass over that correction. The redefinition was caught by neither, because it was a stated acceptance criterion of the change that made it — which is the only one of the three mechanisms that ran *before* the defect could land.

   **That test was rigged until 2026-08-16** — the vocabulary it replaced held one value per field across every row then written ([registry](../evidence.md)), so the absence was guaranteed by the schema and the loop could return only one verdict. An evidence loop whose instrument cannot express the finding it tests for is not evidence. The corpus predating the split carries `unrecorded` for both positions, on the checkable ground that the old vocabulary could express no position earlier than the prose — not on any claim about what its authors did or did not judge. **A schema that can express variance is not yet an instrument that has shown any**, and this amendment's own rows are the first evidence of how far that gap runs. They exercise `framing`, `design`, `implementation`, `post-fix`, `external` and `authoring-review`, so `introduced` and `caught` do vary. **`catchable` does not.** It is identical to `introduced` on all 253 rows.

   **The second rigging, and why the first fix did not reach it.** The 2026-08-16 split fixed the *schema* — the vocabulary could finally express an upstream position — and left the *rule* intact, and the rule was doing the same work: a defect whose preventing decision belonged upstream took that position in both fields, "which is nearly always". So the test still keyed on a field that could not disagree with its neighbour, and the loop could still return only one verdict. The split's own text recorded the identity as an observation about the corpus; it was a consequence of the rule, and stating it as data about the rows read as though more rows would settle it. **They would not have.** Under the old rule no possible corpus separates the axes, so the second amendment is not a refinement of the first — it is the same defect one level up, found because the first fix's stated caveat was read as a live question rather than a closed one.

   This is also the honest bound on what the present amendment claims: it removes a rule that forced the answer. It does not show the axis separating, and it cannot, since it declines to reclassify the corpus and no new rows exist yet. **An instrument that no longer guarantees its own answer is not yet an instrument that has produced one** — the same sentence the split earned, now owed by its successor.

   The case where they *can* differ is worth naming, because it is the one the position axis was really built to measure: a defect **introduced early and detectable only later** — `introduced: design, catchable: implementation` — the class of thing that cannot be sorted out before the artifact exists. No row in this corpus is that shape yet. Until one is, the retirement test is answered by `introduced` wearing `catchable`'s name, and that is a weaker instrument than this section previously claimed to have built.
6. **Quality is still the first constraint.** None of the above relaxes *coverage* — what gets looked at — only the ceremony around it. When lightness and a needed check conflict, the check wins; the ledger is how a check proves it is no longer needed.

## Consequences

- Process weight is a managed quantity with an evidence loop, not a ratchet.
- The backlog measures intent: everything in it passed the pickup test, so it stays small enough to be real.
- Heavier process must recruit evidence to exist, which means the ledger gets consulted, which keeps the loop honest.
