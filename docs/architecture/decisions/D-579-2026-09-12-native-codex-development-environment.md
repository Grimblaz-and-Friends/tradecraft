# D-579 — A native Codex development environment

**Purpose:** preserve the choices behind #578's local setup and Python alignment. **Audience:** a future maintainer changing the development entry point or CI. **Success:** they can distinguish the reproducible repository setup from this owner's machine-local repairs and find the evidence for each.

The owner affirmed [the setup brief](https://github.com/Grimblaz-and-Friends/tradecraft/issues/578#issuecomment-5643877247), including Python 3.14 locally and on both CI operating systems. The [artifact](https://github.com/Grimblaz-and-Friends/tradecraft/issues/578#issuecomment-5643930678) settled in one cold round, WOULD, before implementation.

`.python-version` and `requirements-dev.txt` are shared inputs to local setup and CI. `tools/dev.py` creates a worktree's own `.venv`, invokes it directly without shell activation, and rejects an incompatible interpreter or existing environment without deleting it. The command is Python so the same implementation runs under Windows and Linux. Its failure paths, environment preservation, command forwarding and separate temporary ownership are exercised by `tools/tests/test_dev.py`. The checked-in Codex environment invokes this command rather than carrying another copy of setup logic.

Test scratch belongs outside every Git checkout. The first `python tools/dev.py check` put it under `.tmp` and returned 37 failed, 1194 passed: non-repository fixtures discovered the checkout's parent Git context and lint fixtures inherited its ignored path. The rerun after moving it outside passed all 1,231 tests. Distinct temporary parents prevent one invocation's cleanup from removing another's files. This choice matters beyond Windows permissions; a writable in-repository directory was still wrong. The follow-up checks `.git` markers at the resolved scratch path and every ancestor, matching the fixture's discovery mechanism. A worktree-local boundary alone missed sibling scratch under the enclosing repository; real nested and separate worktree regressions expose that failure, including file-form markers.

The local plugin and keyring repairs are [recorded on the issue](https://github.com/Grimblaz-and-Friends/tradecraft/issues/578#issuecomment-5644026323), not shipped to adopters. They retain the Windows sandbox, update the separate Codex and Claude installations, and route authorized authenticated GitHub operations through approval-managed host execution. Fresh Codex probes demonstrated installed-charter loading and ordinary sandboxed pytest with the persisted scratch setting. Claude's initial probe failed on expired OAuth; after the owner logged into the CLI, a fresh installed-plugin probe matched the source charter's opening, ceremonies and tail. Its first authenticated response used prose, so the successful probe used structured output and passed its prompt through stdin to the installed native executable. No model default was changed.

The installed-plugin check exposed #536 while verifying the repair. Its prompt requested the final prose paragraph but `_charter_evidence` took the last blank-line block, now a list of names already available in the skill index. The selector now takes the final prose paragraph, and the prompt names that boundary explicitly. `test_tail_requires_prose_even_when_the_charter_ends_in_public_skill_names` accepts the paragraph and rejects the list; the live `python tools/check_codex_compat.py --model gpt-6-astra --reasoning xhigh --timeout-seconds 300` passed. This preserves the existing evidence fields rather than adding another anchor.

The local-environment TOML was checked against the installed app's schema and serializer, with its commands exercised separately. That does not claim an actual UI-created worktree was exercised. The PR's consumer note and Windows/Linux CI runs carry the remaining operational evidence.

The [terminal review](https://github.com/Grimblaz-and-Friends/tradecraft/pull/579#issuecomment-5644227507) required stronger reuse and scratch checks. `tools/tests/test_dev.py` now distinguishes real isolated and system-site environments, rejects a foreign interpreter, preserves incomplete environments with move-aside recovery, and rejects resolved in-checkout scratch for both explicit and default selections. Python 3.14 is required to create a new environment; an older outer interpreter may select an already verified 3.14 environment, addressing the external Codex finding without changing the command surface.

The same ruling promoted recorded entry 330: CI subscribes explicitly to opened, synchronize, reopened and edited pull-request events. The declaration checker reads a mutable PR body, so a body edit needs a fresh check. The original remedy ran every job on every edit; two full runs on the same head and CodeRabbit's body edits demonstrated its recurring cost. The owner [approved narrowing that behavior](https://github.com/Grimblaz-and-Friends/tradecraft/issues/578#issuecomment-5647129666), but the conditional matrix at `a404dcc` left both required OS checks **Expected** in GitHub's merge gate. Older passing results remained readable; their retained IDs did not establish that the latest workflow run satisfied branch protection. The owner then [approved restoring the full matrix](https://github.com/Grimblaz-and-Friends/tradecraft/issues/578#issuecomment-5647373492). Every subscribed event again runs both OS suites and the declaration job, accepting the repeated test cost until the optimization is reconsidered separately. The conditional name and job gate are removed; required check names and branch rules remain unchanged. The terminal judge's full-run remedy is restored, and the prior duplicate issue #466 stays closed.

The same approval keeps Python 3.14 alone because the owner is currently the only user. Development and both CI runners share that version; adding earlier-interpreter coverage would impose a compatibility obligation the owner does not currently need. No minimum-version promise for other adopters is inferred from the development declaration.
