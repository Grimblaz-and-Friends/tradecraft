# D-933 — A revision resumes its draft's author and is given what it revises against

**Purpose:** trace #919's decision that a named `run artifact` revising a draft decides continuity from that draft's own history, and that its composed prompt carries the verdicts and holder decisions the revision answers to. **Audience:** a future session changing artifact continuity, the author pairing, the revision prompt or the cap procedure. **Success:** it can recover why an edited draft goes fresh rather than refusing, why an unreadable return refuses, why only one instalment's `would-not` verdicts are carried, and why a stopped attempt older than the draft is not recovered, without restoring recommendation-keyed continuity.

The owner's [affirmed brief](https://github.com/Grimblaz-and-Friends/tradecraft/issues/919#issuecomment-6576570001) governs, quoted at the head of the [settled artifact](https://github.com/Grimblaz-and-Friends/tradecraft/issues/919#issuecomment-6576822600), which was settled on `would` in [6576981396](https://github.com/Grimblaz-and-Friends/tradecraft/issues/919#issuecomment-6576981396). The holder's readings govern the build: H1–H3 ([6576991767](https://github.com/Grimblaz-and-Friends/tradecraft/issues/919#issuecomment-6576991767)) adopt the cold seat's non-blocking observations, a later reading ([6590054484](https://github.com/Grimblaz-and-Friends/tradecraft/issues/919#issuecomment-6590054484)) accepts the build's two departures and adds H4 and H5, and the reviewer-round reading ([6591432565](https://github.com/Grimblaz-and-Friends/tradecraft/issues/919#issuecomment-6591432565)) adds H6. The holder chose ordinary / connected. The product harm answered is the one the issue records on Daemon #103, #105, #93 and #94: product plan revisions ran fresh behind hand-written dispatches, so the author re-read everything, sometimes worked from a draft it was pointed at rather than given, and let unjudged additions into a plan its builder follows.

**Continuity is decided by the draft, not the recommended stage.** `_named_continuity` took the recommendation's continuity only when the recommended stage was `artifact`, so `artifact-cap` and `merged-pull-request` both fell to `fresh`; ten Claude-authored revisions ran fresh that way, one of them Daemon #94's stage 2, which a fix keyed to `artifact-cap` would have missed. The draft under revision is the current term's latest draft posted after `WorkState.instalment_boundary`, the latest `merged_at` among merged implementing-pull-request candidates (I5). That boundary is computed before `read_state`'s ambiguity return, so a third instalment still has one, and it needs no `--instalment` from the holder. The cap count and the recommendation are unchanged, because they belong to #928.

**The author is proved by content (I1).** `_artifact_author` pairs the draft comment with an author bundle's retained return by the cold verdict's own rule, now the shared `_return_match_length`: tradecraft markers removed, line endings and trailing whitespace normalized, the return a run of whole lines in the comment, the longest match winning. It survives the holder's marker line and any note posted above the return, and adds no bundle field. Candidates are the term's author bundles completed after the latest merge and no later than the draft comment, scoped to the holder and instalment; an earlier instalment's return can neither write this draft nor block it, even when no `--instalment` narrows the scope. Bundles of an unsupported dispatch schema are not candidates. The four outcomes:
- `proved`: resume that bundle's session in a fresh copy of the holder's current commit (`_resume_source` selects the paired bundle, not the latest).
- `none`: start fresh and say so. An edited or hand-posted draft is here, not under `unprovable` (I2): every in-scope return was read and none matches, which proves absence. Resuming the latest author would hand a session text it didn't write; refusing would add a step whose only answer is "go ahead". A matching turn with no session identity is here too (I3), because a refusal would be permanent.
- `unprovable`: refuse naming the cause — equal matches from different sessions, an unreadable return, or a returned turn (`success`, `success_uncontinuable`, `invalid_artifact_return`) whose run records a `source_output` field but retained no return, which the launcher leaves when writing the return failed. `_named_continuity` maps it to `resume` (I8) so the one resume route refuses, as the failed-outcome escape already did.
- `first-draft`: no draft in the term or instalment; start fresh.

**An unreadable return refuses unless it is the matched session's (H3).** The artifact's I4 let a readable match override unreadable siblings on the premise that a sibling "could only have the same text". That premise is false: an unreadable bundle could be an equally long match from another session, which is already refused as ambiguous, and row 3 names a corrupt bundle among the refusal cases.

**A stopped or failed attempt is recovered first only when it is later than the draft (H1).** Without that time gate, a draft posted by hand after a failed return would resume the failed session, which didn't write the posted text. With no draft under revision, both checks are as before. The gate applies only to a finished attempt: one with no completion, an unresolved launch, a recovery error or unproved cleanup still takes the recovery route, which returns it to the holder rather than launching a second writer. `work_recovery.latest_stopped` applies the gate, so the read-only recommendation and the stopped-source selection both ignore a finished attempt older than the draft, and an unrecoverable older stop cannot refuse a proved author; only the holder's explicit `--restart-unresolved-reason` still names that attempt, because it is the holder's own choice to replace it; `_later_than_revision_draft` also gates the failed-latest escape in `_named_continuity` and the failed-latest selection in `_resume_source`. The gate compares completion, as H1 states, not launch: an attempt launched before the draft that fails after it still recovers first. A reviewer argued for launch time; that change is the holder's call and is not made here.

**The composed revision carries what the revision answers to (I6, I7, I9).** After the draft whole come only `would-not` verdicts, because a `would` settles the artifact and a `not-settleable` is discharged by the holder's own revision. They come oldest first, each labelled against the artifact under revision or an earlier draft, and only from the instalment's own drafts, so Daemon #94's instalment-1 verdicts would not reach stage 2's author. Then come holder readings posted after the later of the draft and its latest verdict; a reading before that point was made against an earlier draft that this draft already answered. A resumed author is told it wrote the draft only when the session actually resumed is the proved author's, so a stopped-attempt recovery is never told something untrue. A fresh author is told it is new and why. After a `would-not` the read-only recommendation takes the same continuity, so its launch plan never names a session the named stage would not resume. The facts gain `author` and `revision_sources`, and the launch plan gains `author`, so the retained dispatch names exactly what the revision received. A reading posted before settlement still counts for no builder; `skills/work/references/markers.md` now states that moment, and `skills/engagement/references/cold-seat.md` has the holder post its cap decisions as such a reading and diff the returned revision whole before settling `route=cap`.

**Departures from the artifact, accepted by the holder.**
- H1's specified fixture, an `invalid_artifact_return` followed by a hand-posted draft, cannot reach a draft under revision: existing marker validation already invalidates that draft ("latest artifact dispatch has a failed return"). The H1 test uses `completed_no_output` and a stopped `error` attempt instead, and a separate test pins the invalidation and the unchanged recovery.
- A bundle that recorded no return is not an author candidate. It records no author for the posted text, so a legacy bundle whose run carries no `source_output` field, or one of an unsupported dispatch schema, leads to a fresh start rather than a refusal.

**Moved tests.** `test_artifact_review_current_nonfailure_keeps_the_recommendation` became `test_artifact_review_current_nonfailure_starts_a_first_draft_fresh`: with no draft, a recommended resume now yields `fresh`. `test_would_not_without_a_newer_draft_resumes_artifact` became `test_would_not_without_a_newer_draft_revises_the_artifact`, and the would-not row of `test_each_state_table_row_routes_exactly_one_stage` now expects `fresh`: with no author on record, the recommendation after a `would-not` is fresh. `test_public_restart_after_prelaunch_ceiling_reaches_latest_launched_author` reads the older stop through the explicit restart's lookup, because its fixture's draft is newer than that stop.
