## 1. The zone wall's second direction goes in the doctrine, not in a cell

`AGENTS.md` stated the wall one way — shipped never references repo-only — which is correct and silent about the reverse. The permission lived only in code comments; `grep -rn "lawful direction" tools/ skills/ lib/` on this tree reports where, and this change adds one more statement of it in `tools/check_codex_compat.py` rather than removing any.

**The doctrine is where it goes, because that is where the rule is.** The alternative the filing left open was the `substrate` cell, which costs no always-on characters. It was rejected: a cell is shipped, so it may not name `docs/`, `tools/` or `.github/` at all, and the zone shape those names define is this repository's rather than the practice's. A cell could only have stated a general principle about a wall it is forbidden to describe, while the rule a session actually misreads stayed one-directional where it is written. **This ground is the one that carries the admission**, and it is the one to read if the placement is ever reopened.

**The evidence is two consumers, not a reading.** PR #232's two cold experience sessions, different jobs, both stalled and both resolved it by opening a neighbouring script. Both got it right; the route is what does not generalise, and a session resolving it the other way hand-rolls rather than importing `lib/winio.py` — the duplication [D-186] created `lib/` to end — with nothing failing, because the lint's zone wall checks the banned direction exactly.

**No guard decides this for an arbitrary need, which is narrower than "no guard is available".** An earlier draft of this entry claimed the mechanism tier was empty here; this change's own review falsified it. `check_stdio_wired` does check that a script needing `lib/`'s one module reached for it — import binding and call position — and its remedy text already names the resolution route. What no guard can do is decide, for a need it does not know about, that a script should have imported shipped code. The prose is admitted on the ground above, not on an empty tier.

**What this change does not yet demonstrate.** The forward claim is that the doctrine is now where the rule is. This change's own experience session reports a cold consumer writing a repo-only tool with no doubt about the permission — the PR #232 stall did not recur — while still naming a code comment as its route, because it copied a neighbouring tool as a template. The stall is gone; that the doctrine sentence is what removed it has no demonstrator.

## 3. The budget ceiling is a trigger, and the sentence has one owner

The owner observed the pattern repeating across sessions: a session seeing a budgeted file becomes reluctant to edit it, which inverts the budget's design — a tight surface is meant to *trigger* restructuring. The operative sentence already existed, in `tools/lint.py`'s budget-constant comment, a repo-only file no session editing a skill opens.

**It is hoisted to the `authoring` cell's Routing section, and the lint comment now names the cell without restating the rule.** Two half-owners of one sentence kept in agreement by hand is what that cell forbids. A first attempt at this hoist left the whole rule in the comment *and* claimed to have removed it; the review caught that, and the comment now carries a pointer only. The lint's budget findings point at the cell too, since the session that meets a ceiling unbidden meets it there rather than in a constant's comment.

**What this change is and is not evidence for.** It does not demonstrate that the three moves pay for what is added: `python tools/figures.py --base 6d75042 --cell skills/authoring/SKILL.md --cell-budget 7359`, run on the tree that lands this, reports the headroom on both surfaces and the governing-prose delta against the merge base, and both surfaces end tighter than they began. What the change does demonstrate is the behaviour the rule asks for — its own experience session put a cold consumer at a near-full `AGENTS.md`, and it performed an outflow rather than declining the edit. The rule is about what a session does at a ceiling, not about the arithmetic coming out ahead.

## 4. The cell-body strip has one owner, and a guard now says so

The rule — anything measuring a cell body uses the strip the shipped engine provides — was real, pinned by `test_the_body_strip_the_engine_ships_is_the_one_the_guard_applies`, and written down only in `tools/figures.py`'s docstring and that test's name. It was defended against the two implementations that already existed, and against a third by nothing.

**A third was already in the tree.** `tools/check_codex_compat.py` used `text.split("---", 2)[2]`, which keeps the two newlines the engine strips. Harmless where it was used — the result is only split into paragraphs — and green on both the lint and the suite, which is the filing's prediction found already true rather than forecast. It is converted to the engine, and a test measures the difference rather than asserting it. The conversion is also **stricter than what it replaced**: the review's malformed-input corpus shows it raising `CompatError` on a superset of the inputs the hand-rolled form rejected, including cases where the old code silently produced a visibly wrong body.

**A guard, not prose alone, because the admission order puts the mechanism tier first** and the filing had already said the near-miss would have been caught by one where prose would only have been caught if read. `check_body_strip_owner` is the mechanism; one line in the cell names the rule for the reader the guard cannot reach.

The design calls, made by the session and recorded here — several of them rewritten after this change's own review found the first form of the guard both too narrow and too broad:

- **The predicate turns on three properties together.** The marker and the slice must be *connected*, or every long function that merely mentions a marker reads as a strip. The receiver is matched structurally, so an attribute or a chained call is not a free pass, and a marker hoisted to a module constant — the style `tools/roster.py` already writes — is not either. And on a slice of the *tested* text it must be an unbounded **tail**, which separates taking the body below the frontmatter from reading the fields between the markers — but **not on a piece of a marker split**, where requiring a tail would lose the cheapest wrong expression there is. The first form had none of the three beyond the first and reddened lawful field readers outright; what survives that asymmetry is a field read spelled as a split, which is reported, and the finding message names the lawful spelling so the reader has somewhere to go.
- **Its bounds are stated where it is defined, as a class rather than a list of tricks**: it reaches a marker — literal, or a module-level name bound to one, however that binding is spelled — tested or split, and a subscript, *within one scope*. Outside that: a test in one scope with the slice in another, an algorithm that compares rather than splits, a marker on a class attribute, a regex strip, `pop()`, a partition tail bound to a throwaway name, and `list.index`, which no AST pass can tell from `str.index`. A first draft named two of these and read as exhaustive. A bound nobody writes down is one the next reader assumes away.
- **Exemptions are `(path, qualified name)` pairs**, so an exempt name reused on a class or in a nested scope is not thereby exempt. The **owner file is exempt wholesale** — the engine may hold helpers and deciding which of its names are lawful is a design call this check does not make — which means a second strip landing in the engine is guarded by nothing. That is said in the check rather than left to be discovered.
- **What the suite pins is the exemption set's exact membership, which is not a ratchet.** It makes adding an exemption visible in a diff; nothing reports an entry that has gone stale, and an earlier draft of this entry claimed the guarantee `check_entry_references`' recorded sets carry. It does not carry it.
- **Test files are out of scope, and the size of that blind spot is a query rather than a number.** `python tools/figures.py --body-strip-scan` reports what the predicate finds in the excluded corpus on whatever tree you are on. An earlier draft stated it as a figure, measured under a predicate that was then tightened, and the figure outlived the predicate by a factor of five — which is the failure the figure rule exists to prevent, in the change that strengthens that rule.

## 5. What was left open

- **The `authoring` cell's description does not trigger for a session writing a tool that measures a cell body**, which is #190's actual consumer. Its headroom would not carry a new trigger without a trade, and [#188](https://github.com/Grimblaz-and-Friends/tradecraft/issues/188) settled that description deliberately. The guard reaches that consumer whether or not the cell fires, which is why the guard is the primary remedy here and the prose the secondary one. This change's own experience session confirms the gap: the cold consumer never opened the cell, and asked for the rule in `substrate` instead — routed to [#241](https://github.com/Grimblaz-and-Friends/tradecraft/issues/241) with that note as evidence.
- **The class is not widened** beyond the body strip to every measurement a guard also performs. The body strip is the instance that was observed.
- **No budget constant moved.** The surfaces were made to fit; the ceilings were not raised. What a session does at a surface that is genuinely exhausted — where a refusal discharges the outflow but frees no characters and the budget check still reds — is not written anywhere a session reads, and is recorded rather than answered here.
