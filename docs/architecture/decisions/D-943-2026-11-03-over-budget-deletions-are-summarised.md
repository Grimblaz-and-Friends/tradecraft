# D-943 — An over-budget review summarises its wholly deleted files instead of skipping

**Purpose:** trace instalment 1 of #902: when the connected reviewer's composed finder input is over `MAX_FINDER_PROMPT_BYTES`, every wholly deleted text file leaves the diff for a summary entry, its base content stays readable in a second read-only directory, and only an input still over skips. **Audience:** a future session changing the reviewer's input policy, its budget (instalment 2 of #902 measures it), its coverage list or the replay. **Success:** that reader can recover why the summary applies only over the budget and to every deleted file at once, why the old content comes from the diff rather than a fetch, why binary deletions stay, and how the coverage wording stays clear of both review-notice pattern sets, without re-deriving them.

The owner's [affirmed brief](https://github.com/Grimblaz-and-Friends/tradecraft/issues/902#issuecomment-6606454720) governs, admitted on the product incident Organizations-of-Verra #518, whose pull request #557 has been held without a lab review since 2026-10-11 after a size skip. Its pre-implementation artifact was [settled on the cap route](https://github.com/Grimblaz-and-Friends/tradecraft/issues/902#issuecomment-6607705821). The holder's readings govern the build: [6607742688](https://github.com/Grimblaz-and-Friends/tradecraft/issues/902#issuecomment-6607742688) set the floor at CI and held this entry for the pull request's number, and [6608816705](https://github.com/Grimblaz-and-Friends/tradecraft/issues/902#issuecomment-6608816705) accepted the first build and its calls. The lane is ordinary / connected; the brief names a budget set too high as the panel risk, and none was bought.

**Only over the budget, and every deleted file at once.** The owner ruled "Only when over (D1)" at pickup, so an input that fits is sent byte for byte as before; `test_under_budget_launch_is_byte_identical_to_the_reviewer_before_summaries` in `lib/tests/test_connected_review.py` pins its stdin and argv digests, computed by running the same fixture against `71a639a`'s `lib/connected_review.py` and passing on both runtimes. Over the budget, all wholly deleted text files are summarised together rather than the largest until it fits, the holder's call inside row 1, because it is simpler to predict and record and makes no difference on the three skipped heads (`test_every_wholly_deleted_file_is_summarised_not_just_enough_to_fit`). With nothing to summarise, the skip keeps its old cause text exactly; still over after summarising, it names both sizes. The `lines` map that anchors findings is the one computed before summarising, so a finding on an old line of a summarised file still posts inline on side `LEFT`.

**Old content from the diff, not a fetch.** The reviewer's `base` is the pull request's `base.sha`, but its compare diff is three-dot, against the merge base, and the two differ at Verra #557 and #543 (the artifact's §2.2). Content fetched at `base` could therefore disagree with what the diff says was deleted. Every line of a wholly deleted text file is a `-` line in the diff the reviewer already holds, so the folder is rebuilt from those lines: no second GitHub call, no commit to choose, and the replay's exports need no schema change. The artifact's spike rebuilt 110 of 110 files byte for byte. One call made in the build: `execute_review` reads the diff with `read_text`, which translates CRLF to LF, so the folder is rebuilt from the diff file's raw bytes while the prompt keeps the translated text, keeping A1 true and CRs intact (`test_folder_holds_the_bases_exact_bytes_from_a_real_git_diff` covers LF, CRLF, mixed endings, no final newline, empty and multi-byte files against `git show`). Paths are checked before the folder is made and every file is created exclusively, so an unsafe path (absolute, `..`, `.`, empty, `\`, `:`, or a Windows reserved name on Windows) or a collision ends the review on the ordinary failure route with nothing written outside the folder.

**Binary deletions are not summarised.** A binary deletion's section is a header with no content, so the folder would hold nothing and the size saving is nil; it stays in the diff as before and is not listed (`test_summary_keeps_retained_sections_and_skips_binary_and_partial_deletions`).

**Read-only by the same mechanism as the snapshot.** The folder is a second value of the existing `--add-dir`, beside the snapshot, and the launch keeps `--tools Read,Glob,Grep`, `--restricted` and `--permission-mode plan`, so the finder can read it and has no tool that writes. The real-CLI check, the extended `tools/probe_connected_review_confinement.py`, had not been run when this entry was written; the pull request records its result or the departure.

**Coverage wording against both notice pattern sets.** Each summarised file joins the published "Files excluded from diff coverage" list as ``- `P` - deleted-summarised, N lines``, after the lockfile and generated entries. The wording was checked against tradecraft's anchored `REVIEW_NOTICE_PATTERNS` in `lib/work.py` and against change-proof's unanchored whole-body patterns in `proof/check.py` at `4f89467`; it puts no notice word such as "skipped" or "limited" beside "review", and paths cannot supply a phrase because `_coverage_path` escapes spaces. `test_completed_review_coverage_is_not_a_notice_or_finding` and the large-coverage continuation tests carry summarised entries whose paths spell notice phrases.

**Replay summarises only when asked, and its policy version moves.** `tools/connected_review_replay.py` gains `--summarise-deleted-files` and `--summary-threshold-bytes` (default the live budget). Without them the replay is unchanged, so instalment 2 can replay #557 and #107 as they really were. With them, a case's folder is in bounds for reads only for the case that summarised, and the option and threshold are reviewer identity, so a resume cannot mix runs. When a case summarises with preload on, the preload is recomputed on the summarised diff. `COVERAGE_POLICY_VERSION` is 3 and `coverage_settings()` gains `over_budget_summary`, because what is left out of coverage changed; the packaging test's pinned `reviewer_settings()` digest moved with it.

**Measured without a model.** `python tools/measure_connected_review_prompt.py --references summary`, run on the tree committed at `13fbc65`, composes the three skipped heads through the built functions and compares each rebuilt file's git blob hash with the merge base's tree entry. That run gave, in finder stdin UTF-8 bytes before and after summarising: Daemon #107 at `27192a8`, 1,531,247 to 420,016 with 38 files summarised; Verra #557 at `9d2d777`, 701,478 to 534,716 with 23; Verra #543 at `6f848d1`, 799,895 to 797,181 with 4, still over. All 65 rebuilt files matched their merge-base blobs (38, 23 and 4). The tool's fixed snapshot path puts its sizes 26 bytes below the recorded skip sizes, so the comparison with the 600,000-byte budget is what the run settles.

**What this supersedes.** [D-841](D-841-2026-10-03-connected-review-input.md)'s trusted preflight now refuses only an input still over the budget after summarising, and the sentence "No retained content is shortened to fit", which shipped with it in `skills/connected-review/SKILL.md` at `c484a40`, gains this one exception for the over-budget path. Everything else in D-841 stands.

**Departures, accepted by the holder as inside-row calls.**
- The A1 pin uses a fixed instruction text rather than the shipped finder contract, because lint forbids `lib/` tests from reading `skills/`; its digests were recomputed against `71a639a`'s runtime and pass on both.
- The names `over_budget_summary`, `--summarise-deleted-files` and `--summary-threshold-bytes`.
- `tools/measure_connected_review_prompt.py` gains `--references`, so the skipped heads can be measured alone and keep the API reads to them.
- A5's no-model comparison uses git blob hashes at each merge base, which equal byte equality, rather than fetching each file.
