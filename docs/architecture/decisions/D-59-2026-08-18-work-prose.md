# D-59: `artifact` gains `work-prose` for the constitution's off-tree surfaces

**Status:** Accepted 2026-08-18 (PR #59)

## Context

The `artifact` vocabulary had eight values, all naming material in the tree or the constitution itself. The statute routes obligations onto surfaces that are in neither: §6 homes the pre-implementation artifact and the affirmation record on the work's issue, and names the pull-request body as the surface carrying the floor declaration, the closes-what statement and — below the floor — the commitment announcement; §8 requires `ref` to point at a durable surface naming findings individually, which in practice is a review report on an issue or a pull request. A defect sitting in any of them had no correct value — the nearest rows sit under `repo-docs` or `constitution`.

Two instances are on the record, from different directions, which is what made the gap countable rather than argued.

**The design review on [#42](https://github.com/Grimblaz-and-Friends/tradecraft/issues/42)** — this repository's first dedicated adversarial challenge of an upstream artifact, ADR-006 §2's opt-in invoked by the owner — sustained findings across three passes (39 sustained, 9 high; 21 surviving; 15 conceded errata) whose material is a **pre-implementation design artifact hosted as an issue comment**.

**[PR #50](https://github.com/Grimblaz-and-Friends/tradecraft/pull/50)** sustained `DF1` (medium — the body reported three of the affirmed artifact's six acceptance criteria, where §6's own reason for criteria is *"so silence cannot pass as conformance"*) and the `M24(a)` limb (the body miscounted its own diff). Both were fixed; neither was writable with a correct value.

`repo-docs` is the nearest wrong value in both cases and the artifact is not in the tree at all. §8 states the governing principle for its position axis, and its reason is axis-general: *"A judged position with no lawful value is a signal that the vocabulary is short, and the row waits on the amendment rather than absorbing the gap silently."* Roughly 75 findings have been waiting on it — the value is per row, and the minority sited in tree material take their own values ([#60](https://github.com/Grimblaz-and-Friends/tradecraft/issues/60)).

## Decision

**Statute delta:** §8's `artifact` vocabulary gains a ninth value, `work-prose`, denoting prose the constitution requires of a unit of work and homes outside the tree — a framing, design or plan artifact on an issue, an affirmation record, a pull-request body, a review's report — tested by where the material lives rather than by which position it sits at.

**Displaces:** [ADR-006:72]

**One value for the whole class, not one per surface.** The filing proposed `design-artifact`; [the recurrence comment](https://github.com/Grimblaz-and-Friends/tradecraft/issues/46#issuecomment-5323420605) then recorded the pull-request-body case and left the one-or-two question open. One value settles it, on §8's own restraint clause — *no value is added before a query wants one* — and no query yet distinguishes a defect in a design artifact from one in a pull-request body. The decisive argument is not economy but coverage: the constitution mandates four off-tree prose surfaces outright — the pre-implementation artifact, the affirmation record, the pull-request body, and the review's findings surface — and a fifth, the catch-recording comment (§8), whenever a catch lacks a durable record, so a vocabulary that admits them one at a time is short again on the next one, and this issue is refiled. That is the shape [D-53] chose for `constitution` and the reasoning is the same — the field names a *kind* of material, and which surface a row sat in is recoverable from `ref`.

**The argument this decision declines to use.** The natural defence of one value is that the position axis already separates a design artifact from a pull-request body. It does not, reliably: §8 rules that a defect whose preventing decision belonged to an earlier position is `introduced` there *even when no artifact existed to hold it*, so `introduced` tracks where the decision belonged and not which surface holds the text. The two coincide on both instances above and are not guaranteed to. The accepted cost is therefore stated plainly and is the one [D-53] accepted: a query for "defects in design artifacts" reads `ref`, and cannot be answered from `artifact` alone.

**The name.** `work-prose` parallels `skill-prose` in the same vocabulary: the siblings name material kinds, and `-prose` marks material that is read rather than executed, while `work-` scopes it to a unit of work — which is what separates it from `constitution`, also prose and also read, but binding on everyone and living in the tree.

**The pin.** `LEDGER_POSITIONS`, `LEDGER_STAGES`, `LEDGER_DISPOSITIONS` and the seat record's sets are each pinned exactly in `tools/tests/test_lint.py`; `LEDGER_ARTIFACTS` was not. The set this decision amends had no pin — and neither did `LEDGER_SEVERITIES` nor `LEDGER_FIELDS`, so the class was open rather than closed; this change pins all three, each proved red-first by mutation. The pin closes the code side only: the statute's own list stays unguarded, as §8's unenforced-for-now entry records.

**What this decision does not do.** It writes none of the waiting rows. That backfill is bookkeeping and lands in its own pull request, on the precedent of [PR #47](https://github.com/Grimblaz-and-Friends/tradecraft/pull/47); because #42 is closed, it is given a live pickup home rather than left to the closed issue. It restructures nothing else in §8, adds no second value for any other surface, and adds no guard checking this statute's vocabularies against the lint's sets — §8 lists that correspondence as unenforced *for now*, and §2 earns code by recurrence rather than by the first instance.

## Rejected

1. **Two values — `design-artifact` and a second for the pull-request body** (the filing's proposal, extended by [the recurrence comment](https://github.com/Grimblaz-and-Friends/tradecraft/issues/46#issuecomment-5323420605)). Each surface would be directly queryable, and the two do have different authors and different review regimes: the convergence gate reads one, the implementation review the other. Rejected because it mints two values where no query wants either, against §8's own restraint clause, and because enumerating surfaces closes two of the four — the affirmation record and the review report arrive with the vocabulary short again.
2. **Widening `repo-docs` to cover issue-hosted and PR-hosted prose** (declined by recommendation in the filing, and confirmed here). It makes one value cover tree files and non-tree artifacts, which is one value carrying two denotations at once — a different overload from the judgment-versus-absence doubling `authoring` was retired for, and rejected on its own ground; the boundary sentence in the new sub-rule states that reason inline so a later reader meets it where the temptation is.
3. **`github-prose` as the name** — a vendor name inside a durable vocabulary. GitHub is the named state substrate (§3), so the name would not have been false; §9 keeps the practice runtime-neutral, and a vocabulary value is the wrong place to spend that.
4. **`process-artifact` as the name** — reads as covering the rules *about* process, which are `constitution`.
5. **Writing PR #50's two rows here as the value's own proof.** Considered and put to the owner at the convergence gate; declined, because it splits one bookkeeping job across two pull requests for a demonstration the lint already makes.
