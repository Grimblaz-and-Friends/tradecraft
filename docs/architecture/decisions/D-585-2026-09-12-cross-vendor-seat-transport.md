# Cross-vendor seat transport

**Purpose:** record why this dispatch mechanism has its launch and failure boundaries. **Audience:** a future maintainer revising the script or integrating a seat consumer. **Success:** the transport can change without rediscovering the incident or silently turning a failed review into a successful verdict.

The owner affirmed the [mechanism brief](https://github.com/Grimblaz-and-Friends/tradecraft/issues/581#issuecomment-5647604448), including same-vendor fallback and a machine-local expiring hold. The staffing rule was split into #580. The artifact was [settled by a Claude cold seat](https://github.com/Grimblaz-and-Friends/tradecraft/issues/581#issuecomment-5647988948) before implementation; there was no adverse verdict and no amendment to the brief.

`lib/` was chosen because both shipped seat consumers will name the command. A repo-only implementation would force shipped prose through the wall. The existing resolver in `tools/check_codex_compat.py` at `0961446` was moved into the shared helper; the compatibility tests preserve its callable/error contract. The alternative of copying discovery into another launcher was rejected because its bundle and PATH policy would then have two owners.

The caller names both the desired vendor and its own. Guessing from environment would confuse nested launches and silently change fallback staffing. Separate model/effort options prevent the other vendor's model spelling from reaching fallback. Defaults are explicitly named frontier models and effort; this is launch configuration, not a rule deciding who sits where. Codex's Git-repository precheck is skipped for the explicitly named root so the interface also accepts ordinary directories; the read-only sandbox remains.

The [bounded Claude probe](https://github.com/Grimblaz-and-Friends/tradecraft/issues/581#issuecomment-5647950734) is the evidence for safe mode preserving OAuth with only file-reading tools. The issue's earlier bare/plain probe and CLI 2.1.261's help are the evidence for omitting bare mode. General Bash permission was rejected because it would make the claimed read boundary depend on what a shell command did. This deliberately means Claude seats receive executable probe evidence or leave execution to another party. The script does not elevate itself; native Windows Codex invokes it through the already approval-managed host route when it needs the user's CLI login.

Stdin was chosen for the full dispatch so its length and shell punctuation do not become command-line behavior. Windows npm launchers resolve to their payload with an argument vector, never a batch shell. Automatic lookup follows configured PATH entries without Windows implicitly prepending the checkout, including when finding Node; the review demonstrated that the implicit search could execute checkout code before runtime restrictions existed. Explicit paths and deliberately configured PATH entries remain trusted choices. The real transport checks on 2026-09-12 returned `seat ready` from both installed CLIs; `lib/tests/test_dispatch_seat.py::test_real_child_receives_large_utf8_dispatch_and_exact_launch` carries the reproducible payload/root/argv falsifier.

The [review's timeout finding](https://github.com/Grimblaz-and-Friends/tradecraft/pull/585#issuecomment-5648342264) concerned an accepted executable whose descendants outlived its direct-process timeout; the actual Windows Node controls already stopped their children. The fix supplies that containment independently of the selected executable. A Windows worker joins its own kill-on-close job before launching the vendor and passes stdin untouched; terminating the worker closes the job. POSIX launches use a new process group. A descendant deliberately leaving that group can retain a pipe, so post-timeout draining has a bounded grace period, after which the handles close with received bytes preserved; this bounds return without claiming to kill an escaped process. The [bounded job experiment](https://github.com/Grimblaz-and-Friends/tradecraft/pull/585#issuecomment-5648218459) established feasibility; the integrated lifecycle, failure and stream controls travel in `lib/tests/`. A mere timeout-message correction would have left work running.

Availability and seat failure are different outcomes. The runtime's supported auth/usage error forms or a live hold permit one fallback; an unknown failure, a timeout or a permission denial does not. The tests in `lib/tests/test_dispatch_seat.py` distinguish those cases from an ordinary adverse verdict and prose quoting a diagnostic. Real Codex 401/429 responses captured against a loopback HTTP stub supply the failed-event fixtures; a 500 control remains an ordinary error. Their status prefixes are recognized only in failed-runtime context. Bare zero-exit diagnostics are complete forms, without arbitrary explanatory tails. New diagnostic wording may need a new fixture; the separate runtime logs keep unknown errors inspectable. No error without a reliable reset time writes a hold, and no branch buys credits or silently chooses another model within a vendor.

The hold file lives at a user-home path independent of the checkout and plugin version, with an explicit override for machine-local placement. It is read before every attempt, so a hold declared during the first attempt can govern fallback. Strict timezone-bearing rows avoid guessing the owner's reset. Output destinations cannot overlap this input, including when the hold file does not exist yet. Existing verdict/log destinations are refused. Preflight creates each exact destination exclusively, keeps sidecars reserved, and removes the empty verdict reservation before any runtime starts; this catches uncreatable longer log names before spending usage. Transcript contents are withheld until the last attempt finishes, so a fallback reading its output root cannot encounter its predecessor's discarded verdict. Diagnostics and the run record survive ordinary failure; only a successful final message becomes the verdict. Malformed response bytes fail strict decoding, with original diagnostic bytes retained in an identified base64 JSON envelope rather than silently repaired. This keeps outputs UTF-8 and retains the evidence needed to diagnose corruption.

The [incremental external findings](https://github.com/Grimblaz-and-Friends/tradecraft/pull/585#issuecomment-5648558142) exposed the remaining publication-order gap: exclusive creation alone could leave a partial verdict or one whose run record failed afterward. Logs and the record now finish first, including flushing and closing the record. Verdict bytes are staged on the output filesystem, then a hard link creates the final name atomically without replacing a concurrent caller's file. This was chosen over POSIX rename/replace because those operations can overwrite that file. Preflight also verifies hard-link support before invoking a vendor; failed preflight removes every reservation. Failed staging leaves no verdict, and the temporary path is cleaned up. A complete record reports the runtime outcome even if subsequent publication fails; the command's failure and absent verdict distinguish that case. This establishes publication order, not crash-durable storage.

The local test runner's path list was extended alongside CI's, an observation both the cold seat and implementation pickup made. The library tests travel with the library and run from a copy lacking repo-only content. Validation is rederived with `python tools/dev.py check` on this PR's tree; the test count is not a frozen claim.
