# D-184: The always-on surface is one measured total, its ceilings ratchet, and outflow is owed on edit

**Status:** Accepted 2026-08-25 (PR #184)

## Context

#140 was filed against a doctrine file twenty characters from its budget, with the diagnosis that nothing had ever routed a rule out — the pressure valve was stated and had never fired. Two restructures later that file has room again, and the diagnosis has been vindicated rather than answered: **the surface every session reads before acting grew through both of them.** The file shrank each time — 7,980 at `3175369`, 5,958 at `b9bcdeb`, 5,659 at `dade755` — while the surface it belongs to rose, because prose moved between always-on artifacts and each change reported the file it emptied.

Re-derived by `python -c "from tools.figures import always_on_at"` at each tree, counting `AGENTS.md` and `CLAUDE.md` whole, the charter's body, and every cell's name plus description: **11,590** at `3175369` when the issue was filed, **15,075** at `b9bcdeb` after the charter split, **15,602** at `9018f56`, this change's merge base. Those figures include `CLAUDE.md`, which this change added to the count and earlier drafts of this entry omitted.

That was possible because no invocation reported the sum. `tools/figures.py` emitted the doctrine's size, later the charter's, and a per-cell description ceiling — three numbers about three surfaces, and nothing about what a session actually loads.

## Decision

**The always-on surface is one figure, reported for two audiences.** `figure_always_on` sums `AGENTS.md`, `CLAUDE.md`, the charter's body, and every cell's `name` plus `description`, and reports the repository's total and an adopter's separately. They are different sets and conflating them is the error the figure exists to stop: a plugin's root `AGENTS.md` and `CLAUDE.md` land in a consumer's cache as inert files and are never loaded — owner-verified on this issue with a live control against an enabled plugin. An adopter reads the charter and the roster's descriptions and nothing else **of this practice's** — an adopting repository has its own doctrine besides, which the charter says wins on conflict, and this figure counts only what the practice contributes to that surface. On the tree this entry lands in: **15,505 here, 9,747 from this practice for an adopter**, against 15,602 at the merge base — a movement of **−97**, which is what this change is worth and not the −148 an earlier draft of this entry claimed by measuring against the wrong base.

**Outflow is owed whenever an always-on surface is edited, not when a budget is reached.** It is the admission order read backwards — a rule a guard now holds becomes the rule plus the guard's name; a rule that binds only inside one activity moves to that activity's cell; a reason a decision entry already carries compresses to its citation. A surface that empties only under pressure empties once and refills, which is the recorded history of this one. Two constraints travel with it: it may never *drop* a rule, and it measures the whole surface rather than the file being edited, because routing a rule from one always-on artifact into another is the same cost under a different heading and reads as a reduction to anyone measuring one file.

The rule lives in `authoring`'s routing depth rather than its body, because its trigger is the routing trigger. The body had 74 characters of headroom at the merge base and has five now — this change spent 69 of them on the pointer, so the margin is this change's own consequence rather than the constraint that forced the choice. **Reaching the session it is aimed at took two corrections, and the first draft of this entry got it wrong.** That draft said the firing condition was named in the always-loaded pointer — but the pointer is a clause in the cell's *body*, and a body is not always-loaded; only a cell's name and description are, which this same practice states flatly. A cold consumer asked to add a binding rule found the obligation by reading git history and said so. So the trigger moved to `authoring`'s description, which is the surface that actually always loads, and this repository's own doctrine states the obligation directly at the line that used to say the opposite. An adopting repository is reached by the description alone, which is why that correction is the load-bearing one.

**The doctrine's own budget sentence had already been superseded by this change and still said so.** `AGENTS.md` read *"At the budget, adding a line means routing something out"* — the condition this decision replaces — three commits after the replacement landed. A session editing the file would have read the obligation it was under and got the wrong one. Found by the same cold consumer, in the same run, which is two of two.

**Running the audit produced one move and one refusal, and the refusal is the more instructive.** The calling contract's runtime specifics compressed to `[D-156]`, which carries them. The zone wall's consumer-cache clause did not: [D-78](D-78-2026-08-19-carry-the-reasons.md) put that clause in the doctrine deliberately, because its absence made it possible for a session to place content there believing consumers never receive it — D-78 and #75 both record that as a latent defect rather than an incident, and the refusal rests on the clause having been placed deliberately, not on a session having been caught by it. The outflow's first move is to read the citation, and here the citation said don't. **An audit that never declines is not applying the rule.**

**Both ceilings ratchet to what the tree measures.** `AGENTS.md` 8,000 → 6,000, and the charter 6,000 → 5,600 against a measured 5,353. The doctrine's basis moved while this change was open — it was 5,511 when the ceiling was chosen and is 5,747 at landing: 112 characters spent by this change, 177 by a merge that arrived mid-flight, less 53 a review remedy took back out, so 236 net against a headroom of 253 — which is the ceiling doing its work rather than an argument against it. Each margin is argued in the constant's own comment rather than here, so a session raising one reads the argument at the site it is changing. The charter's margin is deliberately tighter: its prose was not audited in this change, so the ceiling is the only pressure it gets.

**A cell body budget becomes a guard.** `authoring`'s cap of 7,359 was stated in #169 as that change's own evidence that depth-shedding is applicable rather than aspirational — and was enforced by nothing, living in a command string inside an entry that had frozen. `CELL_BODY_BUDGET_CHARS` holds it. The value is the bound #169 wrote into its own derivation command — `--budget 7359`, against a body that measured 7,358 before that change; #169's own tree then came in at 7,285. The guard compares with `>`, so 7,359 passes and the cap admits one character more than the size it was derived from — near enough to *no larger than you started* to read as it, and not the same thing. It is that change's judgement rather than a fresh one, and the point is that raising it is now a recorded decision rather than an edit nobody sees. It bit twice while this change was being written, which is the argument for it.

**Cells absent from that map are unbudgeted on purpose.** A number chosen for a cell nobody has argued about would be a ruling on its size arriving as a constant. `adversarial-review` is 23,541 characters at this tree — 30.4% of all cell prose and 2.34× the next largest; that is [#177](https://github.com/Grimblaz-and-Friends/tradecraft/issues/177)'s to decide, not this change's to pre-empt.

**#164 is discharged** — `AGENTS_BUDGET_CHARS` and `POINTER_BUDGET_CHARS` gain literal pins, on the ground its own filing states: a test deriving its bound from the constant it tests cannot catch a change to that constant. Every budget in the file is now red-probed, including the case where a budgeted cell is renamed away, which previously dropped the budget in silence because the guard skips a cell it cannot find.

**The callout carries the total, and this PR's own movement.** A budget only bites where somebody sees it, and this one has only ever been read after the fact — in a write-up, by a session that had already decided what to add. The merge surface is the one moment the number can still change an outcome, and an absolute total cannot tell the owner whether a change grew the surface or shrank it, which is the direction the ceiling exists to resist. Each file is priced against the ceiling that governs it and no other. Neither half may fail quietly: a total that will not derive is stated as an absence with its reason, and so is a base revision that cannot be read — the two were not symmetric, and the delta was silently absent from every callout CI posted until this change's review found it.

**One thing this change dropped, named because its own rule requires it.** `authoring`'s description was at its 700-character ceiling, so admitting the new trigger meant deleting `a piece of` and the parenthetical `(test counts, sizes, deltas)` that D-141 gave the derived-figures trigger as its recognisability. The examples now exist nowhere in the tree. The rule this change lands says naming the drop is lawful and silence is not; the first draft named it in a commit message, which is neither the entry nor the PR body where amendments are recorded.


## Rejected

- **A roster aggregate ceiling.** It would make one cell's PR fail for another cell's prose. The aggregate gets a figure; the pressure it creates is informational, which is the correct shape for a shared resource no single change controls.
- **Per-cell budgets for every cell** (fork E.1, owner-ruled). Eight constants to choose and maintain, and a budget on `adversarial-review` either ratifies its current size or fails CI on day one — a decision about that cell smuggled in as a number.
- **Auditing the charter's prose** (fork D.1, owner-ruled). Its success criterion is that a session reading only it behaves correctly, which resists shedding by construction, and auditing it properly means re-deriving what a consumer needs — nearer #139's question than this one's. Measured and ratcheted instead.
- **Compressing the zone wall's consumer-cache clause**, on reading D-78. Recorded because a later audit will reach the same passage and should not have to re-derive the refusal.
- **A periodic sweep.** A scheduled re-reading of a file is a maintained record, which this repository's records rule rejects. The check is standing and fires on edit.
- **Making the outflow a doctrine line.** It is methodology about where content goes, and the surface it governs is the one it would have grown.
