# D-194: A derived figure lives only where it re-derives, and the review row stops counting

**Status:** Accepted 2026-08-25 (PR #194)

## Context

[#184](https://github.com/Grimblaz-and-Friends/tradecraft/issues/184)'s review ran three cycles, and its figure-defects split into two populations that behaved completely differently. The surfaces that **re-derive at read time** produced no stale number at all: the doctrine callout recomputes on every push, the lint's always-on line recomputes on every run, and a budget constant cannot rot because the guard *is* the number. Its defects there were wiring defects. The surfaces that **transcribe** produced staleness at essentially every site: `D-184`'s own sentences, the margin comment in `tools/lint.py`, a commit message stating a count the tree contradicted, a PR body block pinned to a superseded tree. Three consecutive fix batches each corrected transcriptions and produced fresh ones, and not one wrong *derivation* occurred anywhere in that review. The instruments were right every time; the photographs of them aged.

[D-135](D-135-2026-08-23-repointed-reference.md) and [D-141](D-141-2026-08-23-figures-are-derived.md) had already landed the principle for **write** time — derived rather than recalled, with an engine behind it. #184 is the evidence that write-time derivation does not survive, because prose outlives the moment it was true.

**The thesis reproduced itself while the issue sat open.** `AGENTS_BUDGET_CHARS`' comment stated the file's size and its remaining headroom as current fact. [#186](https://github.com/Grimblaz-and-Friends/tradecraft/issues/186) landed after it was written and spent most of that headroom, so by the time this change picked the issue up the comment was false by two orders of magnitude on the number that mattered — derivable at any tree by `python tools/figures.py`. Nothing had to go wrong for that; the sentence simply stayed still.

The related failure is a **basis** error rather than a staleness one, and it is why the rule names the tree as well as the command: #184's final derived pass, run mid-review after `main` advanced, would have written a delta against `origin/main` where the true merge-base figure was materially different, caught only because the terminating ruling ordered the base pinned.

## Decision

**1. A derived figure lives only on a surface that re-derives it at read time.** A surface that freezes — a decision entry, a commit message, a PR body, a pre-implementation artifact, a comment beside code — states the command and the tree it runs on, never the output. The rule lands in `skills/authoring`'s frozen-document depth, replacing the weaker sentence that asked a count to *travel with* its query; asking for both is what permitted every failure above, since each of them carried its derivation and stated a number beside it anyway.

**The falsifier is stated in the cell**, because a rule a reviewer cannot name is one only its author enforces: *point at any number on such a surface and ask which command, on which tree.* A number standing where a command belongs is the violation.

**2. `Derived` is the subject, and it is narrower than every number.** A figure a command produces from a tree is derived. A primary observation is not — what a review found, what a session did, a measurement read off a record that itself freezes. Read without this scope the rule bans recording a measurement anywhere, which would strike `skills/adversarial-review`'s panel-width basis, the entire empirical warrant for the roster. Those figures are evidence, pinned by the record carrying them rather than by a command.

**3. [D-155](D-155-2026-08-24-measured-figure-lawful-in-the-artifact.md) item 1 is superseded, knowingly, and the argument against doing so is recorded because it is strong.** That entry ruled a measured figure lawful in a pre-implementation artifact, and its Rejected list declined carrying evidence figures by link on the owner's own ground: it *"makes the fork harder to read at the moment it is being argued."* The artifact freezes on affirmation, so it falls squarely under the predicate here.

**The implementing session recommended the narrower rule and the owner ruled the wider one.** The narrow form — state the figure, but pin it to the tree it was taken on — covers every failure on the record, and the sentence in D-184 that is a transcription of three *pinned* figures has not rotted and is still the whole diagnosis of that issue. The owner's ground for the ban is that a rule permitting transcription under a condition still permits the act that failed three fix batches running, and that the condition is satisfiable sloppily: the PR-body block that went stale **was** stamped. A bright line cannot be got wrong; a conditional one was, repeatedly, by sessions applying it in good faith. The forecast half of D-155 is untouched, and `skills/engagement`'s clause about the material a declined spike consulted now names the query and its tree rather than the counts.

**4. The review row stops carrying arithmetic.** From `REVIEW_ROWS_QUALITATIVE`, a row carries date, artifact, lane, each sustained high named, staffing, and the report URL. Every count that left was hand-totalled, cross-totalled, and re-derived by nothing — the one class of figure this change's own rule forbids on a surface that freezes, and this file's whole defect record: [#171](https://github.com/Grimblaz-and-Friends/tradecraft/issues/171) and [#180](https://github.com/Grimblaz-and-Friends/tradecraft/issues/180) are both about values no stage produces, and rows have carried reconciliation prose into a file nobody may edit. **The counts were never answering the question the index exists for.** Both issues close here.

**The retired fields are forbidden rather than optional.** An optional field cannot catch its own omission — the reason both prior boundaries on this row are position-gated — and it additionally lets the shape drift back one row at a time while obliging the guard to validate two live shapes for ever.

**`staffing` survives the cutover.** A model and a runtime are facts about who ran the review, not arithmetic about it, and this row is the only queryable home the per-runtime evidence has. `dispositions`' own obligation window closes where the counting shape does, or a row would be required to carry a field it is forbidden to carry.

**How many highs a review sustained is now the length of `highs`** — derived at read time from the row rather than transcribed into it. That is this change's rule landing a second time, in the shape of the record rather than in prose about it.

**5. Guards go where a checkable subset exists, and nowhere else.** The row's schema is checkable and is guarded, probed in both polarities and mutation-probed on the cutover constant through the repository's own index: set one too low and a row already in the file reds, set one too high and the next lawful row a session writes reds. The figure rule gets **no guard at all**. Detecting a stale sentence is what [#187](https://github.com/Grimblaz-and-Friends/tradecraft/issues/187) proposed and what the charter's admission bar refused; this change removes the *supply* instead, and inventing a prose-scanner here would fail on the ground #187 failed on.

## Rejected

- **Pinning instead of banning** (fork A, option 2 — the filing session's and the implementing session's recommendation). Owner-ruled against, reasoning in Decision 3.
- **Retiring `docs/reviews.jsonl` entirely** (fork 2b). Owner-ruled. It is the larger outflow — the whole schema, its constants, its tests, and the doctrine line — but the failing half of the row is separable and identifiable: every defect and every open issue against this file is about the three counting fields, and the fields that state facts have no defect record. 2b discards the working half to be rid of the broken one, and loses the only enumeration of reviews and the only queryable per-runtime evidence.
- **A PR-body exception for a pasted, stamped figures block**, which #191's own draft permitted. Put to the owner at convergence and declined. The one recorded PR-body failure was a stamped block whose stamp went stale, and on a PR touching the doctrine the callout already re-derives and posts on every push, so the block duplicates a live surface. **The cost is named rather than discovered later:** on a PR that touches no doctrine file no callout fires, so the merge surface carries a command and no number — against D-184's argument that a budget only bites where somebody sees it.
- **Backfilling.** Existing entries, rows, commit messages and PR bodies keep their numbers. Records are exhaust; the rule binds surfaces written after it lands. What was cleaned here is the *live* surfaces only — both budget comments, `always_on_note`, one comment in `tools/figures.py`, and README's token counts. The always-on surfaces carried none, checked once.
- **Reaching filings.** An issue body freezes and falls under the predicate, but [#158](https://github.com/Grimblaz-and-Friends/tradecraft/issues/158) already owns that surface with its own undecided remedy, and a rule arriving there ahead of it would pre-empt the fork that issue exists to settle.

## Deferred, with the evidence that would reopen them

- **The ban's cost to argument is asserted as acceptable and has not been observed.** D-155 recorded a seat saying an artifact was not arguable without the counts it held. **Reopen on:** a fork a reader cannot follow because its magnitudes are behind a command, or an owner decision taken on a surface where the number would have changed it.
- **Nothing distinguishes a derived figure from a primary observation except the writer's word for it**, which is the same seam D-155 left open one rule over. A session can call a derivable count an observation and no guard sees it. **Reopen on:** a figure defended as primary whose command exists.
- **`highs` records what was sustained and not who found it.** [D-185](D-185-2026-08-25-finders-of-each-sustained-high.md) put finders in the report deliberately, and #138's width recomputation reads them there. **Reopen on:** that recomputation needing the row rather than the reports.
