# D-269: A cell's description names its stages, not the tests they apply

**Status:** Accepted 2026-08-30 (PR #269)

## Context

`skills/adversarial-review/SKILL.md`'s frontmatter `description` is the whole of what a Claude Code session here loads about the cell before it fires, and the whole of what an adopter loads [D-210]. It carried two defects in one sentence-pair, filed separately and landed together.

**[#257](https://github.com/Grimblaz-and-Friends/tradecraft/issues/257): it advertised a mechanism the material no longer has.** The clause read *"a terminal stage that weighs value against price"*. [D-230] replaced that axis: the second limb is now a three-part test on owner attention, a design call, and the affirmed boundary, and `priced_out` was retired outright. [Four of five seats in PR #230's review found the staleness independently](https://github.com/Grimblaz-and-Friends/tradecraft/issues/217#issuecomment-5464966821); it was routed to [#217](https://github.com/Grimblaz-and-Friends/tradecraft/issues/217) on the ground that routing evals would catch it, and that issue's exploration measured the instrument saturating and established it cannot see this class at all — the cell fires correctly, because the trigger clauses are intact, and what is stale is the claim about the mechanism.

**[#203](https://github.com/Grimblaz-and-Friends/tradecraft/issues/203): a required step had no trigger.** `AGENTS.md`'s flow lists *"reconcile external reviewer comments"* as its own step. None of the three declared triggers matched it, so a session whose only job was that step could disposition those comments without ever opening the material that governs them — `skills/adversarial-review/references/after-the-fix.md`, which requires a disposition per comment, sustain on independent grounds or not at all, and a record that the pass ran even when it produced nothing.

**The two defects have one source.** The description was in the habit of characterising what each stage *decides by*, and a stage's test is exactly what gets amended. [D-107] rewrote the terminal stage's clause (b) and left this string alone deliberately; [D-230] rewrote it again and left the string alone by omission. Both times the description was falsified with `python tools/lint.py` clean, because nothing compares a description against the material it summarises and no cheap mechanism can — a phrase-presence check needs the description's wording verbatim in the body, which is the duplicated-prose failure `authoring` forbids.

## Decision

**The description names which stages exist; it no longer names their tests.** Both characterising clauses go — the falsified *"that weighs value against price"* and the still-true *"that prices each remedy"* — and nothing replaces them. Deleting the true one with the false one is the whole of the principle: keeping it would preserve the habit that produced #257 and leave the same surface exposed to the next amendment of what the defense prices.

**What goes is any clause a later amendment to the stage can falsify — the test the stage applies, or the act it performs.** The two are one class, and naming only the first would leave the second: the defense does not decide by price, it states one, so *that prices each remedy* is an act rather than a test and leaves for the same reason. The stages themselves are stable in a way their tests are not. `SKILL.md`'s own lane paragraph and `skills/adversarial-review/references/arbitration.md` have been rewritten repeatedly without the panel, the defense, a terminal ruling, or post-fix re-validation ceasing to exist; what those stages decide by has changed twice in eight days. A description that names the first and not the second cannot be falsified by an amendment to the second, which is what closes this defect as a class rather than as an instance.

**This supersedes [D-107]'s rejection of amending this string.** That entry declined the edit on the ground that *"changing a triggering string has a cross-repo regression surface untestable in this review."* The premise held then and does not now: #217 built the harness, ran it over this repository's own cells, and its closing record establishes both that the instrument saturates and that it is blind to this defect. The surface is no more testable than it was — what changed is that the untestability is now measured rather than assumed, and D-107's rejection is read rather than obeyed.

**The added trigger covers the commissioned pass in the same clause** — *"when reconciling what an automated reviewer posted on a pull request or what a review tool you invoked returned"* — because `after-the-fix.md` governs both and [D-230] put the commissioned pass there deliberately, having narrowed `external` back to configured automation. Two trigger clauses for one reference file would state a distinction the description exists to route past.

**The outflow was performed rather than sized to the addition** [D-253]. The description carries no rule a guard now holds and none that argues itself, so two of the three moves are empty. Two candidates for the third were considered and both are blocked. The first is `AGENTS.md`'s *"Every review appends one row to `docs/reviews.jsonl`, and every `record` ruling one entry to `docs/recorded-findings.jsonl`"* binds only inside this activity and would move to this cell, and cannot — the zone wall forbids shipped prose naming a repo-only path, which is why it is in the doctrine to begin with. The charter's Review section is review-only in the same way; moving it is its own change with its own design weight and is routed, not taken here. The second is `AGENTS.md`'s *"Shared code lives only in `lib/`"*, which binds only inside the writing-code activity and which the zone wall does **not** block, `lib/` being shipped: it stays because it names this repository's own layout, which `AGENTS.md` is where a repo-only mechanic belongs, and shipping it in `substrate` would impose that layout on every adopter — `substrate`'s own `skills/substrate/references/text-mode.md` already scopes `lib/` to a script inside this tree. **The obligation is discharged by the refusal**, which is the answer `skills/authoring/references/routing.md` gives where nothing has a cheaper home: say so, and say why. The deletion above is part of the edit rather than its outflow answer — neither deleted clause is a rule, so the fourth answer's gate is not what licenses it. The surface still grows: `python tools/figures.py` on this tree reports the always-on total, and a smaller addition to make the arithmetic come out is what [D-253] forbids.

## Rejected

- **Substituting an accurate terminal-stage test** — *"rules each finding by what acting on it costs in judgment"*. The option the owner was given first, and the one that re-installs the defect class: it states a test on a surface nothing checks, and the test has been rewritten twice already. Put to the owner as one of three at convergence; he picked the deletion.
- **Cutting the mechanism enumeration entirely**, leaving identity plus triggers. Cheapest, and it nets the always-on surface down. Declined on recognition: the enumeration is how a reader recognises the situation the triggers name, and that this is a multi-seat pipeline rather than a code-review pass. Not declined on under-triggering — this entry's own Context says the cell fires correctly because the trigger clauses are intact, and cutting the enumeration would have removed no trigger clause. Also put to the owner at convergence.
- **A guard comparing a description against its material.** The admission order puts a mechanism first, and no reliable cheap form exists: the only mechanical version checks that the description's phrases appear in the body, which requires the duplicated prose `authoring` forbids and would drift the moment either copy is edited.
- **Running a routing eval on the new wording.** #217's closing record measured the instrument saturating and established it blind to exactly this defect. Its own reopen condition is a non-saturated score against a genuinely new mechanism; a reworded description is neither.
- **Landing the two issues separately.** They are one paragraph and one budget; two changes would answer the outflow question twice and leave whichever landed second editing a surface the first had just moved.

## Deferred, with the evidence that would reopen them

- **Nothing holds the stages-not-tests principle but this entry.** No guard can see a description that starts characterising a stage's test again, and the principle is not written into `authoring`'s `skills/authoring/references/cell-structure.md`, which states the description's job as triggers, non-triggers and mutual exclusivity. Left as a decision rather than admitted as a rule, per the charter: an agent-proposed rule needs an incident from real work, and this is one incident on one description. **Reopen on:** a second cell's description found stale for the same reason.
- **The added trigger brings the reconcile job inside this cell, and two always-on surfaces answer that job's default case in opposite directions.** `skills/charter/SKILL.md` says a drop is ruled by a stage that is not the session that built the change, and that outside a review no such stage exists; `skills/adversarial-review/references/after-the-fix.md` lets the reconciling session drop a comment on the evidence; and `AGENTS.md`'s flow makes that session the builder. The charter's condition is factual rather than definitional — a trigger routes a session to material, it does not convene a review — so this change does not itself decide the case, and the repair is outside its boundary. **Reopen on:** a session on the ordinary flow reporting either branch — stalling for want of a stage, or dropping in apparent violation.
- **The other eight descriptions were not audited against their material.** This change fixed the one two issues named. **Reopen on:** any other description found making a claim its cell no longer supports.
