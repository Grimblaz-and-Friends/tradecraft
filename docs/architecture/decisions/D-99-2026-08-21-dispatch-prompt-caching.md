# D-99: The dispatch prompt is not cacheable, and the cost argument is dead for panels

**Status:** Accepted 2026-08-21 (PR #99)

## Context

[D-90](D-90-2026-08-20-dispatch-contract.md) measured [#82](https://github.com/Grimblaz-and-Friends/tradecraft/issues/82)'s prompt-caching argument at one block size, found it did not hold, and then hedged: *"Both results can stand; a payload large enough may clear a breakpoint that a 1,250-token one does not."* [#92](https://github.com/Grimblaz-and-Friends/tradecraft/issues/92) was filed to settle that, and `agent-orchestra` had recorded the same gap as an explicit known-unknown — *the cacheable prefix unit for `Agent` dispatches*. Neither project had ever established where the breakpoint falls.

It has now been measured. This entry records what the instrument found and retires the hedge; it changes no rule.

## Decision

**No payload clears a breakpoint, because the breakpoint is not where the hedge assumed.** A sweep of sibling dispatches whose prompts share a leading block and diverge only in a one-line tail read `cache_read_input_tokens` **26,881 at every size** — 4,226, 16,423, 64,396 and 256,374 prompt characters. The last of those shares a **256,286-character (≈74,800-token) prefix** with a sibling dispatched five seconds earlier, and still rewrote all of it. Cache creation is linear in prompt length with a fit essentially exact — `12,650 + 0.29185 × prompt_chars`, residuals under 74 tokens across a 60-fold span.

**The mechanism is not a missing breakpoint but a misplaced one.** Eight dispatches carrying a *byte-identical* 71-character prompt cache **completely**: `claude` siblings read 40,006 with `create` **0**, `general-purpose` 39,899 with `create` **0**, `Explore` 27,732 with `create` **0** — the entire request, attachments and prompt included. So a breakpoint does sit after the user message; it sits at the **end of the whole request**, behind the per-recipient bytes. Because hits require identity *"up to and including the block marked with cache control"*, one differing byte collapses the hit back to the tools-and-system entry. This is verbatim the failure the API documentation names — *"Place `cache_control` on the last block whose prefix is identical across the requests you want to share a cache… not on the varying block"* — and nothing a dispatcher writes can move it.

**The consequence is structural, and it is stronger than the measurement it rests on. No arrangement of shared-versus-per-seat content produces cross-seat cache sharing on this runtime.** The per-seat difference must exist somewhere, and every available *somewhere* is inside the span that must be identical: put the lens in the prompt and `messages` diverges; put it in the agent definition and `system` diverges, which invalidates `messages` after it. There is no third place. **#82's cost argument was therefore never available to a panel of differing seats at any block size**, and the correctness half carries the rule alone — which is what D-90 concluded on narrower evidence and what this entry confirms on the mechanism.

**What is cached is real and is not what a dispatcher controls.** The 26,881-token region is the agent type's system prompt and tool set, shared by every sibling of that type — visible in the corpus as `Explore` reading 17,052 against `general-purpose` reading 21,551–27,676 across 285 dispatches, and documented for exactly this fan-out: *"Two agents that run with the same model, effort level, agent type, tools, output schema, and working directory build the same tools-and-system-prompt prefix."* Two adjacent facts belong with it. **Within a single dispatch the prompt does cache** — each request reads the whole of its predecessor (0 → 41,214 → 57,716 → 69,442), so the waste is across siblings and never within one. And **a fixed ~12,650 tokens is rewritten on every dispatch before its prompt**: the deferred-tool list (10,584 chars) and skill listing (13,953) injected as attachments, plus `AGENTS.md` (6,833) and the global `CLAUDE.md` (7,244) — about 11,300 tokens of it, injected into the conversation rather than the system prompt. A five-seat panel pays it five times for byte-identical boilerplate. Nothing in this repo controls it; it is recorded so it is not re-derived.

**The predecessor's positive result is best read as its published confounds.** Its span was 64,740 **bytes** — roughly 16K tokens, which this sweep brackets on both sides and exceeds by 4.6x at the top. Its own softer reading points the same way: *the first pass wrote more than before and the other two still wrote ~88K each* is what "written fresh every time" looks like from inside. Its **inside-the-span** formulation is therefore still not imported: its cache-alignment rationale is dead here at every scale, and the correctness half is already carried by the four-word clause `2338ac4` landed. **The instrument must enumerate every project slug for the repository**, D-90's own correction, held throughout.

**One finding cuts against a rule this repo already has, and the rule should not move for it.** The system prompt embeds the working directory, *"so two sessions in different directories build different prefixes and miss each other's cache. That includes worktrees of the same repository."* The skill's *"Seats that mutate the tree get their own worktree"* is correct on its own reason — concurrent readers seeing files change mid-review — and a cost argument is not grounds to weaken it. But it costs a full prefix rebuild per isolated seat, which was not known when it was written, and a future session weighing worktree isolation should weigh that rather than rediscover it.

## Rejected

- **Byte-identical dispatch with a pulled seat assignment.** Give every seat one identical dispatch carrying the whole roster and let each agent claim its seat by a call made on turn 1, after the cached boundary — the discriminator pulled rather than pushed, since anything pushed sits in the request and destroys the identity. Built and measured: it works, siblings two and three receiving their entire dispatch at `create` 0. Rejected on the denominator. The arms differ only on turn 1, where it saves 32,376 base-token equivalents of a 61,483 baseline — **52.7% of a term that is 0.25%–0.70% of a real review**, those costing 4.6M–12.8M across eight corpus sessions. It asks for the contract's per-recipient part deleted, every seat reading every other seat's lens, a race-safe claim tool, and a nondeterministic seat-to-agent mapping. Filed with its numbers and its runner as [#98](https://github.com/Grimblaz-and-Friends/tradecraft/issues/98), which records the two conditions that would reopen it: roughly eighteen siblings sharing one large context, or seats that each do very little.
- **Any change to the dispatch contract.** Nothing measured touches it. The rule is correct on its correctness reason and would be correct if the cache did not exist.
- **Editing D-90 or #82.** The entry is frozen and reversal is by a new entry; the issue is exhaust.
- **Running the `agents/` falsifier before writing this.** Its whole payload was the cost case for hoisting stage-invariant material into an agent definition, and the same denominator kills it: roughly 32,000 base-tokens saved per review, about 0.3%, unchanged whichever way it lands. It is recorded below instead.

## Deferred, with the evidence that would reopen them

- **Whether user-authored agent-definition body text sits inside the cached prefix.** Declared open under `skills/authoring/references/spikes.md`, which is what an unresolved spike is owed. It is documented that the body becomes the subagent's system prompt; it is **not** documented that the harness's breakpoint falls after that body, and [claude-code#50213](https://github.com/anthropics/claude-code/issues/50213) reports the opposing failure mode — trailing system context appended past the marker, ~4.7K tokens rewritten per spawn — closed as not planned rather than fixed. Suggestive but not decisive: `claude` and `general-purpose` share a tool set and a byte-identical message payload, and their reads differ by 107 tokens, which can only be system-prompt text and sits inside the read. **The falsifier:** in a fresh session define two agent types with identical `tools:` and description length differing only in body size, dispatch siblings of each, and compare `cache_read`. A difference of about the body size confirms; a flat result refutes and moves the difference into `create`. **Why it did not run:** an agent type written mid-session is not picked up, the registry being fixed at session start, and both CLI binaries failed with `OAuth session expired and could not be refreshed`. **Reopen on:** anyone populating `agents/` — but note the next line first.
- **The correctness case for `agents/`, which is not this entry's subject and must not be argued on cost.** A dispatcher cannot compress what it does not retype, and that is the failure D-90's own review caught: an evidence-standards block introduced as a quotation, five of seven bullets exact, shipped byte-identically to all five recipients and satisfying the contract completely. If `agents/` is ever populated here that is the reason. **Reopen on:** a recurrence of dispatcher compression that the contract's fidelity clause does not catch.

## Instrument and its limits

`usage.cache_read_input_tokens` and `cache_creation_input_tokens` on each request of each `subagents/**/agent-*.jsonl`, deduplicated by `requestId` — several assistant records share one request and a naive read counts them repeatedly. Costs are stated in base-input-token equivalents at the published multipliers: read 0.1x, five-minute write 1.25x. Dispatches were sequential, which is the *most generous* arrangement for finding a hit and matches the mechanism the harness itself uses — a workflow fan-out holds every sibling but the first until the first response begins, capped by `CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS`, default 5000.

The size sweep ran on the workflow subagent rather than the `Agent` tool, because generating a 256,374-character prompt as an `Agent` call would have cost roughly 255K output tokens to type; the two instruments differ in prefix size (26,881 here against 23,695–27,676 across the `Agent` corpus) and agree on the shape the finding rests on. The model was held fixed at `claude-opus-5` throughout, the confound the predecessor's runs carried. Three arms were refused by a safety classifier — the 16K group's outer siblings and the large seat-claim arm — reading the filler payload as a pattern it had already blocked; the arms were not re-attempted, and both conclusions are bracketed by measured arms on either side, the large seat-claim projection moving its saving from 0.25% to 0.39% of a review and changing no recommendation.
