# D-786 — Role-specific implementers and a machine-wide vendor switch

**Purpose:** preserve why artifact authors and builders have separate model choices, why a machine-wide vendor switch reaches fresh and in-flight work, and how a Claude implementer continues on the record. **Audience:** a future session changing implementer selection, launch, continuity, or judge staffing. **Success:** that session can change a profile or route without silently dropping an override, stranding an in-flight change, or misreporting a same-vendor judgment.

Governed by the [affirmed brief](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881494686), its [row 6 correction](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881517451), the [settled artifact and cold verdict](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881718356), and the holder's [whole-change reading](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881725740). The implementation is carried by [#758](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758), also closing [#777](https://github.com/Grimblaz-and-Friends/tradecraft/issues/777), in [pull request #786](https://github.com/Grimblaz-and-Friends/tradecraft/pull/786).

## Context

[D-733](D-733-2026-09-23-proof-as-one-act-per-head.md) recorded a single interim Codex implementer default of `gpt-5.6-sol` at `xhigh` for artifact and build work. The later comparisons and owner rulings separated those roles. The entrance also accepted a `claude:` implementer override without launching Claude, and an outage would otherwise require a holder to post a switch on each change. A registered implementation root's project holder hook denies writes even from a builder, so a Claude implementing launch must omit that project hook while retaining its chosen permission mode.

## Decision

### Author and builder profiles are separate

The artifact author defaults to `codex:gpt-6-astra:xhigh`; the build and its repairs default to `codex:gpt-6-sol:xhigh`. This supersedes [D-733's implementer default](D-733-2026-09-23-proof-as-one-act-per-head.md), not its Codex judging-seat default. The per-change override gains `artifact_author`; `implementer` applies only to build and repairs. Each role reads only its entry from the latest lawful whole override line, so an omitted role does not revive an older choice.

The owner chose Astra after every blind artifact-author comparison named in the brief chose it, saying, “I'd like to go forward with Astra 6 as the artifact author.” For build, #740's hidden tests passed at 100% for Sol 6 and 58.8% for Sol 5.6; on change-proof #21 and Organizations of Verra #440 both passed every hidden test, while #440's listed build costs were $5.37 and $15.48 respectively. The owner chose “Sol 6.” These observations and quotations are from the [affirmed brief](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881494686), not a new ranking of the comparisons.

### One machine file chooses the fresh vendor

`~/.tradecraft/implementer-vendor` contains `codex` or `claude`. Absence means Codex; any other content refuses the launch. It is read for every implementer invocation. A lawful per-issue role override wins over a valid machine choice, while an invalid file still refuses. Every launch report and record names the selected vendor and its source, including an unavailable attempt. A selected `claude:` choice launches Claude; a runtime error never silently selects the other vendor.

The owner wanted one switch per outage and confirmed that the machine-wide setting replaces the proposed global-memory entry. Per-launch provenance also exposes a forgotten flip. On Organizations of Verra #440, the [brief](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881494686) records $14.01 at list for Opus's build against $5.37 for Sol 6's; the setting is a visible owner choice rather than an implicit fallback.

### Claude implements on its own resumable route

When chosen for either role, Claude uses `claude-opus-5-5` at `high`, `auto` permission mode, and a persistent session named on resume. Its request, return, native usage, and vendor provenance use the implementer dispatch bundle and entrance records. The author profile remains interim. The [correction](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881517451) records that #731 **did** measure Opus authoring at `high` and `xhigh` on #725: both judges ranked `xhigh` first, while `high` tied runner-up Astra 6 on mean rank. It did not compare Opus authoring at `high` against `max`; one change is insufficient under D-645. That missing comparison, as the [holder read](https://github.com/Grimblaz-and-Friends/tradecraft/issues/758#issuecomment-5881725740) confirms, is the reason `high` remains interim. The brief's statement that no Opus authoring effort had been measured is superseded by this correction.

The implementing Claude command selects user settings, omitting project and local settings that carry the holder hook. It supplies repository instructions through an explicit context and plugin path; it does not weaken the holder guard or `auto`. In the build's H1 probe, separate disposable source and adopter fixtures installed a project `PreToolUse` hook that called `holder_tree_guard.decision` with the fixture root. With project settings enabled, each control denied a `Write`. Under `--setting-sources user`, a fresh Claude turn and a named resume edited each fixture, and neither caused another hook invocation. That establishes the source-selection behavior in those fixtures; the probe did not exercise machine registry discovery for the holder guard. The launcher and its fake-process checks are in `lib/dispatch_implementer.py` and `lib/tests/test_dispatch_implementer.py` at `f3e2b4d3f25f78f9cf288e7c147ecc2d5f655993`; the H1 command and native-log paths accompany the build return on PR #786.

### A vendor switch carries an existing lineage forward once

Fresh artifact and build lineages choose independently. A resume stays on its recorded vendor. When the machine file switches off Codex and no role override keeps Codex selected, an existing Codex lineage hands over once to a fresh Claude session in the same root, branch, and implementing pull request. The handover carries the brief, the applicable artifact or current pull-request diff, and the finding; its predecessor, trigger, replacement and packet sources are recorded. That Claude session is resumed for later repairs even after the file returns to Codex. A conflicting per-issue override without the machine-triggered handover is refused, rather than silently discarded. A Codex override over a Claude machine value keeps the Codex lineage. There is no Opus-to-Codex handover.

The owner chose “B, hand over once” so in-flight work could continue during an outage, as a recorded, at-most-once exception to the one-builder-per-pull-request rule. The artifact requires reservation before the replacement may start; an uncertain start is reconciled with the reserved replacement, never treated as permission to start another. Historical vendor evidence comes from the matched bundle, not UUID shape or today's setting. A vendor-less legacy marker without a proving bundle needs authorized vendor-qualified recovery.

Judging compares the judge's actual vendor with the author or builder lineage that produced the material. An Opus judge on Opus work is recorded as same-vendor with a stage-local reason even when Claude was the requested judge; it is not called cross-vendor because no fallback occurred. The Codex judging-seat default stays as [D-733](D-733-2026-09-23-proof-as-one-act-per-head.md) recorded it. The change also makes no error-text fallback, standing Opus default, Claude seat executable-discovery change, or retirement of #683's interim override rulings.
