# D-90: The dispatch contract

**Status:** Accepted 2026-08-20 (PR #90)

## Context

[D-78](D-78-2026-08-19-carry-the-reasons.md) admitted one dispatch rule: a review dispatch carries the artifact's purpose statement verbatim or by link, never the dispatcher's paraphrase. Its exhibit was PR #78's own panel, which judged a compressed charter and filed false findings against affirmed content.

The rule reached the purpose statement and nothing else. Every other packet a stage receives was still authored by the dispatching session — which is, in this repo's single-session lanes, the artifact's author. Two occasions followed within a day — one a near-miss the existing rule absorbed, one a realized failure. On [#82](https://github.com/Grimblaz-and-Friends/tradecraft/issues/82): PR #81's six-seat panel was dispatched as six bespoke prompts, the shared material appearing in all six in varying wording and position, so a dispatcher free to retype the assignment six times could drift on it six ways — in exactly the sentence D-78 had just said must not be a paraphrase. #82 records that this one was harmless, because the pointer was a link rather than a restatement, which is what the existing rule bought. On [#88](https://github.com/Grimblaz-and-Friends/tradecraft/issues/88): a judge dispatched with "six matters it must settle itself," a docket the parent chose, so whatever did not make the parent's list would never be judged. Both raised by the owner in conversation, both filed at his instruction.

## Decision

**Every dispatch is built in three parts, in this order**: a shared block with nothing before it, byte-identical across every recipient at that stage, carrying the assignment and every predecessor stage's output whole; then a dispatcher's note where there is one, labeled as such and additive; last the recipient's own identity, lens brief, and working location where it differs. Calling attention is lawful; filtering and restating are not, and the seat stage takes no note at all, because a cold vantage sits there. **The terminal stage's docket is set by rule** — every merged finding, every defense verdict, every collision or open matter any stage flagged — with the dispatcher's "matters to settle" arriving as a labeled note on it.

This generalizes D-78 rather than sitting beside it. The fidelity requirement itself — carried verbatim or by link, never the dispatcher's paraphrase — moves into the general rule, along with the interested-party reason; the cold-boundary paragraph drops its enumeration entirely and keeps only its negative half, so the assignment is defined in one place.

**This is the second version of that sentence, and the first one was wrong.** As first landed, the general rule required only byte-identity *across recipients* — which is not fidelity *to a source*, and which is vacuous at the defense and judge stages, where there is one recipient. The fidelity requirement survived only inside the cold-seat paragraph, so the change narrowed D-78 while this entry claimed it generalized it. Five seats, the defense, the judge, and the external reviewer found it independently, and the panel's own seat dispatch proved it: an evidence-standards block introduced as a quotation was 5 of 7 bullets exact, and that compression — shipped byte-identically to all five recipients — satisfied the rule completely. The owner amended the affirmed text on 2026-08-20 to land what is written above.

**Placement is part of the decision.** Both issues proposed extending the cold-boundary paragraph for the general rule. It sits after that paragraph instead, under its own heading; the docket rule sits at the terminal stage, as #88 proposed: a session dispatching the judge never reads the cold-seat paragraph, and a rule binding every stage buried inside a rule about one stage stops firing for the others. The new heading also re-homes two existing paragraphs — the independence rule and the worktree rule — out of the roster section; both are self-scoping and neither changes meaning, and the move makes them findable, which is why it is recorded here rather than reversed.

**Nothing precedes the shared block**, which is the predecessor's rule imported as a lesson rather than an artifact. `agent-orchestra` requires the shared payload to sit *inside* the byte-identical span rather than merely first, because a handshake block and selector line preceded its packet and a per-dispatch timestamp in that preamble put unique bytes at position zero ([#975](https://github.com/Grimblaz/agent-orchestra/issues/975)). This repo has no such preamble, so for today's structure the two formulations coincide and only the four-word clause is worth its space. It is admitted on the correctness half alone: a preamble is somewhere to put per-recipient framing ahead of the assignment, which is the same hazard the rule exists to stop. The caching half of the predecessor's rationale is not imported — see below, and [#92](https://github.com/Grimblaz-and-Friends/tradecraft/issues/92).

**#82's prompt-caching argument was measured, and it did not hold at this scale.** The instrument exists and this entry first said it did not: `usage.cache_read_input_tokens` on the first assistant record of each `~/.claude/projects/<slug>/<session-id>/subagents/agent-*.jsonl`. Run across both panels: PR #81's six bespoke prompts shared a 12-character prefix and read 25291 cached tokens per warm dispatch; PR #90's five prompts shared a 5004-character block (5025-character common prefix) and read 23695–25254 across four warm dispatches — no higher, while cache-creation rose. The spread within that series is not explained here: across the wider corpus the same slot takes many values, and a cause written into a frozen entry on two data points would be the defect this paragraph corrects. The warm region is the harness's own system prompt and tools, which subagent dispatches share regardless of what the dispatcher writes; a shared block of this size sits after the last cache breakpoint and is written fresh every time.

**Bounded, not general.** The predecessor measured the opposite at roughly thirteen times this change's shared block: a span of 64,740 bytes, up from 314 before its own change ([agent-orchestra#979](https://github.com/Grimblaz/agent-orchestra/pull/979) and its `Documents/Design/review-dispatch-overhead-measurement.md`; the requirement itself is #975). It was published with its confounds: the model alias changed between runs and the scopes differed. Both results can stand; a payload large enough may clear a breakpoint that a 1,250-token one does not. What is settled is that **the cost argument buys nothing here and must stop being quoted as if it does.** The correctness half carries the rule alone, and it is the half this change's own review proved.

## Rejected

- **Judge-as-orchestrator** — the judge running the review and dispatching its own seats. It removes the author's thumb from the scale and replaces it with the judge's: a judge that staffed the panel, wrote the briefs, and ran the merge is a party to everything it later rules on, which is what the independence rules ("the judge never a finder") exist to prevent. It also spends the fresh terminal vantage the staffing section concentrates the top tier on.
- **Two separate changes, one per issue.** They are one rule at two scopes, and #82's rule and #88's relay rule land in the same sentence; the second would rewrite the first's sentence under a gate that had affirmed only half the composition. (The docket rule lands at the terminal stage, as #88 proposed.)
- **A prompt template or file format.** The rule constrains order and content, not markup. A template is a capability wrapper.
- **A mechanism.** No script can read a dispatch prompt's shape; the doctrine's admission order stops at skill prose here.

## Deferred, with the evidence that would reopen them

- **The parent-owned merge stays parent-owned.** Dedup can bury a finding, so the merge is in this defect class. The narrow duplicate definition — same failure mode at the same location — is the existing guard, and this change should not solve everything at once. **Reopen on:** the class recurring through the merge. **Fired:** this change's own review — the dispatching session's merge buried a seat's deletion remedy, and did it again in the post-fix look; filed as [#91](https://github.com/Grimblaz-and-Friends/tradecraft/issues/91).
- **A clerk that is not the author.** If these prose rules fail the way prose rules sometimes do here, the named next step is moving review orchestration onto a fresh session that did not write the artifact — not onto the judge. [#85](https://github.com/Grimblaz-and-Friends/tradecraft/issues/85)'s self-contained-artifact requirement — an affirmed artifact sufficient for a session with no access to the conversation — makes it nearly free once it lands. **Reopen on:** a recurrence after these rules are in force.
