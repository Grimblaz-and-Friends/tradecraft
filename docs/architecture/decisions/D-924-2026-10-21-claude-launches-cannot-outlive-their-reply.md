# A Claude launch cannot leave work running past its reply, and the launcher refuses a return that work outlived (#887)

**Purpose:** retain why every Claude launch from `lib/dispatch_seat.py` and `lib/dispatch_implementer.py` switches background work off, raises the one-command ceiling, excludes four tools on builders, and reads the stream before recording success. **Audience:** maintainers of the two launchers, `lib/dispatch_lifecycle.py` and the resume sets in `lib/work.py`, and adopters reading their records. **Success:** a maintainer can change a setting, the excluded tools or the stream check's arms knowing what each call rested on and which probe showed it.

The owner bought #887 and affirmed its brief on 2026-10-20 ("Both: switch background work off at every Claude launch, and have the launcher refuse to record success when the stream shows work outliving the reply", then "Raise it: each Claude launch lets one command run up to the stage's own limit, and the session is told it may ask for that", then "Affirm"). The harm was false or lost use evidence: a print-mode Claude session ends at its final reply, so a backgrounded command either died there and the launcher, which kept only the last `result` and checked its subtype, recorded a progress note as Daemon #78's use, or it re-woke the session and a short late reply replaced #886's real return. The settled artifact is [6301344120](https://github.com/Grimblaz-and-Friends/tradecraft/issues/887#issuecomment-6301344120), settled by the recorded cap resolution after two adverse cold rounds.

## The calls

- **The process environment carries both settings.** `claude_launch_env` sets `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` and `BASH_MAX_TIMEOUT_MS` to the recipient's allocation in milliseconds, overwriting any inherited value, because probe P5 showed the process value beat every settings source each launcher's real flags read: the builder's `--settings` file, and the seat root's project and local settings, which `--safe-mode` still reads. The user source was not tested directly; on builders it ranks below `--settings`.
- **The notice is part of the input.** `claude_launch_notice` tells the session it may ask for the ceiling, because the runtime's per-command default stays at 2 minutes and the brief rules out changing it. A seat appends it to the dispatch bytes it sends; a builder appends it to the effective input, so `effective_input_sha256` and the prompt-composition digest cover it.
- **Four tools are excluded on every author and builder launch** with the single argument `--disallowedTools=Monitor,ScheduleWakeup,CronCreate,Workflow`. The switch alone did not deliver row 1: under it Monitor still backgrounded a task and re-woke the session about 40 times (P3), ScheduleWakeup and CronCreate accepted a continuation the reply then ended with one clean `result`, which no stream check can see (P6), and a permitted Workflow backgrounded a task that outlived the reply and re-woke the session (P7). The flag is variadic, and a trailing two-token form swallowed the prompt in P6, so it is written `=`-joined. Seat `--tools` lists already name none of the four, so seats record `disallowed_tools: []`.
- **The stream check's rule.** The return is the first `result` that is not a resumed session's opening empty zero-turn result; the turn ends at the first `post_turn_summary` before it, or at the return. It fires on a further result after the return, a task event after it, or a task with an event before the turn's end and no terminal status by then, which includes one that reports `completed` afterwards, because P7's stream held the return until its background task had completed. Events at or before the last opener never count, because #886's healthy resume opens with a stop notice for the previous session.
- **A refused turn is `work_outlived_return`.** It publishes nothing, exits nonzero and keeps every event. It is in `RESUMABLE_BUNDLE_OUTCOMES` and never in `SUCCESSFUL_BUNDLE_OUTCOMES`, because resume selection admits only that set and a new failure outside it would start a fresh builder over a pushed branch (the Steward's review of the draft). It is treated like `invalid_artifact_return` where a later draft marker is flagged and where artifact continuity resumes, and is kept out of the filter that drops `invalid_artifact_return` for other stages. On seats it is recorded as itself, never as the vendor-availability outcome `unavailable`, and launches no fallback. `run_lifecycle.stopped` counts it with `interrupted` and `error`, so the entrance recovers a refused build or repair turn through `work_recovery.recommend` as `stopped-run-resume` on its own session; left out, the governing-terms check read the refused bundle as an unproved delivery and held the change as holder-owned (PR #924's connected review).
- **Records.** Each Claude request carries `launch_controls`, and each Claude attempt `stream_check` with `clean`, `work_outlived_return` or `unread`; Codex records carry neither, and the entrance's `implementer_environments` report prints `not recorded: launched before #887` only for a launched, completed attempt that lacks the field, and names an unlaunched or still-running attempt as such, because a record this launcher wrote is never one launched before #887 (PR #924's connected review).
- **Out of scope.** `lib/connected_review.py`'s Claude launch is neither launcher. Codex launches, stage limits, native Agent-tool and hand-recorded routes and #683's interims are unchanged.

## Builder calls

- **The entrance's composition check reproduces the notice.** `_composition_error` in `lib/work.py` recomputes the effective-input digest from the retained context and dispatch; the artifact did not name it, and left alone it would have read every new Claude builder bundle as differing from its frozen input. It now appends the notice recorded in `launch_controls` after checking that notice against its digest.
- **A seat's ceiling comes from the request's allocation**, so `launch_controls` is fixed when the request is written; an attempt's own allocation is never larger, and the launcher stops the process at the allocation regardless.
- **A Codex-primary seat request carries `launch_controls` when a Claude fallback is planned**; a Codex-only record carries neither field.
- **The check precedes the return's own success, error and denial fields**, so a fired check is the outcome even when the selected return also carries a failure. On builders a ceiling stop or a session-identity error still takes precedence, as before.

## Evidence

The artifact's probes ran on CLI 2.1.280 with `claude-haiku-4-5-20251001` at `low`, each with a control, and cost $1.99 as it recorded: P2 ($0.36) the switch against `--settings`; P3 ($0.75) the tools under the switch; P4 ($0.06) the ceiling against `--settings`; P5 ($0.26) precedence under each launcher's flags; P6 ($0.39) ScheduleWakeup and CronCreate; P7 ($0.18) Workflow. The holder's pickup probes ($0.92) are in the brief.

The build's live arms ran on the same CLI, model and effort, and cost $0.89 as the CLI reported:

- **Precedence.** Under a hostile builder `--settings` file (`"0"`, `300000`) a `run_in_background` request failed with an InputValidationError, as it did in the read-proof arm with `"1"` and no process value. Under the seat root's hostile project and local settings the session found no `run_in_background` parameter and ran no background task, as in its read-proof arm through the pre-change launcher; the no-settings control is P5's.
- **Timeout.** Through the built seat launcher a command past its 10-second timeout reported exit 143 in the same turn, with no backgrounded task.
- **Ceiling.** An 11-minute command at timeout 700000 completed in one call under a built seat launch with `--timeout-seconds 900` and wrote its marker. A 330-second command at timeout 400000 completed under both hostile `300000` sources through the built launchers and was stopped at 5m0s in each read-proof arm.
- **Excluded tools.** Each of the four was absent from `init.tools` and from `ToolSearch` on the built builder argv, with one result and a clean check; without the exclusion all four were listed, ScheduleWakeup and CronCreate were accepted, and Monitor and a permitted Workflow started background tasks whose streams the new check refused. These builder arms added `--allowedTools=Bash`, as P6 and P7 did.

`lib/tests/test_launch_controls.py` carries the parser criteria R3-1 to R3-6d with synthetic fixtures; `lib/tests/test_dispatch_seat.py` and `lib/tests/test_dispatch_implementer.py` carry the settings, notice, record and refusal criteria on both launchers; `lib/tests/test_work.py` carries resume selection and the draft-marker flag; `lib/tests/test_implementer_reports.py` carries the report. Owed after merge: the first entrance-run build or repair shows `launch_controls` with all four tools and no backgrounded task, and the first long command over 600000 completes in one call.
