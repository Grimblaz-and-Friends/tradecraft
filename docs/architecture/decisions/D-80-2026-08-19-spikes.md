# D-80: Spikes test a premise before it is asserted

**Status:** Accepted 2026-08-19 (PR #80)

## Context

[#28](https://github.com/Grimblaz-and-Friends/tradecraft/issues/28) filed the idea in one line: build something cheap and throwaway before writing the requirements, because many things cannot be found until you try them. The evidence for the narrower half is [#42](https://github.com/Grimblaz-and-Friends/tradecraft/issues/42), whose design reached revision four plus fifteen errata on premises that turned out false about the material. Three of its most consequential discoveries were made while building and appear in none of its review counts: an inventory recovered seven operative rules living in `## Consequences` and `## Context` blocks; a document assumed one post-freeze offset and had five; and sabotaging a script's `main()` to return zero left the first seventeen guard pins green, because the tests could not see the channel CI actually reads. Reading finds none of these — each is a claim about what is in the material, or about whether a mechanism fires.

Admitted as an owner-stated requirement ([D-74](D-74-2026-08-19-constitutional-reset.md)); the trigger condition rests on #42's incidents rather than on [D-77](D-77-2026-08-19-owner-approval-admission-path.md)'s owner path, which is not spent where the ordinary road is open.

## Decision

`skills/authoring/references/spikes.md`, loaded on demand from a one-clause trigger in `SKILL.md`. A spike fires where a pre-implementation artifact asserts something about material nobody has enumerated or about a mechanism nobody has executed; it tests one named premise and stops when that premise is answered either way; unanswered, it is abandoned and the premise enters the artifact as a declared assumption. It reports on the work's issue whether the premise held or fell.

**A spike commits nothing** — scratch tree or throwaway worktree, no tracked file, no branch, no pull request. Stating this as what a spike *is*, rather than as a rule about disposing of one afterwards, is what makes it a bright line needing no branch to check, and it answers the exemption question by leaving the gates no operand: convergence fires on the artifact the spike feeds, release has nothing to merge. The reference says plainly that the rule cannot detect copying — a tree where a session spiked and copied is indistinguishable from one where it wrote the code fresh — and names what bounds the damage instead: code leaving a spike is written again through the ordinary flow, so a leak costs duplicated effort and never unreviewed code.

**Open exploration without a formed question is granted rather than proceduralised.** An earlier revision of the artifact argued for omitting it entirely, on the ground that a strong senior engineer needs no permission to go try something. [D-78](D-78-2026-08-19-carry-the-reasons.md) removed that fixed persona from the authoring standard in favour of the audience the purpose statement names, noting that a session over-obeys where a person skims — which inverts the conclusion: the permission is exactly what a session handed only the named-premise pattern would not assume. The procedure stays unwritten because its stopping condition is judgment, and a procedure would either invent a budget that goes stale or pretend to a bound it does not have.

## Rejected

- **Quarantining spike code in the repo**, cited as evidence and rewritten for the implementation: the code rots in the tree, and "may cite but must rewrite" is enforced only by memory. Note the zone wall does not help here — most of what gets spiked lands in `tools/`, repo-only on both sides.
- **Allowing promotion through the ordinary gates**: honest about what happens anyway, and it destroys the property that makes a spike cheap. If a spike can become the implementation, sessions build it to implementation quality and the expensive build has simply moved earlier with the design skipped.
- **A time or token budget as the bound**: a figure for a build's cost goes stale as models get faster, and it is the wrong instrument regardless — a two-hour spike that never states what it is testing is unbounded in the way that matters.
- **Its own skill**: fails the authoring skill's independent-trigger test, since a spike fires because an artifact is being written.
- **A doctrine line**: methodology, not a rule that must bind before any context loads; and a doctrine line does not travel to consumers, where a skill's reference does.
- **Spiking to catch design defects**: prose consistency, citation correctness and reasoning defects are adversarial review's job, and building tells you nothing about them.
