# D-80: Spikes test a premise before it is asserted

**Status:** Accepted 2026-08-19 (PR #80)

## Context

[#28](https://github.com/Grimblaz-and-Friends/tradecraft/issues/28) filed the idea in one line: build something cheap and throwaway before writing the requirements, because many things cannot be found until you try them. The evidence for the narrower half is the constitutional migration: designed on [#42](https://github.com/Grimblaz-and-Friends/tradecraft/issues/42), implemented in [PR #53](https://github.com/Grimblaz-and-Friends/tradecraft/pull/53), which is where the discoveries and their counts are recorded — an inventory recovering operative rules from `## Consequences` and `## Context` blocks, a uniform post-freeze offset that was not uniform, and a sabotaged `main()` leaving guard pins green because the tests could not see the channel CI reads.

**The claim these support is narrower than it first looks, and the narrowing matters.** Two were made only by going and looking. The third was caught by a review — `H7`, sustained high, by the `wiring-falsifier` seat — but at *implementation*, after the design had already asserted the guard fires; a spike moves that check in front of the assertion. So the warrant is not that review cannot find these. It is that reading a design settles neither what is in the material nor whether a mechanism fires, and the cheapest time to find out is before the assertion is affirmed. #42's revision count is not offered as the cost of false premises — its revisions were an owner-directed scope change and then fix batches for review findings, and none of the three discoveries existed when any of them was written.

Admitted as an owner-stated requirement ([D-74](D-74-2026-08-19-constitutional-reset.md)); the trigger condition rests on the migration's incidents rather than on [D-77](D-77-2026-08-19-owner-approval-admission-path.md)'s owner path, which is not spent where the ordinary road is open.

## Decision

`skills/authoring/references/spikes.md`, loaded on demand from a one-clause trigger in `SKILL.md`. A spike fires where a pre-implementation artifact asserts something about material no enumeration the session can consult covers, or about a mechanism nobody has executed; it tests one named premise and stops when that premise is answered either way; unanswered, it is abandoned and the premise enters the artifact as a declared assumption. It reports on the work's issue in all three cases — the abandoned spike above all, since a premise declared open with no record of what was tested is the one a later reader cannot weigh. **The predicate is keyed to what the session can consult, not to what anyone has ever done**: a trigger turning on the whole world's knowledge is one no session can evaluate, and one keyed to the session's own ignorance would fire on every session, which is what a narrow trigger exists to prevent.

**A spike commits nothing** — a scratch tree outside the repository, no tracked file, no branch, no pull request. A throwaway *worktree* was the mechanism first named, and plain `git worktree add` creates a branch by default — so the named mechanism produced the thing the rule forbids. What is unlawful is the default, not the mechanism: a **detached** worktree creates no branch. The tracked-file case needs a tree that has the repository's files — a detached worktree or a throwaway clone — so an empty scratch directory does not serve it. Stating this as what a spike *is*, rather than as a rule about disposing of one afterwards, is what makes it a bright line needing no branch to check, and it answers the exemption question by leaving the gates no operand: convergence fires on the artifact the spike feeds, release has nothing to merge. The reference says plainly that the rule cannot detect copying — a tree where a session spiked and copied is indistinguishable from one where it wrote the code fresh — and names what bounds the damage instead: code leaving a spike is written again through the ordinary flow, so a leak costs duplicated effort and never unreviewed code.

**Open exploration without a formed question is granted rather than proceduralised.** An earlier revision of the artifact argued for omitting it entirely, on the ground that a strong senior engineer needs no permission to go try something. [D-78](D-78-2026-08-19-carry-the-reasons.md) removed that fixed persona from the authoring standard in favour of the audience the purpose statement names, noting that a session over-obeys where a person skims — which inverts the conclusion: the permission is exactly what a session handed only the named-premise pattern would not assume. The procedure stays unwritten because its stopping condition is judgment, and a procedure would either invent a budget that goes stale or pretend to a bound it does not have.

## Rejected

- **Quarantining spike code in the repo**, cited as evidence and rewritten for the implementation: the code rots in the tree, and "may cite but must rewrite" is enforced only by memory. Note the zone wall does not help here — much of what would be spiked (a guard, a script) lands in `tools/`, repo-only on both sides.
- **Allowing promotion through the ordinary gates**: honest about what happens anyway, and it destroys the property that makes a spike cheap. If a spike can become the implementation, sessions build it to implementation quality and the expensive build has simply moved earlier with the design skipped.
- **A time or token budget as the bound**: a figure for a build's cost goes stale as models get faster, and it is the wrong instrument regardless — a two-hour spike that never states what it is testing is unbounded in the way that matters.
- **A section in the `authoring` skill's body**, the closest rival to what shipped. Rejected on net growth: the trigger is narrow and conditional, so the always-read body would carry the exclusions, the abandonment route, the report's contents, the unenforceability concession and the exploration grant for the many sessions that never spike. **The routing reason stated when this was affirmed does not hold and is corrected here**: that reasoning promised the reference would carry depth — how to pick a premise, how to sabotage a mechanism convincingly, what a useful inventory looks like — and it carries none of it. Writing that depth was declined as procedural how-to about a practice with zero runs. What justifies the reference is the conditional material above, not the depth that was promised.
- **Its own skill**: fails the authoring skill's independent-trigger test, since a spike fires because an artifact is being written.
- **A doctrine line**: methodology, not a rule that must bind before any context loads; and a doctrine line does not travel to consumers, where a skill's reference does.
