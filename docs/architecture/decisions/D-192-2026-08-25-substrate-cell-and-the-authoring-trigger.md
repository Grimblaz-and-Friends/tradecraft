# D-192: The code standards get a cell whose description fires for the session writing code

**Status:** Accepted 2026-08-25 (PR #192)

## Context

[#188](https://github.com/Grimblaz-and-Friends/tradecraft/issues/188) was filed by PR #186's terminal stage, which rescoped a trigger edit out of a fix batch on the ground that a description two characters from its ceiling cannot absorb one. #186 then landed anyway, so the diagnosis arrived on the tree rather than as a forecast.

At `da2e11b`, `authoring`'s description measured **690 of the 700-character ceiling** (`CELL_FIELD_MAX_CHARS`, `tools/lint.py`) and its body **7,357 of 7,359** (`CELL_BODY_BUDGET_CHARS`) — headroom 10 and 2. Both of the cell's budgeted surfaces were full. #186 had shed its text-mode rules to `skills/authoring/references/text-mode.md` at `da2e11b` under exactly that pressure, and that file opens *"Load this when writing a script that prints, or that writes a file something will later compare, restore or measure."*

**That load condition was unreachable for the session it names.** A `references/` file loads from a pointer in the cell's body; the body loads when the description fires; and `authoring`'s six triggers were all prose-shaped — writing or restructuring a skill or governing document, writing or revising a description, deciding whether prose moves behind a pointer, deciding where content belongs or editing an always-on surface, revising governing prose, stating derived figures. None of them describes *I am writing a script*. The cell's own standard says the failure mode is under-triggering, and it had reached the state its own standard names while having no characters left to fix it.

The prose was also narrower than the rule it stated. The bullet read *"Code a cell carries meets the substrate's standards"*, while `check_emitted_ascii` and `check_stdio_wired` parse every `.py` file in the repository — and `git ls-files '*.py' | grep -v '^skills/' | wc -l` returns **11 of 15** at `da2e11b`.

## Decision

**The substrate standards get a cell, `substrate`, and take the text-mode reference with them** — `skills/authoring/references/text-mode.md` at `da2e11b`, now `skills/substrate/references/text-mode.md`. `skills/authoring/references/routing.md` supplies the test and answers it: *"A piece is its own skill when it has an independent trigger: a situation where it should fire without the parent job underway... Where no cell serves it at all, the answer is a new cell — the burden sits on cramming rather than on creating."* A session writing `tools/lint.py` is not authoring a governing document, and no cell on the roster — read at `da2e11b`, all eight — fired for it; `persist-changes` is the nearest and governs committing, not writing.

**The scope widens, and that is a meaning change rather than a relocation.** From *code a cell carries* to the code this practice ships and runs, which is what the two guards already enforced and what 11 of 15 files needed.

**`authoring`'s description is re-derived, not trimmed to fit.** Two triggers were subsets of a third and fold into it: *"writing or revising a skill's description"* and *"deciding whether a skill's prose should move behind a pointer"* become *"including a description alone or what sheds behind a pointer"* on the writing clause, which also absorbs *"revising governing prose"*. The code job is stated as a non-trigger in the excluding form the cell's own standard permits — the job, not the cell, because the sideways-dependency guard refuses the reserved name form between siblings. Landed: **632 of 700, headroom 68**, against a bar of 61 — the median of the five trigger clauses the description carried at the merge base. Its body landed at **6,471 of 7,359, headroom 888**, against a bar of 387 — the median of its twelve bullets.

**`AGENTS.md` repoints two citations at no change in size.** The calling-contract line and the substrate line move from the `authoring` cell to the `substrate` cell; the two names are nine characters each, so a doctrine file with five characters of headroom absorbed the edit exactly.

**`substrate` gets no body budget.** [D-184](D-184-2026-08-25-outflow-and-the-always-on-total.md) holds that a cell absent from `CELL_BODY_BUDGET_CHARS` is unbudgeted on purpose: a number chosen for a cell nobody has argued about is a ruling on its size arriving as a constant. Its description landed at 571 and its body at 1,486.

**The outflow produced one move and one refusal, and the price is stated rather than absorbed.** The move is the second of the three and is this change's whole content — a rule that binds only inside one activity goes to that activity's cell. The refusal is `AGENTS.md`'s CRLF clause, which #186 placed there: `substrate` fires for a session *writing* a script, and that clause is for a session confused by ` M` against an empty diff after *running* one, so moving it would strand the reader it was written for. **A ninth name-and-description pair is a net addition to the always-on surface**, and `skills/authoring/references/routing.md` is explicit that a body-to-body move is not a reduction. Measured by `python tools/figures.py`: the adopter's total goes **9,747 → 10,269, +522**; this repository's **15,753 → 16,275**; `authoring`'s own pair falls 699 → 641. The argument for paying it is that a rule nobody loads costs the same in bytes and delivers nothing — the surface's job is to fire, and for 11 of 15 Python files these rules did not.

## Rejected

- **A `references/` file inside `authoring` plus a code trigger on its description** (fork 1, owner-ruled). Cheaper on the always-on surface by roughly the difference between a trigger clause and a whole pair, and it fixes the body budget the same way — but it makes `authoring` a two-job cell whose purpose header has to widen from prose to prose-and-code, and it answers the routing rule's independent-trigger test by declining to apply it. A session writing `tools/lint.py` would still have to fire a cell called *authoring* to learn how.
- **Adding one trigger to the full string.** This is what #186's terminal stage refused and filed #188 over. At 10 characters of headroom the trade is not an edit; it is a deletion chosen under end-of-batch pressure, which is how [D-184](D-184-2026-08-25-outflow-and-the-always-on-total.md) already recorded losing D-141's recognisability examples.
- **Raising `CELL_BODY_BUDGET_CHARS`.** It answers neither the trigger gap nor the ceiling and ratifies the cell's size by editing a constant — the shape D-184 created that guard to make visible.
- **Ratcheting the 700-character ceiling in this change.** Measured at `da2e11b`, it binds exactly one cell: the other seven descriptions are 592, 590, 588, 529, 511, 497, 308. Ratcheting it inside the change that resizes the one cell it binds would pin the ceiling to a number this change chose for itself, which is the failure D-184's own margin note describes. The landed headroom is on the PR so a later change can ratchet against a settled tree.
- **Re-expanding the calling-contract reason that #186 compressed to `[D-156]`.** A cell body carries no budget, so the pressure that forced the compression is gone — but the compression was itself a lawful outflow move, and undoing it because room appeared is churn. The rule keeps one reason clause and the citation keeps the rest.
- **Three clauses in the first draft of the cell**, removed before commit: a rule about admitting dependencies, a claim about where a test may live, and a reason bullet 5 already carried. The first two were agent-proposed rules with no incident behind them, which the charter's admission order refuses outright; the third was net growth for nothing.
