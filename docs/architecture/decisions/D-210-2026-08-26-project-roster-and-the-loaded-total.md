# D-210: The roster a session here loads is generated, and the total is read from it

**Status:** Accepted 2026-08-26 (PR #210)

## Context

A cell's `description` is the whole of its triggering surface and is always loaded. [D-141](D-141-2026-08-23-figures-are-derived.md) rejected a doctrine pointer on that ground — *"a shipped trigger reaches every consumer and costs none of the doctrine's remaining budget"* — and put the derived-figures trigger in `authoring`'s description. [D-184](D-184-2026-08-25-outflow-and-the-always-on-total.md) then made the move load-bearing and recorded it as **the load-bearing correction** of that change: an earlier draft put the outflow's firing condition in the cell's body, a cold consumer failed to find it, and *"the trigger moved to `authoring`'s description, which is the surface that actually always loads"*.

Both are true of an adopter, who installs the plugin. Neither was true here. `.claude-plugin/marketplace.json` lists this repository as a plugin source and nothing installs it into this repository, so no Claude Code session working here held any cell's name or description; a session reached a cell by opening a file. **Every trigger routed to a description over several changes reached every consumer and missed us.**

[#199](https://github.com/Grimblaz-and-Friends/tradecraft/issues/199) was filed by PR #194's experience session across four cold consumer runs. Three of four never reached `skills/authoring/references/frozen-documents.md`, whose trigger lives in a description, and two wrote a rule violation into a commit message and a PR body as a direct result. One consumer read `AGENTS.md`, pulled the first 400 bytes of every `SKILL.md` frontmatter — truncating `authoring`'s description before the trigger clause, which measured 690 characters at `da2e11b` and `81fb1d9`, the trees that run was against (622 at this entry's own tree) — and went straight to `skills/authoring/references/routing.md` without opening the cell at all.

The figure recorded the same gap and reported past it. `figure_always_on` counted the roster on both sides, which is what an adopter loads and what this repository *would* load: **16,241 characters here against 11,351 a Claude Code session here actually read.** The instrument this practice uses to find out whether a trigger works was running in the one environment where that class of trigger could not work.

## Decision

**The roster a session here loads is generated into `.claude/skills/`, one entry per cell.** `tools/roster.py` writes the cell's frontmatter byte for byte — the part that must load — over a body naming the generator and pointing at the cell. Claude Code loads that directory with no install, no settings edit, and no command run, which a fresh headless session in this branch's worktree confirmed by listing all nine cells and quoting one description back with instructions to read no files.

**The prose keeps one owner.** Only the triggering surface is reproduced, and `check_project_roster` holds the two in step. `verify()` names its shapes rather than counting them, because a stated count of them has now been wrong twice — the second time in the sentence written to fix the first. Three name `--write`: a missing entry, an entry out of step, a generated orphan. Two name no command, because only a person can choose: a cell whose frontmatter will not parse, and a cell's name held by a file this generator did not write. **The expected bytes are the generator's, asked for rather than recomputed** — a guard holding a second definition of what a writer produces agrees with it exactly until either is edited, which is the failure `_always_on` in `tools/figures.py` already records from this repository, where two hand-written copies of one sum let a mutation through green.

**The entry is a pointer rather than a copy**, so invoking a cell by name here reaches the pointer and reads the cell, one hop. That hop is measured rather than assumed: a fresh session given an ordinary filing job, with no mention of skills, invoked `filing` from the generated entry, followed the pointer to `skills/filing/SKILL.md`, and then applied the cell — running its search-before-you-file reasoning and declining a filing whose premise did not hold. Copying whole bodies instead would put **78,931 characters** of prose in a second place and every cell edit into two diffs — the sum over every cell of the file's decoded characters less the block `roster.frontmatter` returns, at this entry's own tree.

**The roster directory is shared, not owned, and ownership is checked on every path that touches a file.** `.claude/skills/<name>/SKILL.md` is the runtime's documented home for a project's own skills — the whole property this change depends on — so a session may lawfully write one there by hand. **The roster owns exactly two things: a name that is a cell, and a file carrying the generated marker.** At a name that is no cell, a foreign file is simply not its business and draws no finding; at a cell's name, a foreign file is a finding that names no command, because the hand-written frontmatter is what loads and the cell's real description then loads nowhere — which only a person can resolve.

Both halves were bought by failures. The orphan branch's remedy used to unlink whatever it found: an untracked file, no prompt, exit 0, lint green over the remains — found at high by three seats independently, all three having run the deletion. Guarding removal alone then left the regeneration branch destroying the same content on a name collision, and made a lawfully hand-written project skill an unclearable lint red — both found by the post-fix look, one of them raised to high on the same evidence as the first. Checking ownership on one path is what let the second survive the fix for the first. **The accepted residual: a directory left under `.claude/skills/` with no `SKILL.md` draws no standing finding** — it holds no skill, so it loads nothing, and `write()` reports residue at the moment it creates it, which is where that report is useful.

**`--write` reports a cell it cannot read rather than raising on it.** It used to let the exception out mid-loop, so entries sorting before the bad cell were already on disk, entries after were untouched, and the orphan-removal loop never ran — the one command every finding named handing back a traceback and a tree in neither state. It now finishes the work it can, reports what it skipped, and re-verifies before exiting, so its exit code answers whether the tree is lawful rather than whether the loop ran.

**Each audience's roster is read from the directory that audience loads it from.** An adopter's from `skills/`, this repository's from `.claude/skills/`. The total is unchanged at 16,241 and now means something different: it is derived from the surface rather than asserted about it, so deleting an entry moves it. What a Claude Code session here actually loads rose **11,351 → 16,241** — a Codex session here loads neither roster and stays at 11,351 — which is a real context cost paid deliberately — the 4,890 the figure had been claiming all along. `always_on_at` splits the same way, so both halves of a delta share one definition.

**No always-on artifact was edited, so no outflow was owed.** The obligation fires on editing one; this change moves no rule and adds no prose to the doctrine, the charter, or any description. The prose delta reads `+0` for that reason, and the roster's own bytes sit under `.claude/`, which no delta measures — stated on the PR rather than left to read as *no new bytes*.

**`.claude` stays out of `REPO_ROOTS`, with the reason narrowed rather than left standing.** Tracking one subtree of it did not answer the constant's recorded objection: a session can still drop `.claude/agents` into a working tree, so admitting `.claude` as a root would reinstate the two-answers defect for every path under it that is not the roster, and admitting the roster alone would be a root one directory deep, which nothing else there is.

**No doctrine rule was added**, per the admission order. What a session needs — that the file is generated, what generates it, where the cell is — the file says itself, and the guard fails when it is wrong. The generated files are written and read as **bytes**, per the substrate cell's third text-mode rule: they are compared on every lint run, and a text-mode write would hold different bytes depending on the platform the generator last ran on. A test caught exactly that through its own fixture, which handed Windows a CRLF cell no checkout here produces.

## Rejected

- **Installing this repository's own plugin**, at any scope. Plugin sources cache per `plugin.json` version — documented — so a session here would read the *published* descriptions rather than the branch's, backwards for exactly the sessions that edit them. `--plugin-dir` does load a directory live, and does not rescue the route: it is per session, and criterion 1 forbids a command run in as many words. Whether any *persistent* live mode exists for a directory or git source is undocumented either way, which is a weaker claim than an earlier draft of this entry made. The second limb stands on its own: a plugin enabled only by committed project settings does not load until each person runs the install command — which this repository's `README.md` records as an observation against every CLI surface tried, while explicitly disclaiming that it measured what a teammate gets.
- **Relocating the cells to `.claude/skills/`** and pointing `plugin.json`'s `skills` field there, which is technically available since that field adds paths rather than replacing the default. Priced out at **120 references to `skills/` inside frozen decision entries** — `grep -rn "skills/" docs/architecture/decisions | wc -l` at `87d1d65` — which the log's mover-pays rule would oblige repointing, many of them quotations where repointing would falsify the sentence and force a recorded exemption instead.
- **A committed symlink**, the form Claude Code documents for `.claude/skills/<name>`. Dead on the owner's machine: `mklink /D` returns *insufficient privilege*, git carries `core.symlinks=false`, and MSYS `ln -s` silently copies, so the entry would check out as a broken duplicate.
- **Accepting the split and stating it** — a clause in `authoring` saying a description-borne trigger does not fire in the practice's own repository, plus a figure reporting what a session here loads. The cheapest option and the one that leaves the defect live: the next cold consumer here still misses the rule, and every future routing call stays worse here than it looks. Put to the owner as one of three at convergence; he picked the mechanism.
- **A repo-only `SessionStart` hook emitting the roster as prose.** Strictly worse once the native route was shown to work: it costs the same characters, needs project settings and a trust prompt, and leaves cells not invocable by name.
- **Adding `.claude` to `REPO_ONLY_NAMES`.** `skills/experience-session/SKILL.md` already names `.claude/skills/` in shipped prose lawfully — it is where a consumer tree puts cells so their descriptions load — and that rule would turn a lawful line red.
- **Adding `.claude/skills/` to the prose delta's paths.** It would double-count every description edit, since the entry and the cell always change together.
- **Fixing [#198](https://github.com/Grimblaz-and-Friends/tradecraft/issues/198) here.** The generated frontmatter is byte-identical to cells `check_cell_frontmatter` already reads, so the roster is guarded transitively; that issue's blind spot is neither depended on nor closed.

## Evidence

**Criterion 2 is met with a limit, and the limit is on the record rather than reinterpreted.** Its affirmed wording is a universal — *a session here that meets a situation whose only trigger lives in a cell description reaches that cell's rule* — and its stated falsifier fired: of two cold consumers whose jobs met the condition, one reached the rule through the description and one did not, reaching an adjacent discipline through a script's comments instead. **1 of 2 on this repository's own trees.** A description that loads is necessary for firing and is not sufficient, which is what this change buys and the whole of what it buys.
