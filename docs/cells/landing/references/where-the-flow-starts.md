# Where the flow starts

**Loaded when** your change may owe no implementation brief, may carry an affirmed mechanical lane, or may deliver the truth of some text, and you want to know what that changes about where this cell's flow starts. This file says which step each class skips and names the surface or decision that selects it.

**Where the flow starts depends on the change.** Purely mechanical work under the charter has no implementation brief and no artifact to settle, so it branches and goes straight to *build*; the branch is never skipped, `main` refusing direct pushes. Its pull request still carries the experience session or the line declining it before ready, as the `experience-session` cell decides. This no-brief class is not a shortcut for brief-backed work.

**A change that owes an implementation brief starts with design and the owner's affirmation.** When the owner selects `ordinary` / `mechanical`, that lane skips the artifact, cold seat and use regardless of changed paths, then retains the floor, connected reviewers, proof and release report; the proof command supplies its current-head no-use carrier. The holder proposes the lane and the owner selects it, so this cell never infers it from size or paths. Every other affirmed lane follows the ordinary artifact and path-classified use route.

**Where what the change delivers is the truth of some text, a slice of build precedes the artifact**, as the flow chain marks and the `engagement` cell states; the artifact stays settled before the first commit.
