# Implementer environments

**Purpose:** constrain author and builder launches and describe what each actually held. **Audience:** launchers, holders and adopters reading artifact/build/repair records. **Success:** operating settings survive, observations have sources and coverage, and unknowns or excess never masquerade as requested exclusions.

Claude retains the user setting source, global instructions, native memory and permission configuration; project/local sources remain excluded. Strict MCP configuration supplies no servers, Chrome is disabled, and invocation-private settings disable discovered foreign plugin IDs without replacing other user keys. Only verified tradecraft's directory is supplied, inherited foreign sideloads are suppressed in the child, and runtime built-ins remain. Discovery includes installed disabled IDs and declared/supplemental origin metadata; it executes no plugin code. The private override survives the child and is then removed. Sync settings and owner installations are never changed, because sync-disable can remove cached material beyond a turn. Preparation failures retain their causes and never fall back to an unrestricted launch.

Codex retains user configuration, sandbox/network and shell/pytest settings. An invocation-owned app-server disables apps and computer/browser features; effective config discovery supplies exact-name false overrides for standalone MCP and foreign configured plugins. Native installed IDs are rediscovered for every invocation and passed as the complete `disabledPluginIds` on `turn/start`, because omitting that field retains an older list. Fresh `thread/start` or exact-identity `thread/resume` receives workspace-write, on-request approvals and automatic review; artifact turns retain their tighter filesystem policy. The frozen dispatch is the sole user input; no preparatory model turn runs. Unsupported client requests receive a recorded error, never a fabricated approval. The process owner drains both streams, closes input and stops descendants within the invocation deadline.

Requests freeze intent, discovery identities/paths and override digests, separately from observations. Each attempt's additive `environment` uses local `schema_version=1` without changing the enclosing dispatch schema. It records runtime version, session/current turn, boundary and these categories: `plugins`, `integrations`, `tools`, `skills`, `instructions`, `memory`, `permissions`. A category has `status` (`known`, `partial`, `unknown`), `values`, `reason` and exact runtime `sources`. Only an explicit complete native inventory proves known empty. Missing fields, false app/plugin instruction booleans, config and saved exclusions cannot do so.

Claude's init owns its invocation snapshot, including full tool/skill lists, memory paths and actual permission mode. Codex's matched session log owns current-turn context; startup instruction sources are separately attributed to the native startup response. Skill ownership proves visible skill-providing plugins only, so that catalog is partial. Resolve skill aliases only against roots from that report. Instruction prose is retained only as a digest, never as a file inventory inferred from existence or similarity. Unreported memory, tools, integrations or sandbox implementation stay unknown. Session logs must match metadata/session and current-turn identity; older world states, finals and usage are not current evidence. Unsupported formats or inaccessible logs explain unknowns without stopping the turn.

Observations checkpoint while running and survive failed output, malformed lines and stops. Positive foreign plugins/skills, servers, integrations and desktop tools appear in `excess`; unfamiliar tools remain unclassified. Present, none-observed and unknown are distinct. Excess is information for the holder's path reading, never an execution, publication, readiness or release gate. Memory paths describe held context, including Claude's writable memory store; they establish no write audit or read-only boundary.

Native Codex parsing correlates RPC requests and acknowledged session/current turn. A matching completed terminal event owns completion despite transient errors; failure, interruption, missing terminal or protocol error do not. The last completed current-turn agent message owns the source return. Fresh usage retains the latest cumulative `tokenUsage.total` with every native class rather than summing snapshots or using `last`; resumed invocation usage is unknown without a proved baseline. Historical exec parsing and judging launch defaults remain unchanged. Source bytes flush before atomic publication; final records are immutable.

The entrance's `implementer_environments` names bundle/dispatch/stage/vendor/session/turn, lifecycle/outcome, coverage, values, reasons and excess. Immediate reports include the just-run failed/interrupted/no-output attempt before artifact-copy disposal. Later reads use existing work, holder, instalment and lineage scopes and deduplicate dispatch IDs; they perform no catalog/account/network discovery. Missing historical environments say `unknown: producer did not record an observed launch environment`; malformed and unfinished bundles stay visible. Old records remain byte-for-byte unchanged and resumable.

No normalized environment contains credentials, full settings, global instruction prose or memory contents. Native capture keeps its existing retention contract.
