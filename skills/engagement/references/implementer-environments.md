# Implementer environments

**Purpose:** constrain author and builder launches and describe what each actually held. **Audience:** launchers, holders and adopters reading artifact/build/repair records. **Success:** operating settings survive, observations have sources and coverage, and unknowns or excess never masquerade as requested exclusions.

Claude retains the user setting source, global instructions, native memory and permission configuration; project/local sources remain excluded. The tree's own root instructions still load natively, as a Codex builder's `AGENTS.md` does, so they hold for every turn rather than resting on the builder choosing to read them: the launch adds its working tree with `--add-dir` and the child sets `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`, so the runtime loads that tree's `CLAUDE.md`, `.claude/CLAUDE.md` and `.claude/rules/`, with every file they import, and nothing from a directory above the tree. Tree skills, commands, agents, output styles, hooks and settings still do not load, and neither does `CLAUDE.local.md`. A tree whose rules live only in `AGENTS.md` gets a one-line shim `CLAUDE.md` importing it, written for that invocation in the tree's Git directory with a relative import, or else in the invocation's temporary directory with an absolute one, and removed when the invocation ends; spaces in the import are escaped. The launcher removes the shim ignoring errors, and the record does not prove the removal. No tested form of an import path containing `#` loaded, raw or escaped, so when neither placement avoids one the Claude launch is refused before any process starts, naming the tree; relaunch on Codex or move the tree. Strict MCP configuration supplies no servers, Chrome is disabled, and invocation-private settings disable discovered foreign plugin IDs without replacing other user keys. The child process sets `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=0` before discovery and launch to exclude installed function-hook mods from inherited environment or user settings, while runtime built-ins remain. Only verified tradecraft's directory is supplied, inherited foreign sideloads are suppressed in the child, and runtime built-ins remain. Discovery includes installed disabled IDs and declared/supplemental origin metadata; it executes no plugin code. The private override survives the child and is then removed. Sync settings and owner installations are never changed, because sync-disable can remove cached material beyond a turn. Preparation failures retain their causes and never fall back to an unrestricted launch.

Every Claude launch from either launcher, seat and use consumer included, sets `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` and `BASH_MAX_TIMEOUT_MS` to the recipient's allocation in milliseconds in the child process environment, overwriting any inherited value, because a print-mode session ends at its final reply and anything still running then is lost, while the process value beats every settings source a launch reads. A session therefore cannot start a background command, a command past its timeout is stopped and reported in its own turn, and one command may run as long as the launch itself; a launcher notice appended to the input the child receives tells it so, and an implementer's `effective_input_sha256` covers that notice. Author and builder launches also pass `--disallowedTools=Monitor,ScheduleWakeup,CronCreate,Workflow` as one argument, because each of those can leave work running past the reply or schedule a continuation the reply ends even with background tasks off; seat `--tools` lists already name none of them. The launcher then reads the stream: the return is the first result that is not a resumed session's opening empty result, and the turn ends at the first `post_turn_summary` before it. A further result after the return, a task event after it, or a task still running when the turn ended records `work_outlived_return`, publishes nothing, exits nonzero and keeps every event in the log; a seat does not fall back, and an author or builder session stays the next turn's resume source. Each Claude request records `launch_controls` (both values with their sources, the excluded tools, and the notice digest) and each Claude attempt records `stream_check` (`clean`, `work_outlived_return`, or `unread` when no return could be read, with the return line, turn-end line, result lines, causes and backgrounded task ids). Codex records carry neither.

Codex retains user configuration, sandbox/network and shell/pytest settings. An invocation-owned app-server disables apps and computer/browser features; effective config discovery supplies exact-name false overrides for standalone MCP and foreign configured plugins. Native installed IDs are rediscovered for every invocation and passed as the complete `disabledPluginIds` on `turn/start`, because omitting that field retains an older list. Fresh `thread/start` or exact-identity `thread/resume` receives workspace-write, on-request approvals and automatic review; artifact turns retain their tighter filesystem policy. The frozen dispatch is the sole user input; no preparatory model turn runs. Unsupported client requests receive a recorded error, never a fabricated approval. The process owner drains both streams, closes input and stops descendants within the invocation deadline.

Requests freeze intent, discovery identities/paths and override digests, separately from observations. Each attempt's additive `environment` uses local `schema_version=1` without changing the enclosing dispatch schema. It records runtime version, session/current turn, boundary and these categories: `plugins`, `integrations`, `tools`, `skills`, `instructions`, `memory`, `permissions`. A category has `status` (`known`, `partial`, `unknown`), `values`, `reason` and exact runtime `sources`. Only an explicit complete native inventory proves known empty. Missing fields, false app/plugin instruction booleans, config and saved exclusions cannot do so.

Claude's init owns its invocation snapshot, including full tool/skill lists, memory paths and actual permission mode. Codex's matched session log owns current-turn context; startup instruction sources are separately attributed to the native startup response. Skill ownership proves visible skill-providing plugins only, so that catalog is partial. Resolve skill aliases only against roots from that report. Instruction prose is retained only as a digest, never as a file inventory inferred from existence or similarity. Claude's init reports no instruction files, so its `instructions` come from the session transcript's `instructions` attachments under the runtime's projects directory. Each value names the file's `path`, `runtime_type`, the `sha256` and `bytes` of the content the runtime recorded, `delivered` (`this-invocation` for attachments past the transcript's pre-launch length, else `earlier-in-session`) and `launcher_shim`. That digest covers the content as the runtime recorded it, with line endings as checked out and the trailing newline trimmed, so checking a record against the tree means hashing that text, not the file's bytes; a file hash that differs proves nothing. A fresh launch is `known`, which covers the files those attachments list for this invocation and nothing beyond them. A resume is `partial`, because the runtime re-lists only new or changed files. A missing, ambiguous or unreadable transcript, or one without an attachment, is `unknown` with its reason; flags and files on disk never fill the gap. An init inventory, if a runtime adds one, keeps priority. Unreported memory, tools, integrations or sandbox implementation stay unknown. Session logs must match metadata/session and current-turn identity; older world states, finals and usage are not current evidence. Unsupported formats or inaccessible logs explain unknowns without stopping the turn.

Observations checkpoint while running and survive failed output, malformed lines and stops. Positive foreign plugins, servers, integrations and desktop tools appear in `excess`, and so does a namespaced skill that neither tradecraft nor a reported runtime built-in plugin owns. Claude's claude.ai account skills arrive that way under `anthropic-skills:`; the launch requests no control over them, because the only one found is unproved here (`syncClaudeAiSkills` in user settings would also move the owner's synced skills), so they are recorded as excess with provenance `claude.ai account skill`. Bare skill names and unfamiliar tools whose origin the runtime does not report stay `unclassified`, which means not checked, not clean. Present, none-observed and unknown are distinct. Excess is information for the holder's path reading, never an execution, publication, readiness or release gate. Memory paths describe held context, including Claude's writable memory store; they establish no write audit or read-only boundary.

Native Codex parsing correlates RPC requests and acknowledged session/current turn. A matching completed terminal event owns completion despite transient errors; failure, interruption, missing terminal or protocol error do not. The last completed current-turn agent message owns the source return. Fresh usage retains the latest cumulative `tokenUsage.total` with every native class rather than summing snapshots or using `last`; resumed invocation usage is unknown without a proved baseline. Historical exec parsing and judging launch defaults remain unchanged. Source bytes flush before atomic publication; final records are immutable.

The entrance's `implementer_environments` names bundle/dispatch/stage/vendor/session/turn, lifecycle/outcome, coverage, values, reasons and excess. Each attempt's `instructions` repeats the instruction-file status and reason with every file's path, runtime type, digest, delivery and shim flag, and a Claude attempt's `launch_controls` and `stream_check` repeat what its launch applied and what its stream showed, or `not recorded: launched before #887`. Immediate reports include the just-run failed/interrupted/no-output attempt before artifact-copy disposal. Later reads use existing work, holder, instalment and lineage scopes and deduplicate dispatch IDs; they perform no catalog/account/network discovery. Missing historical environments say `unknown: producer did not record an observed launch environment`; malformed and unfinished bundles stay visible. Old records remain byte-for-byte unchanged and resumable.

No normalized environment contains credentials, full settings, global instruction prose or memory contents. Native capture keeps its existing retention contract.
