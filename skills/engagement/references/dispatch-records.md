# Recording a dispatch

**Loaded when** starting any agent, retaining its return or product, or comparing a dispatch's cost with what it produced. Choosing whether a stage is fresh, resumed, ordinary, cold or terminal is the stretch's staffing judgment; this file records the choice and its result.

## The choice and the launch

**The owner says an override and the holder records it as one ordinary line on the work's issue**, because the holder already has the choice when it dispatches. There is no settings file to maintain and no parser that guesses settings from discussion. A later explicit instruction supersedes the earlier one only for the scope it names. Every launch receives model and effort explicitly from that issue line or from the standing default, and its record names which source supplied them. Requested settings remain requests; a runtime value is observed only where the return exposes it.

**Every agent dispatch leaves its request, source return, reported usage and product in a durable bundle**, including failures, availability skips, fallbacks and resumes, because reconstructing any one of them later makes the cost/result comparison an argument again. `python <plugin>/lib/dispatch_seat.py` records fresh judging seats. `python <plugin>/lib/dispatch_implementer.py` records a fresh or explicitly resumed Codex implementer with workspace-write and automatic approval review; the latter never uses `--last` or `--ephemeral`, since either defeats the named continuity it is meant to preserve. Both entry points take `--work`, `--stage`, `--settings-source` and `--settings-scope`, and accept `--output` when the holder has a particular evidence store; otherwise they print the unique result path created below the user's `.tradecraft/dispatches` directory. A whole-invocation retry names the earlier dispatch id rather than overwriting it.

There is no Claude implementing wrapper: Codex is the standing implementer and the shipped Claude launcher is deliberately a bounded read-only seat. Where an owner assigns implementation to Claude, or where a native dispatch tool performs any role, bracket that actual dispatch with `python <plugin>/lib/dispatch_record.py begin` and `finish`; give `begin` the exact dispatch input and pass the source tool return to `finish`, never a summary. This records the tool and capability boundary actually used instead of moving the work to a convenient launcher. `attach` copies an uncommitted product or later assessment into the bundle. A committed product may instead be identified by repository and revision.

## What the bundle says

**One invocation gets one immutable completion record and each retry gets another**, so a resumed conversation is a chain of dispatches rather than one total overwritten at the end. The launch request is written before the agent starts. The completion names the work and stage, settings source, requested vendor/model/effort, fresh or resumed selection and session id, permission boundary, attempts and fallback reason, observed identifiers and settings where the runtime supplies them, elapsed time, source-native usage, runtime-reported money, source output and assessment state. Output and logs publish only after the record completes. A bundle that cannot be reserved fails before launch; an interrupted one leaves its request and evidence marked unfinished rather than a fabricated success.

**Unknown is a value with its reason, never zero or the requested value.** A missing observed effort stays missing. Multiple models in one return stay multiple. Cached input, total input and a per-model breakdown are retained in their native fields and never added across overlapping populations. A skipped attempt consumed unknown-or-no reported usage rather than a successful zero-cost turn. Monetary cost is recorded only where the runtime returns it; a price table, a subscription charge and a reconstructed invoice are outside the record.

**Resume usage is per-dispatch only where its scope is established.** Retain the raw snapshot either way. Where a runtime returns a cumulative counter, subtract only like counters on the same session with a known uninterrupted baseline; otherwise the per-dispatch value stays unknown. `attach` adds a later verdict, held-out check, sustained remedy or report as a new source attachment, leaving the original result `unassessed` until that evidence exists and never rewriting process success into quality success.

The repository's review index keeps its own population: review seats, defense and judge. Capturing every dispatch does not widen that aggregate, backfill old rows, or include convergence, implementer, spike, experience or commissioned-pass usage there.
