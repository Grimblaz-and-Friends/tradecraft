# Recording a dispatch

**Loaded when** starting any agent, retaining its return or product, or comparing a dispatch's cost with what it produced. Choosing whether a stage is fresh, resumed, ordinary, cold or terminal is the stretch's staffing judgment; this file records the choice and its result.

## The choice and the launch

**The owner says an override and the holder records it as one ordinary line on the work's issue**, because the holder already has the choice when it dispatches. There is no settings file to maintain and no parser that guesses settings from discussion. A later explicit instruction supersedes the earlier one only for the scope it names. Every launch receives model and effort explicitly from that issue line or from the standing default, and its request names the source of each setting separately so a launcher default cannot read as an owner instruction. Requested settings remain requests; a runtime value is observed only where the return exposes it.

**Every agent dispatch leaves its request, source return, reported usage and product in a durable bundle**, including failures, availability skips, fallbacks and resumes, because reconstructing any one later makes the cost/result comparison an argument again. `python <plugin>/lib/dispatch_seat.py` records fresh judging seats, requiring `--classification` and `--requires read|execute`; it refuses a non-detached root or a vendor mode unable to supply that capability before that mode launches. `python <plugin>/lib/dispatch_implementer.py` records a fresh or explicitly resumed Codex implementer with workspace-write and automatic approval review; the latter never uses `--last` or `--ephemeral`, since either defeats the named continuity it is meant to preserve. Both entry points take `--work`, `--stage`, `--settings-source` and `--settings-scope`, and accept `--output` when the holder has a particular evidence store; otherwise they create the unique result path below the user's `.tradecraft/dispatches` directory. Every reserved bundle prints its dispatch id and path, including a failed run, so the holder can carry that route with the return. The holder retains that route and does not delete its bundle before the change's report and records have landed. A whole-invocation retry names the earlier dispatch id rather than overwriting it.

There is no Claude implementing wrapper: Codex is the standing implementer; Claude's seat launcher has file-only read and declared-command execute modes, neither an implementing route. Execute has no OS sandbox, and detachment is not write confinement. Where an owner assigns implementation to Claude, where a write-capable Claude experience consumer operates the result, or where a native dispatch tool performs any role, bracket that actual dispatch with `python <plugin>/lib/dispatch_record.py begin` and `finish`. Give `begin` the exact dispatch input; where it was not retained, give `--input-unavailable-reason` instead, never a paraphrase. Name the source of vendor, model, effort, classification, continuity and permission boundary separately. Give `finish` the source tool return, never a summary, and give the actual runtime duration or the reason it is unavailable rather than deriving one from the recorder's command times. This records the launching tool and capability boundary it selected instead of moving the work to a convenient launcher. `attach` copies an uncommitted product or later assessment into the bundle. A committed product may instead be identified by repository and revision.

## What the bundle says

**One invocation gets one immutable completion record and each retry gets another**, so a resumed conversation is a chain of dispatches rather than one total overwritten at the end. Before start, the seat launcher's request names work, stage, each source, requested vendor/model/effort/classification/capability, fresh or resumed selection and session id, selected permission route, input, and launch time — or why either is unavailable. Its completion links that request and names each attempt's selected boundary or why none was supplied, fallback, runtime-supplied identifiers and settings, elapsed time or its reason, native usage, runtime money, source output and assessment. Logs and source output flush before publication; publication is claimed only after atomic success and removed if the final write fails. An unreservable bundle fails before launch; an interrupted one leaves request and evidence unfinished, never fabricated success.

**Unknown is a value with its reason, never zero or the requested value.** A missing observed effort stays missing. Multiple models in one return stay multiple. Cached input, total input and a per-model breakdown are retained in their native fields and never added across overlapping populations. A skipped attempt consumed unknown-or-no reported usage rather than a successful zero-cost turn. Monetary cost is recorded only where the runtime returns it; a price table, a subscription charge and a reconstructed invoice are outside the record.

**Resume usage is per-dispatch only where its scope is established.** Retain the raw snapshot either way. Where a runtime returns a cumulative counter, subtract only like counters on the same session with a known uninterrupted baseline; otherwise the per-dispatch value stays unknown. `attach` adds a later verdict, held-out check, sustained remedy or report as a new source attachment; consumers read assessment from those immutable attachments rather than from a rewritten completion record, so process success never becomes quality success by mutation.

The repository's review index keeps its own population: review seats, defense and judge. Capturing every dispatch does not widen that aggregate, backfill old rows, or include convergence, implementer, spike, experience or commissioned-pass usage there.
