# Recording a dispatch

**Loaded when** starting any agent, retaining its return or product, or comparing a dispatch's cost with what it produced. Choosing whether a stage is fresh, resumed, ordinary, cold or terminal is the stretch's staffing judgment; this file records the choice and its result.

## The choice and the launch

**An artifact cold seat names the draft it receives before launch or native reservation.** `work.py run cold-seat` composes and binds its latest lawful draft automatically and continues to refuse supplied dispatches. A direct `dispatch_seat.py --stage cold-seat` launch and `dispatch_record.py begin --stage cold-seat` require `--work OWNER/REPO#N --draft-comment COMMENT_ID` and exact UTF-8 input. Their authenticated GitHub GET resolves that issue's draft under the work cell's source-claim rules. The entire fetched body must occur contiguously, byte for byte, in the supplied input; excerpts and normalized substitutes refuse rather than being repaired, because a hash of the whole dispatch cannot identify the draft judged.

The entrance retains an additive `judged_draft` object in the immutable request and initial/completed run: `comment_id`, `sha256`, `sha256_basis=whole-comment-body-lf-utf8`, `body_offset` and `body_bytes`. The digest normalizes only CRLF and CR to LF; the slice identifies the original UTF-8 body in retained dispatch bytes. Both vendors and fallback receive that same frozen input and binding. Native `finish` validates and copies `begin`'s binding without fetching the issue again. Completion evidence must agree with the request and recomputed slice, so an edited issue cannot substitute for the judged text. Every newly recorded artifact cold seat, including an adverse one, requires this evidence. A pending pre-change native request remains historical and is never backfilled. The global bundle schema and cold-verdict marker stay unchanged; the work cell's marker reference owns settlement interpretation and its expressly reported historical compatibility. Other native jobs retain their unavailable-input route, but `--input-unavailable-reason` cannot record a new artifact cold seat.

**The owner says one override choice and the holder records it in one exact `model-override` line owned by the `work` cell**, because the holder already has the choice when it dispatches and a parser must not guess settings from discussion. A lawful line is the whole current override choice: it may carry a different vendor, model and effort for every role it names; the latest lawful line supersedes all earlier override lines as a whole. `artifact_author` governs artifact turns and `implementer` governs build and repair turns. A missing role uses the machine's `~/.tradecraft/implementer-vendor` choice and that role's pinned profile; an absent file means Codex, while invalid content refuses the launch. The direct implementer launcher reads the same file for a fresh turn; `--vendor` carries an explicit role choice and wins over a valid file. A named direct resume requires that explicit vendor from its recorded session, since the session id does not establish one. The entrance likewise passes a present role entry to the launcher explicitly. The request and launch report name the selected vendor, its source, and the separate sources of model and effort so a default cannot read as an owner instruction. An `ordinary_seat` or `terminal_seat` entry reaches a launch only when the holder passes the resolved values to `dispatch_seat.py` directly, naming the marker comment as each source. Defaulted model and effort fields also use the machine ruling bridge under the `work` cell's launch-settings contract, reached through its depth index. Both launchers print their resolved settings before launch. A bridge-supplied field retains the full entry identity, file path, compared pairs and ruling locator in its requested source and each seat attempt's setting sources, because the machine file may later change or disappear. Requested settings remain requests; a runtime value is observed only where the return exposes it.

**A standing default is chosen on what comparisons have shown, never on a model's price rank.** A comparison here speaks only to the role and task it tested: candidates receive identical assignments and trees through a byte-identical dispatch, and an independent rater told nothing about their provenance chooses blind between the results. A definitive separation makes the better model the recommendation; a definitive, confident no-difference makes the cheaper model the recommendation on the comparison's relevant owner-paid cost evidence. An inconclusive, missing or interrupted result leaves the owner's named preference as an interim default, recorded as interim with the further comparison runs it needs, because failing to detect a difference is not finding none. **The cost that counts is what the owner pays, which is not always the rate the runtime advertises** — a subscription's allocation burn is outside the bundle; a money figure in any comparison is a rate-card equivalent and ranks options only as far as that equivalence holds. The recommendation and its evidence go to the owner, whose choice is the standing default; the full model id is pinned where that default is set so a vendor alias cannot move it without another decision.

**Every agent dispatch leaves its request, source return, reported usage and product in a durable bundle**, including failures, availability skips, handovers and resumes, because reconstructing any one later makes the cost/result comparison an argument again. Schema version 2 gives every attempt one normalized usage row carrying change, dispatch, requested and runtime-reported model, native token classes, scope, exact source field and runtime version; additional native token classes stay named rather than being folded into another class. Unknown carries its reason. Currency never enters that normalized row, while a vendor-returned monetary value remains in the immutable native log. `python <plugin-root>/lib/dispatch_seat.py` records fresh judging seats, requiring `--classification` and `--requires read|execute`; it refuses a non-detached root or a vendor mode unable to supply that capability before that mode launches. `python <plugin-root>/lib/dispatch_implementer.py` records a fresh or explicitly resumed Codex or Claude implementer. Codex uses workspace-write and automatic approval review without `--last` or `--ephemeral`, since either defeats named continuity. Artifact launches and resumes come through `work.py run artifact`, which supplies the entrance-owned copy lifecycle and `--artifact-brief FILE`: a UTF-8 file containing the affirmed brief comment's text, retained independently of the dispatch so the return can be checked. A direct artifact launch without that lifecycle refuses before recording a bundle, because an author must not work in the holder checkout. Both entry points take `--work`, `--stage`, `--settings-source` and `--settings-scope`, and accept `--output` when the holder has a particular evidence store; otherwise they create the unique result path below the user's `.tradecraft/dispatches` directory. Every reserved bundle prints its dispatch id and path, including a failed run, so the holder can carry that route with the return. The holder retains that route and does not delete its bundle before the change's report and records have landed. A whole-invocation retry names the earlier dispatch id rather than overwriting it.

The implementing launcher can run Claude Opus 5.5 at high in auto permission mode, with persistent named sessions and user setting sources so the implementation tree's project holder hook does not load into the child. Its artifact-author profile is interim until a comparison measures it. The launcher supplies repository instructions and the shipped plugin explicitly because project settings are omitted. The seat launcher remains a separate judging route. Claude has no OS write sandbox; detachment is not write confinement. A Codex judging seat has three separate boundaries: `sandbox=read-only` confines filesystem writes, `user_config=ignored` removes per-app enables and other settings from the user configuration file while preserving authentication, and `apps=disabled-by-feature` records `--disable apps`, so the seat holds no catalogue of connected apps or tool that reads one. The launcher retains `apps._default.enabled=false`; a Codex that does not recognise the feature switch fails the launch visibly, and the launcher never retries with it dropped. On Windows, the launcher additionally reads only `[windows].sandbox` from an absolute `CODEX_HOME/config.toml`, or the user's `.codex/config.toml` when `CODEX_HOME` is unset or empty, and passes that owner-selected mode as one explicit override because the machine's configured sandbox implementation is what lets the bounded seat read without importing the rest of its owner's configuration. The request and launched-attempt boundaries name the mode and resolved file-and-key source. A relative `CODEX_HOME`, or a missing, unreadable, malformed, non-string or empty sandbox value, makes the Codex attempt unavailable before executable resolution, so the existing availability fallback runs instead of recording a blind seat as successful; the configured, isolated, missing and fallback cases are pinned by the Windows Codex tests in `lib/tests/test_dispatch_seat.py`. Where a native dispatch tool performs a role outside either launcher, bracket that actual dispatch with `python <plugin-root>/lib/dispatch_record.py begin` and `finish`. Give `begin` the exact dispatch input; where it was not retained, give `--input-unavailable-reason` instead, never a paraphrase. Name the source of vendor, model, effort, classification, continuity and permission boundary separately. Give `finish` the source tool return, never a summary, and give the actual runtime duration or the reason it is unavailable rather than deriving one from the recorder's command times. `attach` copies an uncommitted product or later assessment into the bundle. A committed product may instead be identified by repository and revision. For a native use or cold seat, the entrance judges staffing from the recorded seat vendor and the stage's producer record. Give `finish --vendor` the vendor that actually ran the seat. To accept a same-vendor seat, give `begin --same-vendor-reason REASON` and repeat that recorded reason in the degraded marker.

## What the bundle says

For a raw run file, request and attach its summary under the `authoring` cell's run-output reference, so product attachment does not turn the bundle into a raw-evidence store. Dispatch requests, native logs, source returns and usage retain the contract above.

**For a Codex turn, the JSONL stream owns completion.** A `turn.completed` event with no `turn.failed` event is complete. An `error` event is retained and counted in the observed record but is not itself a turn failure. When the last-message file is empty, the last completed stream `agent_message` supplies the source return. When neither source supplies a final message, the attempt records `completed_no_output` with reason `turn completed without a final message`; it remains a completed, non-error attempt but publishes no source return or seat verdict. A successful attempt has an empty reason; every error, unavailable result, continuability qualification, or completed-no-output result carries the reason belonging to that outcome.

**One invocation starts with a durable growing run record, and only its final atomic write completes and freezes it; each retry gets another**, so a resumed conversation is a chain of dispatches rather than one total overwritten at the end. Before start, the seat launcher's request names work, stage, each source, requested vendor/model/effort/classification/capability, fresh or resumed selection and session id, selected permission route, input, and launch time — or why either is unavailable. Its completion links that request and names each attempt's selected boundary or why none was supplied, requested and actual vendor, qualified or degraded staffing with its reason, fallback, runtime-supplied identifiers and settings, elapsed time or its reason, native usage, runtime money, source output and assessment. A degraded same-vendor return leaves a cross-vendor stage incomplete unless that stage records why the same-vendor result is accepted. Before launching, flush the immutable request, exact dispatch input and parseable initial run record. Drain stdout and stderr concurrently and retain raw bytes immediately, declaring their encoding. Record the observed session and its exact source as soon as the vendor reports it, separately from requested or reserved identities; a later malformed event cannot erase that identity. A resume may retain its proved predecessor identity with that provenance. Checkpoint elapsed time even during silence and retain process identity so the entrance can refuse live or unresolved launches. Logs and source output flush before publication; publication is claimed only after atomic success and removed if the final write fails. An unreservable bundle fails before launch; a caller-killed one leaves request and evidence unfinished, never fabricated success. A controlled ceiling stop completes the launcher record with an interrupted outcome rather than successful stage evidence. A missing completion write reports an unfinished interruption without inventing its cause or completion time.

**Unknown is a value with its reason, never zero or the requested value.** A missing observed effort stays missing. Multiple models in one return stay multiple. Cached input, total input and a per-model breakdown are retained in their native fields and never added across overlapping populations. A skipped attempt consumed unknown-or-no reported usage rather than a successful zero-cost turn. A vendor monetary value stays only in its immutable native return; it is not normalized as usage.

**Resume usage is per-dispatch only where its scope is established.** Retain the raw snapshot either way. Where a runtime returns a cumulative counter, subtract only like counters on the same session with a known uninterrupted baseline; otherwise the per-dispatch value stays unknown. `attach` adds a later verdict, held-out check, sustained remedy or report as a new source attachment; consumers read assessment from those immutable attachments rather than from a rewritten completion record, so process success never becomes quality success by mutation.

## Reading cost at close

Run `python <plugin-root>/lib/change_cost.py holder-close --repo OWNER/REPO --issue N --vendor VENDOR` with either `--tokens-file FILE` or `--unknown-reason TEXT`, then run `python <plugin-root>/lib/change_cost.py report --repo OWNER/REPO --issue N`. Use the repository spelling recorded in the work identifier exactly: matching is case-sensitive, and the report does not infer a repository name from a checkout path.

`holder-close` appends a normalized usage row to `~/.tradecraft/changes/OWNER/REPO/N/holder-usage.jsonl`, or to the file named by `--output`. It records the supplied counters or their unknown reason, the requested model when supplied, and a unique holder-close ID. It records no money; its timestamps are the close capture time. The report includes that holder-usage file by default, and `--holder-usage FILE` selects another file.

The `change-cost:v1` report keeps raw usage, list-price equivalence and bill/plan status separate. Codex prices use the model requested for each attempt and the card's short-context rates, so every Codex figure is labelled as a floor. Cached input and cache writes are removed from total input before uncached input is charged; reasoning is already inside output. A resumed Codex dispatch contributes only the difference from its preceding comparable snapshot in the same session. Without a usable baseline, its share is unknown.

For a fresh Claude dispatch, the report checks the runtime's recorded list-price figure against the card price of its four per-model token populations. This comparison requires card coverage for every positive billable count, including non-token requests; an uncovered charge makes the figure unknown. It uses the runtime figure when the difference is no more than a cent. Above a cent, it shows both figures, flags the mismatch and uses the card figure. With no runtime figure, including holder-close usage, it uses the card. Thinking is already inside output, and reported limits are not usage. Claude resumes remain unknown.

The change total counts each dispatch once, including its distinct attempts, even when copied bundles occur beneath the dispatch root. Attempts that never launched are listed as `not-launched` and contribute no cost or unknown gap. It states the list-price basis, the known amount, the number of dispatches with unknown contributions, and any skipped records. Missing contributions and short-context Codex pricing make the amount a floor; it is not what a plan or subscription bills. Unsupported or unreadable evidence is named rather than silently omitted.

The report selects dated prices by the recorded launch timestamp. A launch after a promotional interval has ended is unknown until an applicable row is added, with a reason to re-read the posted page; an earlier launch keeps its applicable promotional price when reported later. Missing prices, billable token classes and usable baselines carry their reasons. Shipped-default coverage is checked when tests run, without failing solely because a row has expired.

The report reads requests first and opens no completion whose request identifies another change. A same-session foreign request between snapshots makes the resumed share unknown, because the difference would include another change's usage. A running or interrupted dispatch attributable to the asked change appears as an unknown contribution. When neither request nor completion can establish attribution, the completion path is listed separately among skipped records.

Rates are shipped; plan terms remain machine-local, and gauge snapshots stay with the change. Subscription allocation by change remains unknown. The Codex gauge reader uses `account/rateLimits/read`, retaining an interactive `/status` capture when needed; Claude's gauge is a separate `/usage` capture. Neither display is converted to tokens or an invoice without a vendor mapping. The monetary commands measure and record without halting a dispatch. The entrance separately accounts recipient runtime against the build-only budget in the work cell; its report shows both bounds and their separate bases, excluded repair runtime and each per-run override reason without converting unknown usage into spend. Growing records retain the elapsed checkpoint interval and margin; historical growing records use the same timer policy from the work cell.

A vendor-spawn acknowledgement proves launch; starting a containment worker does not. Linux controlled stops adopt and reap session-escaping descendants. If cleanup cannot be proved, the bundle remains inspectable and cannot supply safe resume continuity. A dead completed fresh failure with no reported identity can be replaced only through the entrance's explicit `--restart-unresolved-reason`, retaining the failure and budget lineage. A failed handover retains its reserved-session recovery route.
