# The dispatch contract

**Loaded when** you are writing the dispatch that sends a review role its work — a seat, a defense, a judge. A recipient reading a dispatch it was handed does not need it.

**Every dispatch is built in three parts, in this order** [D-90] [D-97]. The **shared block** comes first, with nothing before it but a byte-identical title line — a preamble puts per-recipient framing ahead of the shared block. It carries, verbatim or by link and never the dispatcher's paraphrase, the assignment — artifact location, diff base, purpose statement, evidence standards, any session note reporting use of the artifact, and any findings an earlier review recorded against it, carried with the instruction that a seat files whatever an entry now earns and does not rule it — and every predecessor stage's output whole, which a dispatch read cold does not receive but for the carve-outs the roster names (`../references/roster.md`); nothing else in it aims attention. The assignment is byte-identical across every recipient dispatched against the same diff base. Then a **dispatcher's note** where there is one, labeled as such and additive; no seat takes one, because a cold vantage sits among them and aimed attention is what that vantage is defined against. Last, **in this skill's own words**, the recipient's identity and its lens brief — which the `cold-read` seat does not take, for the reason and with the full list of what a cold dispatch withholds in the roster (`../references/roster.md`). Its output format and working location where it differs are the only other per-recipient content. **Calling attention is lawful; filtering and restating are not** — an author compressing its own charter is an interested party.

**Findings an earlier review recorded against this artifact are fetched before the first dispatch**, from wherever the repository keeps them. **Match an entry by the subject it names against what this change touches** — a file the change edits, or the cell that holds it — not by the change under review, which no later review shares. A finding held for evidence is promoted by being met again, which cannot happen if the stage that would meet it never reads it — so the fetch belongs here, at the assignment, and not to the stage that wrote the entry.

**Independence extends to every role**: defense and judge are staffed like seats — never the artifact's author, and the judge never a finder. In a single-session lane, all review roles are fresh dispatches, not the authoring session reviewing itself. The launch records the working root, sandbox or permission boundary, model, and reasoning effort; those are inputs to the evidence, not ambient defaults.

**A dispatch whose subject is text the change edits gets a working root whose copy of that text is the change's own**, and is told that any always-on text reaching it otherwise is not its governing text. A runtime injects the repository's own doctrine and charter into every session it starts, from wherever it resolves them — which on this practice's own evidence can be a tree that is neither the change, its base, nor the default branch, so a recipient reads the rule the change replaced and rules against it. Naming the working root is not enough on its own [D-222]: the stale text arrives beside it, and only an isolated root plus that statement has been observed to make a recipient reject it. **Nor does diffing against the default branch establish it** — the tree one seat was handed sat five commits behind that branch, and that check passes.

**The dispatch names the revision, not only the root, and carries what lands the recipient there.** A root is not a revision: isolation cut by a dispatching tool comes up on the repository default every time rather than occasionally — every stage of one review, each recovering only because the dispatch said to — so a dispatch naming a root alone has named the text the change replaced. `git checkout --detach <sha>` inside the root is the remedy to carry, because `git worktree add <path> <branch>` refuses a branch already checked out elsewhere, which is the ordinary case here.

**And the recipient states, in its output, the revision it actually worked at.** Every occurrence of this failure on record was caught because the affected session happened to volunteer it, which is the signature of a class no instrument observes. A statement the report carries (`../references/the-record.md`) is what makes a stage that judged replaced text legible to someone who was not in it. **It remains the recipient's own account**, and what it buys over none is that the account is a checkable fact rather than a judgement of its own compliance, given by a party with no stake in the dispatch being right, landing where the terminal stage and the owner read it.

**Seats that mutate the tree get their own worktree, cut detached from a base the dispatch names, and their write boundary there.** Mutation testing, red-probes, anything that writes: dispatch it isolated, or concurrent readers see files change underneath them mid-review. **`git worktree add --detach <path> <base>`** — plain `add` creates a branch, and where the base was the change under review that branch carries the change's own content, so a pull request opened from it re-proposes the reviewed change under an unrelated title. That happened on one review, the probes each in compliance with this sentence as it stood before the base was named. **Detached, the base may be the change under review** — a seat probing that change has to hold it. The branch was the failure, never the base. **And the typed-halt's bar on editing the artifact under review is a bar on the tree other stages read**, which this boundary is what satisfies — a seat reading that bar literally declines the job it was dispatched for.
