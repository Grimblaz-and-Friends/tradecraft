# Ending the review

**Loaded when** you are closing a review: writing its final report, ruling whether another pass runs, appending its row to the review index, or ruling `record` and writing the entry. Nothing before the terminal ruling needs it.

The final report, posted to the PR or issue, carries:

- The lane and why, and the purpose statement judged against.
- **Per-seat counts** — raw / merged / sustained, highs broken out — with each seat's model and runtime. A seat's `merged` counts its own findings surviving the merge. **Its `high` counts the sustained highs that seat is credited on, so the column carries credits and never distinct highs** [D-185]. The unit counted throughout is the finding as originated and dispositioned, never a row of a ruling table.
- **Each sustained high's finders** — every credited seat as the merge records them, primary first and a merge-added co-finder labeled as its own; or the stage or seat that originated it where no merge carried it; and where a merge carried it with no finder list to copy, that fact.
- **Every finding's disposition**, with each drop's one-line reason, each record's entry, and each handed-on decision's destination.
- Any lens retired, and the evidence that earned it.
- The external pass's outcome, and any commissioned pass's.
- **The split by consequence shape** (`../references/arbitration.md`), and whether a session note was carried.
- The terminal fitness ruling, and the **next-pass ruling** — run or stop.

The default is stop once a pass has sustained no high it will fix; continuing argues the next pass is worth its cost, and stopping names the residual risk accepted and what is expected to catch it instead. A run ruling binds the session that wrote it: dispatch the pass before closing, or record why not.

**A pass continues only while the findings it expects are about the artifact.** A look returning only apparatus-facing material — the review's own bookkeeping, the record of having reviewed — has reached the **relevance terminus**, and the ruling names it as the reason it stops, whatever the cycle budget still allows — the budget round one's ruling named (`../references/after-the-fix.md`), which also carries the count terminus this one races; whichever fires first ends the cycle. It is a second condition because it closes a second failure: findings real, probe-backed and correctly arbitrated, on a subject that has drifted from the change to the record of reviewing it — which a budget counting rounds cannot see. **That material is no longer a subject of the look**, whose scope has retired it (`../references/after-the-fix.md`) though it is still read where it locates what the look is for. The split above is what makes that drift legible while stopping is still cheap, taken over every finding the pass returned.

Where the repo keeps a review index, append **one row per review, never one per cycle** — date, artifact, lane, each sustained high named (`highs`, a list of strings), the model and runtime that staffed it (`staffing`), the external pass's qualitative outcome (`external`, a non-empty string), report URL, and `notes` where one line of context would otherwise be lost — written once and never maintained. **The row carries no arithmetic.** Every count it used to carry was totalled and reconciled by hand into a file nobody may edit, and that is this index's whole defect record: what a review was worth is read from the report it links, and how many highs it sustained is the length of the list. **Where seats were staffed unevenly, say so in the value** — `fable (cold-read), opus (rest)` — and spell a runtime the same way every time — one spelling per runtime, as `claude-code (windows)` — or the per-runtime evidence the record exists for cannot be gathered.

Neither a bot comment nor a review tool the session invoked is a panel seat, since neither received the dispatch and seat contract that makes one. They are not the same thing either, and the row keeps them apart: `external` carries what configured automation posted, and a commissioned pass (`../references/after-the-fix.md`) is reported in prose alone. Neither ever reaches staffing or a revived counting field.

**Where the repo keeps a record of findings held for evidence**, a `record` ruling appends one entry — `artifact`, `finding` as ruled, and the `promotion` that would earn it a remedy. The keys are named because a first writer facing an empty file invents its own, and an entry keyed differently from the one that follows it cannot be found by the review it was written for. **`artifact` names the durable subject the entry survives to be met on** — the file, the cell, the sentence — and never the change under review: an entry keyed to a change is met by no later review of it, so it is a sink rather than a record. This is the one place the two records deliberately part vocabulary, since the index's subject is a change and this one's is what the change touched. Appending is this stage's act; the reading belongs to the next review's assignment, which fetches it before dispatching (`../references/dispatch.md`), because a file only the closing stage is told to open is one no opening stage ever reads. Nothing maintains it: a finding that returns is promoted by a new entry, never by editing an old one, and an entry nothing ever promotes is the ruling working.

Before reading what such a record says, ask what it could have said: an evidence loop whose instrument cannot express the finding it tests for is not evidence, and a record is silent about everything its fields do not carry. **A convention stated per row is one no later row inherits**, which is why the counting rules above are stated here once. Where a seat failed unreplaced the report records the degraded width, and the row's `staffing` value says so wherever it would otherwise misdescribe the panel. Where the repo keeps no index, the report alone is the record.
