# Ending the review

**Loaded when** you are closing a review: writing its final report, appending its row to the review index, or ruling `record` and writing the entry. Nothing before the terminal ruling needs it.

The final report, posted to the PR or issue, carries:

- The lane and why, and the purpose statement judged against.
- **Per-seat counts** — raw / merged / sustained, highs broken out — with each seat's model and runtime. A seat's `merged` counts its own findings surviving the merge. **Its `high` counts the sustained highs that seat is credited on, so the column carries credits and never distinct highs** [D-185]. The unit counted throughout is the finding as originated and dispositioned, never a row of a ruling table.
- **Each sustained high's finders** — every credited seat as the merge records them, primary first and a merge-added co-finder labeled as its own; or the stage or seat that originated it where no merge carried it; and where a merge carried it with no finder list to copy, that fact.
- **Every finding's disposition**, with each drop's one-line reason, each record's entry, and each handed-on decision's destination.
- **What the review cost to run, and where each sustained high landed**, wherever the repository's index records either — so the row's values have a prior statement to be read against, which is what every other field on that row already has.
- Any lens retired, and the evidence that earned it.
- The external pass's outcome, and any commissioned pass's.
- **The split by consequence shape** (`../references/arbitration.md`), and whether a session note was carried.
- **What the executable floor returned** (`../references/after-the-fix.md`), and which sustained findings it could not reach.
- **The experience session the fix batch bought**, or the one line declining it.
- The terminal fitness ruling.

**The review closes here.** There is no further pass to rule on — a review is one round (`../references/after-the-fix.md`) — so the report names the residual risk accepted and what is expected to catch it instead: the experience session on the fixed tree, and friction met under the merged material once it is in use.

**The split above is what makes drift legible.** A review whose sustained findings were mostly apparatus-facing spent its round on the record of having reviewed rather than on the work — a fact about the instrument, which the next lane choice reads and which a count of findings cannot show.

Where the repo keeps a review index, append **one row per review, whatever it took to run** — date, artifact, lane, each sustained high named (`highs`, a list of strings, one entry per high — a repository whose index carries more per high may make an entry a mapping instead, so long as it still names the high under a key its own material states), the model and runtime that staffed it (`staffing`, a mapping of `model` and `runtime`), the external pass's qualitative outcome (`external`, a non-empty string), report URL, and `notes` where one line of context would otherwise be lost — written once and never maintained. **The row carries no arithmetic over the findings.** Every count it used to carry was totalled and reconciled by hand into a file nobody may edit, and that is this index's whole defect record: what a review was worth is read from the report it links, and how many highs it sustained is the length of the list. **A fact about the run is not that arithmetic** — `staffing` is one, and what the review cost to run is another where a repository records it: read off what each dispatch returned rather than totalled from a transcript, and evidence for the next lane choice rather than a ceiling to come under. **A repository recording it says in its own material which dispatches it counts**, for the reason the spelling rule below exists: two records counting different populations cannot be read against each other, and the span is not obvious — whether the review's own cold pass, a post-fix experience session, or a tool the session invoked itself sits inside it is a choice each time. **This licence reaches facts about the run and nothing further**; a count of findings under any name is the arithmetic this cutover retired. **Where seats were staffed unevenly, say so in the value** — `fable (cold-read), opus (rest)` — and spell a runtime the same way every time — one spelling per runtime, as `claude-code (windows)` — or the per-runtime evidence the record exists for cannot be gathered.

Neither a bot comment nor a review tool the session invoked is a panel seat, since neither received the dispatch and seat contract that makes one. They are not the same thing either, and the row keeps them apart: `external` carries what configured automation posted, and a commissioned pass (`../references/after-the-fix.md`) is reported in prose alone. Neither ever reaches staffing or a revived counting field.

**Where the repo keeps a record of findings held for evidence**, a `record` ruling appends one entry — `artifact`, `finding` as ruled, the `promotion` that would earn it a remedy, and the `value` acting on the finding would serve, since an entry is by construction a worth-it judgment the evidence did not settle. Give it as the ranking's own designator for that value, number and name — `2 (Compounding)` — so a reordering cannot silently re-point a frozen entry and an unordered ranking still resolves. Where the repository declares no ranking the key is omitted and its absence claims nothing; where one is declared the key is owed, and its absence in an entry written since says the values argument was not made — entries predating the requirement claim nothing either way. The keys are named because a first writer facing an empty file invents its own, and an entry keyed differently from the one that follows it cannot be found by the review it was written for. **`artifact` names the durable subject the entry survives to be met on** — the file, the cell, the sentence — and never the change under review: an entry keyed to a change is met by no later review of it, so it is a sink rather than a record. This is the one place the two records deliberately part vocabulary, since the index's subject is a change and this one's is what the change touched. Appending is this stage's act; the reading belongs to the next review's assignment, which fetches it before dispatching (`../references/dispatch.md`), because a file only the closing stage is told to open is one no opening stage ever reads. Nothing maintains it: a finding that returns is promoted by a new entry, never by editing an old one, and an entry nothing ever promotes is the ruling working.

Before reading what such a record says, ask what it could have said: an evidence loop whose instrument cannot express the finding it tests for is not evidence, and a record is silent about everything its fields do not carry. **A convention stated per row is one no later row inherits**, which is why the counting rules above are stated here once. Where a seat failed unreplaced the report records the degraded width, and the row's `staffing` value says so wherever it would otherwise misdescribe the panel. Where the repo keeps no index, the report alone is the record.
