# What a frozen document owes its reader

**Loaded when** you are about to put a figure into anything that does not re-derive it at read time, or a claim about how something currently behaves into anything nobody goes back to correct. The trigger is having one of them to place, not having decided it is a lawful one. The two properties are not the same and each rule below names its own. Nothing else needs it.

**A derived figure lives only on a surface that re-derives it at read time.** A surface that freezes — a decision entry, a report, a commit message, a PR body, a pre-implementation artifact, a comment beside code — states the command and the tree it runs on, never the output. Deriving at write time buys nothing, because the prose outlives the moment it was true: the instrument is right and the photograph of it ages.

**The falsifier is one question, asked of any number on such a surface: *which command, on which tree?*** A number standing where a command belongs is a violation a reviewer can name without consulting anything else. **A comment beside code answers the tree half with the reader's own** — it travels with the code, so naming a fixed tree in it makes it false everywhere else; say the command prices whatever tree you are on, and pin only a figure that is genuinely about one past tree.

**Derived is the subject, and it is narrower than every number.** A figure a command produces from a tree is derived. A primary observation is not — what a review found, what a session did, a measurement read off a record that itself freezes. Those are evidence, pinned by the record carrying them rather than by a command, and this rule does not reach them.

**This cell ships the mechanism a named command points at.** `../scripts/figures.py` derives the recurring figures — suite count, a document's size against its budget, prose delta against a named base — each printed with its basis and the tree it was measured on. Name it rather than improvising arithmetic — and name it as it resolves for the reader, from the root of the repository they will run it in, never by the path this cell reaches it at; and where the repository wraps this engine with its own parameters and repo-bound figures, name that wrapper — it is what keeps a figure agreeing with the guard that judges it. A figure needing a caller decision (the delta's base) must be given explicitly; the script refuses to pick a basis silently, because a silently chosen basis is how stated numbers diverge from checkable ones, and because a command missing its base is one the reader cannot run.

**A claim about current behaviour names what demonstrates it.** On a surface that is not maintained — a decision entry, a commit message, a PR body or a report once posted, a pre-implementation artifact once affirmed, an append-only record — name the probe, test, ruling, or file that shows the behaviour instead of paraphrasing it. Nothing routes a later session back to repair a wrong sentence in one of these, so the paraphrase is a copy that can be wrong while the original stays right, and it stays wrong. **The falsifier is one question: *which probe, test, ruling, or file shows this?*** The claim must be about behaviour that already exists; a proposed one has nothing to point at and stays prose. Where a practice admits a narrow correction to one of these surfaces, that is a repair and not maintenance: it does not put the surface outside this rule, and the correction itself names a demonstrator rather than writing a fresh paraphrase.

**That scope differs from the figure rule's above, and turns on a different property.** The figure rule reaches what nobody re-derives at read time; this one reaches what nobody goes back to correct. The lists differ in both directions. **A comment beside code is inside that rule and outside this one** — it can be edited, so a wrong sentence in it is repaired by an ordinary fix, and describing what the code does is frequently the exact thing its reader needs, where a pointer to a test would be worse prose. **An append-only record is inside this one and outside that.** Revisable prose is outside this rule for the comment's reason: a skill, a doctrine file, a README.

**What is irreducible stays prose.** The decision, the alternatives rejected, why the choice was made, what was known at the time — none of it has a demonstrator to name, and none of it can be falsified by a later tree, only superseded. The rule reaches a description of what the tree does, never the record of what somebody judged.

**Pin a frozen document's evidence to the commit it shipped at.** A document that cannot be revised freezes while the tree keeps moving, so an unpinned quotation goes stale silently and a later reader cannot tell whether the citation was wrong or the file changed under it. Leave one unpinned only where your practice repairs references whose targets move; nothing repairs them by default.
