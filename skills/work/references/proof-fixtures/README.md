# Proof v1 interoperability fixtures

**Loaded when** implementing or testing the independent gate that consumes the entrance's proof document.

`v1-review-body-dispositions.json` carries live-record cases for the body-answer rule in the connected-reviewer answer contract. Each case supplies its repository and pull-request number, submitted reviews, inline roots and replies, conversation comments, connected reviewer logins and marker producers. `expected` names unanswered reviewer/identity pairs, unanswered unidentified review ids, the full unidentified classification and ignored answer authors. Review ids in a finding's `sources` are the reviews actually carrying that identity. These records are fetched independently by each consumer; they are not proof-document fields and require no import from the entrance. The representative CodeRabbit markup retains the blockquote/details structures of #733 and #757, with shortened finding text; the #812 fix-prompt shape remains identity-free. Synthetic mutations exercise the same contract in both polarities.

The repair cases retain the walkthrough's `Security Findings and Attack Paths` heading from [#757's conversation comment](https://github.com/Grimblaz-and-Friends/tradecraft/pull/757#issuecomment-5817397750), both as conversation text and as a review body. Its headings and the `Security Findings` summary control declare nothing for CodeRabbit. The real outside-diff cases preserve the emoji-prefixed bold blockquote and per-finding summary from [#733's review](https://github.com/Grimblaz-and-Friends/tradecraft/pull/733#pullrequestreview-5291109788), in answered, unanswered and identity-missing variants. The remaining additions exercise shared rules A (section boundaries and innermost ownership), B (counted prose beside an inline root), C (a lone backtick before live markup), wrapped symbol-prefixed titles and mixed-case reviewer/producer logins. Configured logins use lowercase; fetched records retain GitHub's case. Existing `Other comments (N)` cases remain declarations; CodeRabbit's existing `Findings` heading cases retain identity obligations without a whole-review obligation.

`v1-valid.json` is a schema-valid document whose public records are assumed to match the live fixture. `v1-negative-cases.json` names the rejecting cases and expresses only the field overlay that differs from the valid document plus the trusted live fact the gate must re-derive. An overlay replaces the named object or array; it is not a JSON Merge Patch implementation requirement.

The schema rejects the producer-verification field structurally. The other cases are deliberately schema-shaped where possible: schema validity cannot establish head applicability, public check identity, configured reviewer completeness, review credit, disposition authority, or the public/declaration distinction. The gate applies those cases against its own fetched records and trusted policy.

`v1-actions-receipts.json` supplies positive and negative shared-Actions receipt cases. Its `document_patch` overlays the valid document with a declared review receipt; that declaration remains schema-valid even when the live facts reject it. For each case, copy `live`, update each named object with its `live_patch` fields, and replace arrays whole. Assemble the API run's `path` by joining `workflow_path.segments` with `/` and appending `@` plus `workflow_path.ref` when non-null; these are fixture representations of the fixed adopter destination, not proof fields. `job_pages` are the object pages from the jobs GET with `filter=all`. The expected `result` tests independently fetched receipt facts, including success in an earlier attempt on a later page despite the run's overall failure.
